# บทที่ 5 — กระบวนการทำงานแบบผสมผสาน

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 5 คือแท็ก `ch05` บทนี้เพิ่มคลาส C++ หนึ่งคลาส (`AWorkflowDemoActor`) และ Blueprint ลูกหนึ่งคลาส (`BP_WorkflowDemo`) ซึ่งแสดงกระบวนการทำงานทั้งบทในตัวอย่างเดียว ได้แก่ Specifier ของ `UPROPERTY` (EditAnywhere, VisibleAnywhere, EditDefaultsOnly, BlueprintReadWrite, BlueprintReadOnly), `TSubclassOf`, และ Specifier ของ `UFUNCTION` ทั้งสามระดับ (BlueprintCallable, BlueprintImplementableEvent, BlueprintNativeEvent)

## เริ่มต้น

โปรเจกต์ประกอบเก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch05` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch05.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch05` แล้วใช้โฟลเดอร์ `companion/HAPBook/`) ไฟล์ zip นี้มี Blueprint `BP_WorkflowDemo` ที่สร้างเสร็จแล้วรวมอยู่ด้วย
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch05` ซึ่งมี `BP_WorkflowDemo` วางไว้แล้ว ตัว Blueprint อยู่ใน `Content/Blueprints` ผู้อ่านที่ต้องการสร้าง Blueprint นี้ด้วยตนเองตั้งแต่ต้น ให้ทำตามสูตรในหัวข้อ "ตัวอย่างประกอบ" ของบทที่ 5 แล้ววางในแผนที่เอง
5. กด *Play* เมื่อกด Play ตัวละครผู้เล่นของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับตัวละครผู้เล่นเดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `Workflow` ในช่องกรอง เปรียบเทียบกับหัวข้อ "จุดตรวจสอบผลลัพธ์" จากนั้นเปลี่ยนคำกรองเป็น `Conventions` เพื่อดูสองบรรทัดของบทที่ 2 ที่ Actor ที่ถูกสร้างขึ้นบันทึกไว้

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch04` คลาสของบทที่ 2 และบทที่ 4 ยังอยู่ในโปรเจกต์และไม่เปลี่ยนแปลง

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายสองข้อจากการอ่านชุดคำสั่งและสูตร Blueprint (1) ค่าใดที่ Blueprint เขียนทับค่าเริ่มต้นของ C++ และบรรทัดใดแสดงผลของการเขียนทับนั้น (2) บรรทัดใดพิสูจน์ว่า `DescribeSelf` ซึ่งเป็น BlueprintNativeEvent ถูก Blueprint เขียนทับแล้ว จากนั้นจึงเปรียบเทียบกับ Output Log

กรองด้วยคำว่า `Workflow` ต้องเห็นห้าบรรทัดต่อไปนี้ตามลำดับ

```
LogTemp: [Workflow] BeginPlay: MaxHealth=120, CurrentHealth=120
LogTemp: [Workflow] ApplyDamage(30) -> CurrentHealth=90
LogTemp: [Workflow][BP] Health changed: 90
LogTemp: [Workflow] DescribeSelf: Blueprint override
LogTemp: [Workflow] Spawned: ConventionsDemoActor
```

กรองด้วยคำว่า `Conventions` ต้องเห็นสองบรรทัดของบทที่ 2 ด้วย เพราะ `AConventionsDemoActor` ที่ถูกสร้างขึ้นทำงาน `BeginPlay()` ของตนเอง (บรรทัดทั้งสองปรากฏก่อนบรรทัด `Spawned` เมื่อดูโดยไม่กรอง)

```
LogTemp: [Conventions] Name: Sentinel-01 | Health: 100 | Scores: 3 items (sum 270)
LogTemp: [Conventions] Data object created via NewObject: UConventionsData (Level=2)
```

- `MaxHealth=120` (ไม่ใช่ 100 ตามโค้ด C++) คือค่าจาก Class Defaults ของ `BP_WorkflowDemo` ซึ่งซ้อนทับค่าเริ่มต้นของ C++ ตามกลไก CDO ของบทที่ 4
- บรรทัด `[BP] Health changed: 90` มาจาก Blueprint: C++ เรียก `OnHealthChanged` (BlueprintImplementableEvent) แล้ว Blueprint เรียก `LogFromBlueprint` (BlueprintCallable) กลับมา
- บรรทัด `DescribeSelf: Blueprint override` พิสูจน์ว่า Blueprint เขียนทับ BlueprintNativeEvent แล้ว หากไม่เขียนทับจะได้ `DescribeSelf: C++ default`
- บรรทัด `Spawned: ConventionsDemoActor` พิสูจน์ว่า `TSubclassOf<AActor>` รับคลาสจาก Class Defaults และ C++ สร้าง Actor ของคลาสนั้นได้โดยไม่รู้จักคลาสจริงล่วงหน้า

## ปัญหาที่พบบ่อย

- **เพิ่ม `UPROPERTY` หรือ `UFUNCTION` ใหม่ใน C++ แล้วไม่ปรากฏใน Blueprint** — Live Coding ไม่รองรับการเปลี่ยนแปลงในไฟล์ Header ให้ปิด Editor สั่ง Build ใหม่จาก Rider เปิด Editor แล้วเปิด Blueprint อีกครั้ง หากยังไม่ปรากฏ ให้กด *Compile* ใน Blueprint Editor
- **แก้ค่า `MaxHealth` แล้วผลลัพธ์ไม่เปลี่ยน** — ตรวจสอบว่าแก้ที่ใด ค่าใน *Class Defaults* ของ Blueprint ใช้กับทุกอินสแตนซ์ ส่วนค่าในแผง Details ของ Actor ที่วางในฉากใช้กับอินสแตนซ์นั้นเท่านั้น และซ้อนทับ Class Defaults หากแก้ Class Defaults หลังจากวาง Actor แล้ว อินสแตนซ์ที่เคยแก้ค่ารายตัวไว้จะไม่เปลี่ยนตาม
- **ช่อง `CurrentHealth` เป็นสีเทาแก้ไม่ได้** — เป็นพฤติกรรมที่ถูกต้องของ `VisibleAnywhere` สมาชิกนี้มีไว้ให้สังเกตสถานะ ไม่ใช่ให้กำหนดค่า (ภาพที่แสดงช่องนี้คือภาพประกอบ Access Specifier ในบทที่ 5)
- **รายการเลือกของ `SpawnClass` ไม่มีคลาสที่ต้องการ** — `TSubclassOf<AActor>` กรองให้เลือกได้เฉพาะคลาสลูกของ `AActor` เท่านั้น คลาสที่ไม่ใช่ Actor (เช่น `UConventionsData`) จะไม่ปรากฏโดยเจตนา และช่องนี้แก้ได้เฉพาะใน Class Defaults เพราะเป็น `EditDefaultsOnly`
- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch05` และได้กด *Play* แล้ว หากผู้อ่านลบ `BP_WorkflowDemo` ออกจากแผนที่ไป ให้ลากจาก `Content/Blueprints` กลับไปวางใหม่
- **หาที่เขียนทับ `DescribeSelf` ไม่พบ** — การเขียนทับ BlueprintNativeEvent ที่มีค่าส่งกลับทำในแผง *My Blueprint* หัวข้อ *Functions* รายการ *Override* ไม่ใช่เมนูคลิกขวาใน Event Graph (เมนูคลิกขวาแสดงเฉพาะเหตุการณ์ที่ไม่มีค่าส่งกลับ เช่น `OnHealthChanged`)
- **Link error `unresolved external symbol ... DescribeSelf_Implementation`** — ฟังก์ชันที่ประกาศเป็น `BlueprintNativeEvent` ต้องนิยามในไฟล์ `.cpp` ด้วยชื่อที่ต่อท้ายด้วย `_Implementation` เสมอ การนิยาม `DescribeSelf()` ตรง ๆ จะขัดกับตัวนิยามที่ UHT สร้างให้
- **Blueprint แจ้งข้อผิดพลาดหลังแก้ลายเซ็นฟังก์ชันใน C++** (เช่น เปลี่ยนชนิดพารามิเตอร์ของ `OnHealthChanged`) — Node ในกราฟยังอ้างลายเซ็นเดิม ให้คลิกขวาที่ Node เลือก *Refresh Nodes* หรือใช้ *File → Refresh All Nodes* หากคลาสแม่เปลี่ยน ให้ใช้ *File → Reparent Blueprint* แล้วกด *Compile*
