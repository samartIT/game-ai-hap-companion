# บทที่ 7 — สถาปัตยกรรมปัญญาประดิษฐ์พื้นฐาน

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 7 คือแท็ก (Tag) `ch07` บทนี้เป็นบทแรกของส่วนที่ 3 และสร้างศัตรู (Enemy) ตัวแรกซึ่งเป็นฐานที่บทที่ 8–13 ต่อยอด ได้แก่ คลาส (Class) `AEnemyCharacter` (ร่าง (Pawn)) และ `AEnemyAIController` (สมอง) ที่รากของโมดูล (Module) กับ Asset `BB_Enemy` (Blackboard หนึ่งคีย์ (Key) `PatrolLocation`), `BT_Enemy` (Behavior Tree หนึ่งกิ่ง (Branch): Sequence → Move To → Wait) และ `BP_Enemy` (Blueprint ลูกที่ถือโมเดล (Model) Mannequin, Animation Blueprint และ Behavior Tree) Enemy เดินลาดตระเวนผ่าน TargetPoint สามจุดวนซ้ำในแผนที่ `L_Ch07` ซึ่งเป็นสำเนาของ `Lvl_ThirdPerson` ของแม่แบบ (Template)

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch07` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `game-ai-hap-companion-ch07.zip` แตก File แล้วได้โฟลเดอร์ (Folder) `game-ai-hap-companion-ch07/` ซึ่งมี `HAPBook/` อยู่ภายใน (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch07` แล้วใช้ Folder `HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch07` ซึ่งมี `BP_Enemy` หนึ่งตัว TargetPoint สามจุด (กำหนดไว้ใน `Patrol Points` ของ Enemy แล้ว) และ `NavMeshBoundsVolume` วางไว้แล้ว
5. กด *Play* เมื่อกด Play แล้ว Player ของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับ Player เดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `[AI]` ในช่องกรอง เปรียบเทียบกับหัวข้อ "จุดตรวจสอบผลลัพธ์" ในฉาก Enemy จะเดินจากจุดหนึ่งไปอีกจุดหนึ่ง หยุดหนึ่งวินาที แล้วเดินต่อวนซ้ำ ระหว่างเล่น กดปุ่ม Apostrophe (`'`) ขณะกล้องมองเห็น Enemy เพื่อเปิด Gameplay Debugger ซึ่งแสดงชื่อ Behavior Tree Node ที่กำลังทำงาน และค่าของ Key `PatrolLocation`

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools (Build Tools for Visual Studio) พร้อมเวิร์กโหลด (Workload) "Desktop development with C++" และ ".NET desktop build tools" (ขั้นตอนอยู่ในภาคผนวก ก ของงานเขียน)
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของ Project สำหรับบทนี้คือ Tag `ch06` Class ของบทก่อนหน้ายังอยู่ใน Project และไม่เปลี่ยนแปลง บทนี้เพิ่ม Module `NavigationSystem` และ `GameplayTasks` ใน `HAPBook.Build.cs` (Module `AIModule` มีอยู่แล้วจาก Template) ผู้อ่านที่สร้างตามใน Project ของตนเพิ่มสองชื่อนี้ใน `PublicDependencyModuleNames` ก่อน Build

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายว่าบรรทัดแรกมาจากฟังก์ชัน (Function) ใด (`OnPossess()` หรือ `OnMoveCompleted()`) และตัวเลขในบรรทัด Reached จะเรียงลำดับใด จากนั้นจึงเปรียบเทียบกับ Output Log ซึ่งต้องแสดงสี่บรรทัดต่อไปนี้ทุกอักขระตามลำดับ และหลังบรรทัดสุดท้ายจะวนกลับไป `1 of 3` ต่อเนื่อง

```
LogTemp: [AI] Possessed BP_Enemy_C: 3 patrol points, Behavior Tree running
LogTemp: [AI] Reached waypoint 1 of 3
LogTemp: [AI] Reached waypoint 2 of 3
LogTemp: [AI] Reached waypoint 3 of 3
```

- บรรทัดที่ 1: จาก `OnPossess()` ปรากฏก่อน Enemy ขยับ `BP_Enemy_C` คือชื่อ Class ที่เอนจิ้น (Engine) สร้างจาก Blueprint (ต่อท้าย `_C`) ยืนยันว่า Pawn ที่ถูกควบคุมคือ Blueprint ลูก เลข 3 มาจากอาร์เรย์ (Array) `Patrol Points` ที่กรอกไว้ที่อินสแตนซ์ (Instance) ในฉาก
- บรรทัดที่ 2–4: จาก `OnMoveCompleted()` ครั้งละหนึ่งบรรทัดต่อการมาถึงหนึ่งจุด ตัวเลขเพิ่มทีละหนึ่งเพราะดัชนีถูกเลื่อนหลังบันทึก และวนกลับเป็น 1 หลัง 3
- สิ่งที่ตรวจสอบคือ **ลำดับ** ของบรรทัด ไม่ใช่เวลาที่ห่างกัน เวลาขึ้นกับระยะระหว่าง TargetPoint (ในแผนที่ประกอบห่างกันประมาณ 600–1000 หน่วย) และความเร็วเดินของ Enemy 400 หน่วยต่อวินาที (*Max Walk Speed* ของ `BP_Enemy`)

การทดลองเพิ่มเติม: เลือก Node Move To ใน `BT_Enemy` แล้วเปลี่ยน `Acceptable Radius` จาก 50 เป็น 500 แล้ว Play ใหม่ ลำดับของบรรทัดไม่เปลี่ยน แต่ปรากฏถี่ขึ้นและ Enemy หยุดก่อนถึงจุดราว 5 เมตร (แบบฝึกหัดข้อ 9 ของบทที่ 7)

## ปัญหาที่พบบ่อย

- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch07` และได้กด *Play* แล้ว ช่องกรองพิมพ์ `[AI]` (มีวงเล็บเหลี่ยม) หากผู้อ่านลบ `BP_Enemy` ออกจากแผนที่ไป ให้ลากกลับไปวางบนพื้นสีเขียว แล้วกำหนด `Patrol Points` ที่ Instance ใหม่
- **มีบรรทัด Possessed แต่ Enemy ยืนนิ่ง และไม่มีบรรทัด Reached** — ไม่มี `NavMeshBoundsVolume` หรือ TargetPoint อยู่นอก NavMesh กด `P` ในตัวแก้ไข (Editor): พื้นที่สีเขียวคือพื้นที่เดินได้ ทั้ง Enemy และ TargetPoint ทั้งสามต้องอยู่บนสีเขียว หากไม่มีสีเขียวเลย ให้ลาก `NavMeshBoundsVolume` จาก *Place Actors* ลงในฉากแล้วขยายให้ครอบคลุมพื้นที่เล่น Output Log จะมีบรรทัด `LogAINavigation: Error: AAIController::MoveTo: Destination is not valid!` ในกรณีนี้
- **Enemy ไถลไปในท่ายืนโดยไม่เล่นแอนิเมชัน (Animation)** — ตรวจกล่อง *Use Acceleration for Paths* ในหมวด **Nav Movement** ของ Component Character Movement (`FNavMovementProperties::bUseAccelerationForPaths` ค่าเริ่มต้น (Default Value) ของ Engine คือเท็จ) เมื่อเป็นจริง การเดินตามเส้นทางส่งทิศทางเข้าทาง `AddMovementInput` จึงมีความเร่งและ `ABP_Unarmed` เล่นท่าเดิน เมื่อเป็นเท็จ จะกำหนดความเร็วโดยตรง (`RequestDirectMove`) ความเร่งเป็นศูนย์ Pawn จึงไถลในท่ายืน `AEnemyCharacter` ของ Companion ตั้งค่านี้เป็นจริงใน C++ แล้ว ดังนั้นหากตัวละคร (Character) ที่ผู้อ่านสร้างเองไถล นี่คือสาเหตุ (เพิ่มบรรทัดที่ตั้ง `bUseAccelerationForPaths` เป็นจริงในตัวสร้าง (Constructor) ตามตัวอย่างชุดคำสั่งที่ 7.3 หรือเลือกช่องในหมวด Nav Movement ของ Blueprint) **ระวังกล่องชื่อเดียวกันในหมวด Character Movement (General Settings) → Advanced** (`bRequestedMoveUseAcceleration`) ซึ่งเป็นคนละค่าและไม่เปลี่ยนอาการ หากตั้งค่าในหมวด Nav Movement แล้วยังไถล จึงตรวจว่า `Anim Class` ของ Component Mesh เป็น `ABP_Unarmed` (ผลลัพธ์ใน Output Log ถูกต้องทุกกรณี เพราะ Animation ไม่เกี่ยวกับการนำทาง (Navigation))
- **ไม่มีบรรทัด Possessed แต่มี Warning `Behavior Tree not started (asset or patrol points missing)`** — `Patrol Points` ของ Instance ในฉากว่าง หรือ `Behavior Tree Asset` ใน Class Defaults ของ `BP_Enemy` ยังไม่ได้ตั้ง `Patrol Points` เป็น `EditInstanceOnly` จึงต้องกรอกที่ตัวที่วางในฉาก (เลือก Actor ในฉาก → Details → หมวด Patrol) ไม่ใช่ใน Class Defaults
- **มี Warning `PatrolPoints[n] is not assigned`** — ช่องใดช่องหนึ่งของ Array ว่าง (กด + แล้วไม่ได้เลือก TargetPoint) ให้เลือก TargetPoint ให้ครบทุกช่อง
- **`EnemyCharacter` ไม่ปรากฏในรายการคลาสแม่ (Parent Class) เมื่อสร้าง Blueprint** — โค้ด (Code) C++ ยังไม่ผ่านการคอมไพล์ (Compile) ในสถานะล่าสุด สั่ง Build ใน Rider ให้เสร็จก่อน แล้วเปิด Editor ใหม่ (Live Coding ไม่รองรับการเพิ่ม Class ใหม่อย่างน่าเชื่อถือ)
- **กด Apostrophe แล้วไม่มีอะไรปรากฏ** — Gameplay Debugger แสดงข้อมูลของ AI ที่อยู่ในสายตาของกล้องเท่านั้น ให้หันกล้องไปที่ Enemy ก่อนกด และต้องกดขณะ Play (ไม่ใช่ใน Editor)
- **สับสนระหว่าง Enemy ของบทนี้กับ Enemy ใน Variant_Combat** — `ACombatEnemy`, `ACombatAIController` และ `Content/Variant_Combat/` เป็นมินิเกมตัวอย่างของ Epic ที่ใช้ StateTree ไม่ใช่ส่วนหนึ่งของงานเขียนฉบับนี้ Enemy ของบทนี้คือ `AEnemyCharacter`/`AEnemyAIController` ที่รากของ `Source/HAPBook/` และ `Content/AI/` เท่านั้น (ดูหัวข้อ "จุดตั้งต้น: แผนที่ของ Template Third Person" ของบทที่ 7)
