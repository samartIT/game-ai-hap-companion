# บทที่ 7 — สถาปัตยกรรมปัญญาประดิษฐ์พื้นฐาน

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 7 คือแท็ก `ch07` บทนี้เป็นบทแรกของส่วนที่ 3 และสร้างศัตรูตัวแรกซึ่งเป็นฐานที่บทที่ 8–13 ต่อยอด ได้แก่ คลาส `AEnemyCharacter` (ร่าง) และ `AEnemyAIController` (สมอง) ที่รากของโมดูล กับ Asset `BB_Enemy` (Blackboard หนึ่งคีย์ `PatrolLocation`), `BT_Enemy` (Behavior Tree หนึ่งกิ่ง: Sequence → Move To → Wait) และ `BP_Enemy` (Blueprint ลูกที่ถือโมเดล Mannequin, Animation Blueprint และ Behavior Tree) ศัตรูเดินลาดตระเวนผ่าน TargetPoint สามจุดวนซ้ำในแผนที่ `L_Ch07` ซึ่งเป็นสำเนาของ `Lvl_ThirdPerson` ของ Template

## เริ่มต้น

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch07` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch07.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch07` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch07` ซึ่งมี `BP_Enemy` หนึ่งตัว TargetPoint สามจุด (กำหนดไว้ใน `Patrol Points` ของศัตรูแล้ว) และ `NavMeshBoundsVolume` วางไว้แล้ว
5. กด *Play* เมื่อกด Play ตัวละครผู้เล่นของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถเดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `[AI]` ในช่องกรอง เปรียบเทียบกับหัวข้อ "จุดตรวจสอบผลลัพธ์" ในฉาก ศัตรูจะเดินจากจุดหนึ่งไปอีกจุดหนึ่ง หยุดหนึ่งวินาที แล้วเดินต่อวนซ้ำ ระหว่างเล่น กดปุ่ม Apostrophe (`'`) ขณะกล้องมองเห็นศัตรูเพื่อเปิด Gameplay Debugger ซึ่งแสดงชื่อ Behavior Tree Node ที่กำลังทำงาน และค่าของคีย์ `PatrolLocation`

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch06` คลาสของบทก่อนหน้ายังอยู่ในโปรเจกต์และไม่เปลี่ยนแปลง บทนี้เพิ่มโมดูล `NavigationSystem` และ `GameplayTasks` ใน `HAPBook.Build.cs` (โมดูล `AIModule` มีอยู่แล้วจาก Template) ผู้อ่านที่สร้างตามในโปรเจกต์ของตนเพิ่มสองชื่อนี้ใน `PublicDependencyModuleNames` ก่อน Build

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายว่าบรรทัดแรกมาจากฟังก์ชันใด (`OnPossess()` หรือ `OnMoveCompleted()`) และตัวเลขในบรรทัด Reached จะเรียงลำดับใด จากนั้นจึงเปรียบเทียบกับ Output Log ซึ่งต้องแสดงสี่บรรทัดต่อไปนี้ทุกอักขระตามลำดับ และหลังบรรทัดสุดท้ายจะวนกลับไป `1 of 3` ต่อเนื่อง

```
LogTemp: [AI] Possessed BP_Enemy_C: 3 patrol points, Behavior Tree running
LogTemp: [AI] Reached waypoint 1 of 3
LogTemp: [AI] Reached waypoint 2 of 3
LogTemp: [AI] Reached waypoint 3 of 3
```

- บรรทัดที่ 1: จาก `OnPossess()` ปรากฏก่อนศัตรูขยับ `BP_Enemy_C` คือชื่อคลาสที่เอนจิ้นสร้างจาก Blueprint (ต่อท้าย `_C`) ยืนยันว่าร่างที่ถูกควบคุมคือ Blueprint ลูก เลข 3 มาจากอาร์เรย์ `Patrol Points` ที่กรอกไว้ที่อินสแตนซ์ในฉาก
- บรรทัดที่ 2–4: จาก `OnMoveCompleted()` ครั้งละหนึ่งบรรทัดต่อการมาถึงหนึ่งจุด ตัวเลขเพิ่มทีละหนึ่งเพราะดัชนีถูกเลื่อนหลังบันทึก และวนกลับเป็น 1 หลัง 3
- สิ่งที่ตรวจสอบคือ **ลำดับ** ของบรรทัด ไม่ใช่เวลาที่ห่างกัน เวลาขึ้นกับระยะระหว่าง TargetPoint (ในแผนที่ประกอบห่างกันประมาณ 600–1000 หน่วย) และความเร็วเดิน 500 หน่วยต่อวินาทีของ `CharacterMovementComponent`

การทดลองเพิ่มเติม: เลือก Node Move To ใน `BT_Enemy` แล้วเปลี่ยน `Acceptable Radius` จาก 50 เป็น 500 แล้ว Play ใหม่ ลำดับของบรรทัดไม่เปลี่ยน แต่ปรากฏถี่ขึ้นและศัตรูหยุดก่อนถึงจุดราว 5 เมตร (แบบฝึกหัดข้อ 9 ของบทที่ 7)

## ปัญหาที่พบบ่อย

- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch07` และได้กด *Play* แล้ว ช่องกรองพิมพ์ `[AI]` (มีวงเล็บเหลี่ยม) หากผู้อ่านลบ `BP_Enemy` ออกจากแผนที่ไป ให้ลากกลับไปวางบนพื้นสีเขียว แล้วกำหนด `Patrol Points` ที่อินสแตนซ์ใหม่
- **มีบรรทัด Possessed แต่ศัตรูยืนนิ่ง และไม่มีบรรทัด Reached** — ไม่มี `NavMeshBoundsVolume` หรือ TargetPoint อยู่นอก NavMesh กด `P` ในตัวแก้ไข: พื้นที่สีเขียวคือพื้นที่เดินได้ ทั้งศัตรูและ TargetPoint ทั้งสามต้องอยู่บนสีเขียว หากไม่มีสีเขียวเลย ให้ลาก `NavMeshBoundsVolume` จาก *Place Actors* ลงในฉากแล้วขยายให้ครอบคลุมพื้นที่เล่น Output Log จะมีบรรทัด `LogAINavigation: Error: AAIController::MoveTo: Destination is not valid!` ในกรณีนี้
- **ศัตรูไถลไปในท่ายืนโดยไม่เล่นแอนิเมชัน** — ตรวจกล่อง *Use Acceleration for Paths* ในหมวด **Nav Movement** ของ Component Character Movement (`FNavMovementProperties::bUseAccelerationForPaths` ค่าเริ่มต้นของเอนจิ้นคือเท็จ) เมื่อเป็นจริง การเดินตามเส้นทางส่งทิศทางเข้าทาง `AddMovementInput` จึงมีความเร่งและ `ABP_Unarmed` เล่นท่าเดิน เมื่อเป็นเท็จ จะกำหนดความเร็วโดยตรง (`RequestDirectMove`) ความเร่งเป็นศูนย์ ร่างจึงไถลในท่ายืน `AEnemyCharacter` ของชุดโค้ดประกอบตั้งค่านี้เป็นจริงใน C++ แล้ว ดังนั้นหากตัวละครที่ผู้อ่านสร้างเองไถล นี่คือสาเหตุ (เพิ่มบรรทัดเดียวกันใน Constructor หรือเปิดกล่องในหมวด Nav Movement ของ Blueprint) **ระวังกล่องชื่อเดียวกันในหมวด Character Movement (General Settings) → Advanced** (`bRequestedMoveUseAcceleration`) ซึ่งเป็นคนละค่าและไม่เปลี่ยนอาการ หากตั้งค่าในหมวด Nav Movement แล้วยังไถล จึงตรวจว่า `Anim Class` ของ Component Mesh เป็น `ABP_Unarmed` (ผลลัพธ์ใน Output Log ถูกต้องทุกกรณี เพราะแอนิเมชันไม่เกี่ยวกับการนำทาง)
- **ไม่มีบรรทัด Possessed แต่มี Warning `Behavior Tree not started (asset or patrol points missing)`** — `Patrol Points` ของอินสแตนซ์ในฉากว่าง หรือ `Behavior Tree Asset` ใน Class Defaults ของ `BP_Enemy` ยังไม่ได้ตั้ง `Patrol Points` เป็น `EditInstanceOnly` จึงต้องกรอกที่ตัวที่วางในฉาก (เลือก Actor ในฉาก → Details → หมวด Patrol) ไม่ใช่ใน Class Defaults
- **มี Warning `PatrolPoints[n] is not assigned`** — ช่องใดช่องหนึ่งของอาร์เรย์ว่าง (กด + แล้วไม่ได้เลือก TargetPoint) ให้เลือก TargetPoint ให้ครบทุกช่อง
- **`EnemyCharacter` ไม่ปรากฏในรายการคลาสแม่เมื่อสร้าง Blueprint** — โค้ด C++ ยังไม่ได้คอมไพล์ในสถานะล่าสุด สั่ง Build ใน Rider ให้เสร็จก่อน แล้วเปิดตัวแก้ไขใหม่ (Live Coding ไม่รองรับการเพิ่มคลาสใหม่อย่างน่าเชื่อถือ)
- **กด Apostrophe แล้วไม่มีอะไรปรากฏ** — Gameplay Debugger แสดงข้อมูลของ AI ที่อยู่ในสายตาของกล้องเท่านั้น ให้หันกล้องไปที่ศัตรูก่อนกด และต้องกดขณะ Play (ไม่ใช่ในตัวแก้ไข)
- **สับสนระหว่างศัตรูของบทนี้กับศัตรูใน Variant_Combat** — `ACombatEnemy`, `ACombatAIController` และ `Content/Variant_Combat/` เป็นมินิเกมตัวอย่างของ Epic ที่ใช้ StateTree ไม่ใช่ส่วนหนึ่งของงานเขียนฉบับนี้ ศัตรูของบทนี้คือ `AEnemyCharacter`/`AEnemyAIController` ที่รากของ `Source/HAPBook/` และ `Content/AI/` เท่านั้น (ดูหัวข้อ "จุดตั้งต้น: แผนที่ของ Template Third Person" ของบทที่ 7)
