# บทที่ 13 — การบูรณาการระบบต่อสู้ของ AI

- สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 13 คือแท็ก (Tag) `ch13`
- บทนี้ปิดวงจรการต่อสู้ (Combat Loop): ศัตรู (Enemy) เปลี่ยนสถานะระหว่างลาดตระเวน ตื่นตัว ไล่ตาม โจมตี และค้นหา และผู้เล่น (Player) ต่อสู้กลับได้
- ฝั่ง C++ มีคลาส (Class) ใหม่สอง Class ได้แก่ Task การโจมตี (Attack) `UBTTask_Attack` (เป้าหมายในระยะโจมตี 200 ซึ่งวัดเป็นช่องว่างระหว่างแคปซูล → หันหาเป้าหมาย → `ApplyDamage` 10 หน่วยด้วยชนิด `UDamageType_Melee` โดยมี Controller ของ Enemy เป็น Instigator; ล้าง `TargetActor` เมื่อ Attack ทำให้เป้าหมายตาย) และชนิดความเสียหาย (Damage) `UDamageType_Melee`
- `UHealthComponent` รายงานทุกเหตุ Damage ต่อ AI Perception ด้วย `UAISense_Damage::ReportDamageEvent` และมี `IsActorDead()`
- ตัวรับสิ่งเร้าของ `AEnemyAIController` ได้สาขาของ Sense Damage (ผู้กระทำที่เป็นปรปักษ์ (Hostile) กลายเป็น `TargetActor`) และเพิกเฉยเมื่อร่าง (Pawn) ของตนหรือ Actor ที่รับรู้ตายแล้ว
- `AHAPPlayerCharacter` ได้ `LogFromBlueprint()` (เครื่องมือวัด)
- การเปลี่ยนแปลงของ Behavior Tree ทั้งหมดอยู่ใน `BT_Enemy_Combat` (สำเนาของ `BT_Enemy_EQS` ที่มีกิ่ง (Branch) `Attack` ทางซ้ายของ `Chase`) กับ Blackboard `BB_Enemy_Combat` (Parent = `BB_Enemy_EQS`)
- ฝั่ง Player มี Input Action `IA_Attack` (เมาส์ซ้ายใน `IMC_Default`) กราฟ (Graph) Attack และ Graph การตาย (Death) ใน `BP_ThirdPersonCharacter`
- `BP_EnemyAIController` ได้ AI Damage sense config
- แผนที่ `L_Ch13` เป็นสำเนาของ `L_Ch12`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch13` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `game-ai-hap-companion-ch13.zip` แตก File แล้วได้โฟลเดอร์ (Folder) `game-ai-hap-companion-ch13/` ซึ่งมี `HAPBook/` อยู่ภายใน (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch13` แล้วใช้ Folder `HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch13` ซึ่งมี `BP_Enemy` หนึ่งตัว (เลือก *Perception Enabled* และตั้ง *Behavior Tree Asset* เป็น `BT_Enemy_Combat` ที่อินสแตนซ์ (Instance) แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, `BP_AlertZone`, หุ่น `Dummy_01`–`Dummy_03`, `EnemySpawner` (*Spawn Count* 0), `TP_Target` และ `BP_EQSTester` ของบทก่อน เมื่อกด Play แล้ว Player เป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของ Player คือ Stimulus ที่ AI รับรู้

บทนี้สร้างเป็นสี่ขั้น Tag `ch13` คือสถานะหลังขั้นที่ 4 การทดลองแต่ละขั้นทำดังนี้

5. ขั้นที่ 1 — Enemy โจมตี: กด Play จากนั้นบังคับ Player ให้เดินเข้าไปในที่ที่ Enemy มองเห็น แล้วให้ Player ยืนนิ่งจน Enemy ไล่ตามมาถึง Enemy หันหา Player และโจมตีทุกประมาณ 1.5 วินาที ข้อความ `Health 190.0/200.0` ปรากฏบนหน้าจอ เมื่อ Player เดินออกนอกระยะ Enemy กลับไปไล่ตาม
6. ขั้นที่ 2 — Player ต่อสู้กลับ: กด Play ใหม่ จากนั้นบังคับ Player ให้เดินอ้อมไปด้านหลังของ Enemy ขณะ Enemy ลาดตระเวนโดยไม่ให้ Enemy เห็น และให้ Player เข้าไปให้ชิด แล้วกดเมาส์ซ้ายหนึ่งครั้ง Enemy ละทิ้งการลาดตระเวน (Patrol) หันมา และโจมตีกลับ
7. ขั้นที่ 3 — Death ของทั้งสองฝ่าย: ให้ Player โจมตี Enemy จนครบสามครั้ง Enemy หยุดนิ่งและหายไปหลังสามวินาที จากนั้นกด Play ใหม่ ให้ Player ยืนในระยะของ Enemy โดยไม่โจมตีราวสามสิบวินาทีจนพลังชีวิต (Health) ถึงศูนย์ แล้วลองบังคับ Player ให้เดินและลองกดเมาส์ซ้าย Player ขยับไม่ได้ และ Enemy กลับไปลาดตระเวน
8. ขั้นที่ 4 — วงจรทั้งวง: กด Play ใหม่ รอจน Output Log แสดง `[AI] Reached waypoint 1 of 3` บังคับ Player ให้เดินเข้า `BP_AlertZone` ขณะ Enemy มองไม่เห็น Player แล้วยืนในที่โล่งใกล้เขต เมื่อ Enemy มาถึงและโจมตีหนึ่งครั้ง ให้ Player โจมตีกลับหนึ่งครั้ง แล้ววิ่งไปหลบหลังบล็อก (Block) ที่สูงกว่าตัวละคร (Character) ย้ายไปอีกด้านของ Block เมื่อทรงกลมสีส้มปรากฏใกล้จุดที่ยืน และอยู่ในที่ซ่อนจน Enemy กลับไปลาดตระเวนและถึงจุดลาดตระเวน (Patrol Point) ถัดไป

## จุดตรวจสอบผลลัพธ์

ขั้นที่ 1 — Enemy โจมตี: สองบรรทัดนี้ติดกัน ซ้ำทุกประมาณ 1.5 วินาทีโดยตัวเลขลดลงครั้งละ 10 ตราบที่ Player อยู่ในระยะ (กรอง Output Log ด้วย `[Damage]` และ `[Combat]`) ก่อนกด Play ผู้อ่านควรทำนาย Health หลัง Attack ครั้งที่สาม

```
LogTemp: [Damage] BP_ThirdPersonCharacter_C took 10.00 (Melee) -> 190.00/200.00
LogTemp: [Combat] Attack: BP_ThirdPersonCharacter_C -> 190.00/200.00
```

- บรรทัด `[Damage]`: บรรทัดของ `UHealthComponent` (บทที่ 10) บน Player เกิดภายใน `ApplyDamage` ก่อนฟังก์ชัน (Function) คืนค่า ป้าย `Melee` คือชื่อ Class `UDamageType_Melee` หลังตัดคำนำหน้า (Prefix)
- บรรทัด `[Combat]`: จาก `UBTTask_Attack` หลัง `ApplyDamage` คืนค่า ตัวเลขจึงตรงกับบรรทัดก่อนหน้าเสมอ

ขั้นที่ 2 — Player ต่อสู้กลับ: สองบรรทัดนี้ตามลำดับเมื่อกดเมาส์ซ้ายหนึ่งครั้ง ตามด้วยสองบรรทัดของขั้นที่ 1 ภายในครึ่งวินาที และบรรทัด `[Perception] Sight gained: BP_ThirdPersonCharacter_C` ของบทที่ 11 เมื่อ Enemy หันมาถึง Player ไม่มีบรรทัด `Patrol aborted` ของบทที่ 8

```
LogTemp: [Damage] BP_Enemy_C took 34.00 (Melee) -> 66.00/100.00
LogTemp: [Perception] Damage from: BP_ThirdPersonCharacter_C
```

- บรรทัด `[Damage]`: บรรทัดของ `UHealthComponent` บน Enemy Function เดียวกันรายงานเหตุต่อการรับรู้ (Perception) หลังบรรทัดนี้ โดยไม่บันทึกสิ่งใด
- บรรทัด `Damage from`: จากสาขา Damage ของ `OnTargetPerceptionUpdated()` ใน Tick ถัดไปของ Perception Player เป็น Hostile ตัวรับจึงเขียน `TargetActor` และ `Chase` (Both) ยุติ Patrol

ขั้นที่ 3 — Death ของทั้งสองฝ่าย: การเล่นครั้งแรก (Player โจมตี Enemy สามครั้ง): Attack ครั้งที่สองและสามให้บรรทัดต่อไปนี้ ไม่มีบรรทัด `Damage from` หลังบรรทัด died

```
LogTemp: [Damage] BP_Enemy_C took 34.00 (Melee) -> 32.00/100.00
LogTemp: [Damage] BP_Enemy_C took 34.00 (Melee) -> 0.00/100.00
LogTemp: [Damage] BP_Enemy_C died
```

การเล่นครั้งที่สอง (Enemy โจมตี Player ยี่สิบครั้ง): Attack ครั้งสุดท้ายให้สี่บรรทัดนี้ตามลำดับ จากนั้น Player ขยับไม่ได้ และ Enemy กลับไปลาดตระเวน

```
LogTemp: [Damage] BP_ThirdPersonCharacter_C took 10.00 (Melee) -> 0.00/200.00
LogTemp: [Damage] BP_ThirdPersonCharacter_C died
LogTemp: [Combat] Player died
LogTemp: [Combat] Attack: BP_ThirdPersonCharacter_C -> 0.00/200.00
```

- กล่องแรก: บรรทัดของ `UHealthComponent` ทั้งหมด ลำดับ Death ของ Enemy (หยุด Behavior Tree ปิดการชน (Collision) ทำลายหลัง 3 วินาที) เป็นของบทที่ 10 Enemy ที่ตายแล้วไม่รับรู้สิ่งใดเพิ่ม จึงไม่มีบรรทัด `Damage from` ของ Attack ครั้งที่สาม
- กล่องที่สอง: สามบรรทัดแรกเกิดภายใน `ApplyDamage` ของ Task (Component → Broadcast `OnDeath` → Death Graph ของ Player: Disable Input แล้ว Log From Blueprint) บรรทัดที่สี่มาจาก Task ซึ่งล้าง `TargetActor` หลังบรรทัดนี้

ขั้นที่ 4 — วงจรทั้งวง: สิบสองบรรทัดนี้ตามลำดับ บรรทัดเริ่มต้นของการเล่น (`Possessed`, บรรทัด ready สองบรรทัด และบรรทัด Teams) อยู่ก่อนบรรทัดแรก บรรทัด `[Nodes]` ของ Branch `Face` อาจแทรกระหว่าง Patrol และ Attack ซ้ำของ Enemy ให้คู่บรรทัดของขั้นที่ 1 เพิ่ม ก่อนกด Play ผู้อ่านควรเขียนลำดับของสถานะที่คาดว่าจะเกิด

```
LogTemp: [AI] Reached waypoint 1 of 3
LogTemp: [BT] Alert raised at AlertZone
LogTemp: [BT] Patrol aborted by Observer Aborts (Lower Priority)
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
LogTemp: [Damage] BP_ThirdPersonCharacter_C took 10.00 (Melee) -> 190.00/200.00
LogTemp: [Combat] Attack: BP_ThirdPersonCharacter_C -> 190.00/200.00
LogTemp: [Damage] BP_Enemy_C took 34.00 (Melee) -> 66.00/100.00
LogTemp: [Perception] Damage from: BP_ThirdPersonCharacter_C
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
LogTemp: [EQS] Search: checking hidden spot
LogTemp: [AI] Reached waypoint 2 of 3
```

ลำดับตามวงจร: ลาดตระเวน (บทที่ 7) → ตื่นตัว (บทที่ 8) → ไล่ตาม (บทที่ 11) → โจมตี (บทที่ 10 และ 13) → Player โจมตีกลับ (บทที่ 10 และ 13) → มองไม่เห็นเป้าหมายแล้ว ตรวจสอบ และค้นหา (บทที่ 11, 8 และ 12) → ลาดตระเวน (บทที่ 7) ตัวเลขของบรรทัดสุดท้ายคือจุดที่ Patrol มุ่งไปเมื่อเขตเตือนขัดจังหวะ หาก Enemy พบ Player ที่จุดซ่อน (Hiding Spot) Branch `Chase` เข้าแทนที่ทันที

การทดลองเพิ่มเติม: เปิด `L_Ch07` ถึง `L_Ch12` แล้ว Play ทีละแผนที่โดยไม่กดเมาส์ซ้าย ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[Combat]` ใดเลย Enemy ในแผนที่เหล่านั้นทำการรัน (Run) `BT_Enemy` หรือ `BT_Enemy_EQS` ซึ่งไม่มี Branch `Attack` สิ่งที่ต่างจาก Tag ของบทนั้นเกิดเฉพาะเมื่อ Player โจมตี (Attack ของ Player และนโยบาย Death เป็นของทั้ง Project): บรรทัด `[Damage]` ของ Enemy และใน `L_Ch11`–`L_Ch12` Enemy ที่โดนโจมตีไล่ตาม Player โดยไม่โจมตี ใน `L_Ch10` Player ที่เข้าเขตอันตรายครั้งที่แปดหยุดรับ Input พร้อมบรรทัด `[Combat] Player died`

## ปัญหาที่พบบ่อย

- Enemy ไล่ตามมาถึงแล้วยืนนิ่ง ไม่มีบรรทัด `[Combat]` เลย — ตรวจตามลำดับ: (1) Branch `Attack` อยู่ทางขวาของ `Chase` (`Chase` สำเร็จทุกครั้งที่ `TargetActor` ตั้งอยู่ Branch ทางขวาจึงไม่ถูกถาม) ให้ลากไปไว้ทางซ้ายสุดของ Selector (2) ตัวเลขของระยะ: Move To ของ `Chase` หยุดเมื่อช่องว่างระหว่างแคปซูลไม่เกิน Acceptable Radius บวกร้อยละ 10 ของรัศมี Enemy คือ 150 + 3.4 = 153.4 และ *Attack Range* วัดช่องว่างเดียวกัน คู่ที่ถูกคือ Acceptable Radius 150 กับ *Attack Range* 200 (ช่องว่างที่หยุดน้อยกว่าระยะโจมตี 46.6) หากเพิ่ม Acceptable Radius เกินราว 196 หรือลด *Attack Range* ต่ำกว่าราว 154 Enemy จะหยุดนอกระยะ หากเขียน Task เองโดยวัดระยะจากจุดศูนย์กลางถึงจุดศูนย์กลาง ระยะที่การไล่ตามหยุดคือ 150 + 42 + 1.1 × 34 = 229.4 ซึ่งมากกว่า 200 และ Enemy จะไม่โจมตี Player ที่ยืนนิ่งเลย (3) Instance ของ Enemy ใน `L_Ch13` ยังทำการ Run `BT_Enemy_EQS` (*Behavior Tree Asset* ในหมวด *AI* ของแผง Details) (4) *Target Actor Key* ของ Task ไม่ใช่ `TargetActor` หรือ ROOT ของ `BT_Enemy_Combat` ยังชี้ `BB_Enemy_EQS` แทน `BB_Enemy_Combat`
- Enemy โจมตีทุก 5 วินาที แทน 1.5 วินาที — *Cool Down Time* ของ Decorator Cooldown ยังเป็นค่าเริ่มต้น (Default Value) 5.0
- กดเมาส์ซ้ายแล้วไม่มีบรรทัดใด — `IA_Attack` ยังไม่อยู่ใน `IMC_Default` หรือการจับคู่ไม่ใช่ *Left Mouse Button* หรือ Graph ต่อจากพินอื่นที่ไม่ใช่ *Started* หรือ *Object Types* ของ Sphere Overlap Actors ไม่มี *Pawn* หรือ *Actor Class Filter* ไม่ใช่ `EnemyCharacter` หรืออยู่ห่างเกินระยะ (ทรงกลมรัศมี 200 รอบจุดศูนย์กลางของ Player ถึงแคปซูลของ Enemy เมื่อช่องว่างระหว่างแคปซูลไม่เกิน 158) อีกสาเหตุคือยังไม่ได้ Build ในสถานะล่าสุด `DamageType_Melee` จึงไม่มีในรายการ *Damage Type Class*
- คลิกครั้งเดียวมีบรรทัด `[Damage]` หลายบรรทัด และ Enemy ตายทันที — Graph ต่อจากพิน *Triggered* ซึ่งเกิดทุก Tick ตราบที่ปุ่มถูกกดค้าง (Input Action ที่ไม่มี Trigger) ให้ต่อจาก *Started* หรือเพิ่ม Trigger *Pressed* ให้การจับคู่
- มีบรรทัด `[Damage]` ของ Enemy แต่ไม่มีบรรทัด `Damage from` และ Enemy ที่โดนจากด้านหลังไม่หันมา — ตรวจตามลำดับ: `HealthComponent.cpp` ยังไม่มีการเรียก `ReportDamageEvent` (เอนจิ้น (Engine) ไม่รายงาน Damage ต่อ Perception เอง); *Senses Config* ของ Component AIPerception ใน `BP_EnemyAIController` ยังไม่มี *AI Damage sense config*; Enemy ที่วางใน `L_Ch13` ไม่ได้เลือก *Perception Enabled* (Listener ถูกถอนตอน Possess); หรือ Graph ของ Player ไม่ได้ต่อทั้ง *Event Instigator* และ *Damage Causer* (ไม่มีผู้กระทำให้รายงาน)
- มีบรรทัด `Damage from` แต่ Enemy ไม่หันมาไล่ตาม — ตัวรับไม่ได้ถือว่า Player เป็น Hostile: `BP_ThirdPersonCharacter` ยังไม่ได้ Reparent เป็น `HAPPlayerCharacter` (บทที่ 11) หรือ Decorator ของ `Chase` ไม่ใช่ Observer Aborts *Both*
- Player ตายแล้วยังเดินได้ และไม่มีบรรทัด `[Combat] Player died` — ยังไม่ได้ผูก `On Death (Health)` ใน `BP_ThirdPersonCharacter` (บทที่ 10 ผูกไว้เพียง *On Health Changed*) หากมีบรรทัดนี้แต่ยังเดินได้ พิน *Player Controller* ของ *Disable Input* ไม่ได้ต่อจาก *Get Player Controller* หรือชี้ Controller อื่น
- ไม่พบ *Log From Blueprint* ในรายการ Node — `BP_ThirdPersonCharacter` ยังมีคลาสแม่ (Parent Class) เป็น `HAPBookCharacter` (Function อยู่ใน `HAPPlayerCharacter`; บทที่ 11 ขั้นที่ 2) หรือยังไม่ได้ Build
- Enemy โจมตี Player ที่ตายแล้วต่อ บรรทัด `[Combat] Attack: ... -> 0.00/200.00` ซ้ำทุก 1.5 วินาที — Task ไม่ได้ล้าง `TargetActor` เมื่อเป้าหมายตาย (ส่วนท้ายของ `ExecuteTask()` ในตัวอย่างชุดคำสั่งที่ 13.3)
- Enemy วนกลับมาไล่ตาม Pawn ของ Player ที่ตายแล้ว หรือมีบรรทัด `Damage from` หลังบรรทัด died ของ Enemy — ตัวรับสิ่งเร้ายังไม่มีการเพิกเฉยต่อความตาย (ตัวอย่างชุดคำสั่งที่ 13.6)
- `BT_Enemy_Combat` มี Node ชื่อ `Engage`, `Take Position` หรือ Service *Set default focus* — `BT_Enemy_EQS` ที่ใช้ทำสำเนายังมี Branch ที่บทที่ 12 ถอนออกแล้ว ให้ลบ Selector `Engage`, Sequence `Take Position` และ Service นั้นออก แล้วต่อ Decorator ของ `Chase` ให้อยู่บน Sequence `Chase` ตามภาพโครงสร้างของบท
- แผนที่ก่อนหน้า (`L_Ch07`–`L_Ch12`) มี Enemy โจมตี Player — *Behavior Tree Asset* ถูกตั้งใน Class Defaults ของ Blueprint `BP_Enemy` แทน Instance ที่วางใน `L_Ch13` ให้คืน `BT_Enemy` ใน Class แล้วตั้ง `BT_Enemy_Combat` ที่ Instance ปุ่มลูกศรวนกลับ (*Reset to Default*) ข้างช่องยืนยันว่าค่าของ Instance ต่างจากค่าของ Class
- Enemy ตามทันเสมอ หนีไม่พ้น — *Max Walk Speed* ของ `BP_Enemy` ยังเป็น Default Value 600 ขณะที่ Player เดินที่ 500 ให้ตั้งเป็น 400 ตามขั้นตอนในสูตรการสร้าง `BP_Enemy` ของบทที่ 7 และหลบหลัง Block ที่บังแนวสายตา (Line of Sight) ไม่ใช่วิ่งออกให้ไกล
- Enemy โจมตีถึงได้จากระยะที่ Player โจมตีไม่ถึง — เป็นการออกแบบ: ระยะของ Enemy คือช่องว่าง 200 ระยะของ Player คือช่องว่างประมาณ 158 Enemy ที่ไล่ตามมาหยุดที่ช่องว่างไม่เกิน 153.4 Player ที่ยืนรอจึงโจมตีกลับได้ แต่ Player ที่ถอยออกเล็กน้อยต้องเดินเข้าหา
