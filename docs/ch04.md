# บทที่ 4 — ระบบวัตถุของ Unreal Engine

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 4 คือแท็ก (Tag) `ch04` บทนี้เพิ่มคลาสสาธิตสามคลาส (Class) เข้าไปในโมดูล (Module) `HAPBook` เพื่อสังเกตกลไกสองอย่างที่บทที่ 4 อธิบายไว้ขณะทำงานจริง ได้แก่ ระบบ Reflection (Constructor กับ Class Default Object และการไล่อ่าน `UPROPERTY` ของตนเอง) และ ระบบเก็บขยะอัตโนมัติ (Garbage Collection: GC; การอ้างอิง (Reference) ที่ GC ติดตามกับ Reference ที่ไม่ติดตาม)

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch04` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch04.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch04` แล้วใช้โฟลเดอร์ (Folder) `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch04` ซึ่งมี `ReflectionDemoActor` และ `GcDemoActor` วางไว้แล้วทั้งสองตัว ในขั้นนี้ Output Log จะมีบรรทัด `[Reflection] Constructor: ... (IsTemplate=true)` ปรากฏอยู่แล้วก่อนกด Play ซึ่งเป็นการสร้าง CDO ขณะโหลด Module
5. กด *Play* เมื่อกด Play Player ของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับ Player เดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* พิมพ์ `Reflection` ในช่องกรอง เปรียบเทียบกับบรรทัดในหัวข้อ "จุดตรวจสอบผลลัพธ์" แล้วเปลี่ยนคำกรองเป็น `GC`
7. บรรทัด `[GC] After collection` จะปรากฏหลังบรรทัด `Before` ประมาณ 2 วินาที (ค่า `ReportDelaySeconds` ของ Actor) ผู้อ่านต้องรอให้ครบก่อนหยุด Play

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools (Build Tools for Visual Studio) พร้อมเวิร์กโหลด (Workload) "Desktop development with C++" และ ".NET desktop build tools" (ขั้นตอนอยู่ในภาคผนวก ก ของงานเขียน)
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

File `HAPBook/.vsconfig` เป็นรายการสำหรับ Visual Studio ฉบับเต็ม Rider ไม่ได้ใช้ File นี้ สถานะเริ่มต้นของ Project สำหรับบทนี้คือ Tag `ch02` (บทที่ 3 ไม่มีโค้ด (Code))

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายสองข้อจากการอ่านชุดคำสั่ง (1) สมาชิก (Member) ตัวใดของ `AReflectionDemoActor` จะ **ไม่** ปรากฏในรายการ Property และเพราะเหตุใด (2) วัตถุ (Object) `UGcDemoData` ชิ้นใดในสองชิ้นจะรอดจาก Garbage Collection และเพราะเหตุใด จากนั้นจึงเปรียบเทียบกับ Output Log

กรองด้วยคำว่า `Reflection` ต้องเห็นบรรทัดต่อไปนี้ (บรรทัด `IsTemplate=true` ปรากฏตั้งแต่ก่อนกด Play และบรรทัด `IsTemplate=false` อาจปรากฏมากกว่าหนึ่งครั้ง)

```
LogTemp: [Reflection] Constructor: ReflectionDemoActor (IsTemplate=true)
LogTemp: [Reflection] Constructor: ReflectionDemoActor (IsTemplate=false)
LogTemp: [Reflection] Property: Health (IntProperty)
LogTemp: [Reflection] Property: Codename (StrProperty)
LogTemp: [Reflection] Property: Speed (FloatProperty)
```

กรองด้วยคำว่า `GC` ต้องเห็นสองบรรทัดต่อไปนี้ โดยบรรทัดที่สองมาหลังบรรทัดแรกประมาณ 2 วินาที

```
LogTemp: [GC] Before collection: Tracked=valid, Untracked=valid
LogTemp: [GC] After collection: Tracked=valid, Untracked=INVALID
```

- `HiddenCounter` ไม่ปรากฏ เพราะไม่มี `UPROPERTY` จึงไม่ถูก UHT ลงทะเบียน ระบบ Reflection เห็นเฉพาะสิ่งที่ UHT ลงทะเบียนไว้เท่านั้น ชื่อชนิดในวงเล็บคือชื่อ Class `FProperty` ของแต่ละ Member (`FIntProperty`, `FStrProperty`, `FFloatProperty` โดยตัดคำนำหน้า (Prefix) F ออก)
- บรรทัด `IsTemplate=true` คือ Constructor ของ Class Default Object ซึ่งทำงานขณะโหลด Module ก่อนที่ World ใด ๆ จะมีอยู่ นี่คือเหตุผลที่ Constructor ห้ามเรียก `GetWorld()` บรรทัด `IsTemplate=false` คืออินสแตนซ์ (Instance) จริง ปรากฏได้หลายครั้ง (ตอนวางในแผนที่ และตอน Play-In-Editor คัดลอกแผนที่ไปเล่น)
- `TrackedData` รอด เพราะถูกถือด้วย `UPROPERTY() TObjectPtr` ซึ่ง GC มองเห็นจาก Root Set ส่วน Object ที่สอง `INVALID` เพราะไม่มี Reference อย่างเข้มที่ใดเลย (ตัวแปร (Variable) ภายใน `BeginPlay` สิ้นอายุไปแล้ว และ `TWeakObjectPtr` ไม่รั้ง Object ไว้) จึงไม่สามารถเข้าถึงได้จาก Root Set และถูก GC เก็บในรอบ Full Purge ที่ `ForceGarbageCollection(true)` ร้องขอ ซึ่งเอนจิ้น (Engine) ดำเนินการในรอบ Tick ของเฟรม (Frame) ถัดไป

การทดลองเพิ่มเติม: เพิ่ม `UPROPERTY(EditAnywhere) bool bArmed = false;` ต่อท้าย `Speed` ในไฟล์ Header (Header File) แล้วปิด ตัวแก้ไข (Editor) ทำการคอมไพล์ (Compile) ใหม่ และ Play บรรทัด `Property: bArmed (BoolProperty)` จะปรากฏต่อจาก `Speed` ตามลำดับการประกาศ

## ปัญหาที่พบบ่อย

- **เพิ่ม Class File ใหม่แล้ว Editor ไม่รู้จัก `ReflectionDemoActor` หรือ `GcDemoActor` ในแผง Place Actors** — Live Coding ไม่รองรับการเพิ่ม `UCLASS` ใหม่หรือการแก้ไข `UPROPERTY` ใน Header File ให้ปิด Editor สั่ง Build ใหม่จาก Rider แล้วเปิด Editor อีกครั้ง
- **`error: ... .generated.h must be the last include`** — บรรทัด `#include "GcDemoActor.generated.h"` (หรือของ Class อื่น) ต้องเป็น `#include` บรรทัดสุดท้ายของ Header File ให้ย้าย `#include` อื่นขึ้นไปไว้ก่อนหน้า
- **การ Compile ไม่ผ่านโดยแจ้งข้อผิดพลาดที่บรรทัด `UCLASS()` หรือชื่อ Class** — ขาดมาโคร (Macro) `GENERATED_BODY()` ในบรรทัดแรกของตัว Class Macro นี้จำเป็นสำหรับทุก Class ที่กำกับด้วย `UCLASS()` เพราะเป็นจุดที่ UHT แทรก Code สนับสนุน
- **บรรทัด `Constructor: ... (IsTemplate=true)` ปรากฏตั้งแต่ก่อนกด Play** — เป็นพฤติกรรมที่ถูกต้อง นี่คือการสร้าง Class Default Object ขณะ Engine โหลด Module `HAPBook` และเป็นหลักฐานว่า Constructor ทำงานก่อนที่ World จะมีอยู่
- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch04` และได้กด *Play* แล้ว หากผู้อ่านลบ Actor สาธิตออกจากแผนที่ไป ให้ค้นหา `ReflectionDemoActor` และ `GcDemoActor` ในแผง *Place Actors* แล้วลากกลับไปวางใหม่
- **ไม่เห็นบรรทัด `[GC] After collection`** — บรรทัดนี้มาหลังบรรทัด `Before` ประมาณ 2 วินาที หากหยุด Play ก่อนเวลา ตัวจับเวลาจะถูกยกเลิก ให้ Play แล้วรออย่างน้อย 3 วินาที
- **บรรทัด `After` แสดง `Untracked=valid`** — Garbage Collection ยังไม่เกิดขึ้นในรอบนั้น เพราะ `ForceGarbageCollection` เป็นการร้องขอให้ Engine ทำ GC "ในโอกาสถัดไป" และ Engine อาจเลื่อนออกไปหากขณะนั้นมีการโหลดแบบไม่ประสานเวลา (Async Loading) หรือมีการล็อก GC อยู่ ให้หยุดแล้ว Play ใหม่ ผลที่คงที่คือ Object ที่ไม่มี Reference อย่างเข้มจะถูก GC เก็บในรอบแรกที่ GC ทำงานจริง เพราะไม่สามารถเข้าถึงได้จาก Root Set ไม่ใช่เรื่องของโอกาส
