# บทที่ 4 — ระบบอ็อบเจกต์ของ Unreal Engine

โฟลเดอร์ `HAPBook/` คือโปรเจกต์ Unreal Engine 5.8 ที่ใช้ตั้งแต่บทที่ 2 เป็นต้นไป สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 4 คือแท็ก `ch04` (หรือไฟล์ `ch04.zip` ในหน้า Releases) บทนี้เพิ่มคลาสสาธิตสามคลาสเข้าไปในโมดูล `HAPBook` เพื่อสังเกตกลไกสองอย่างที่บทที่ 4 อธิบายไว้ขณะทำงานจริง ได้แก่ ระบบ Reflection (คอนสตรัคเตอร์กับ Class Default Object และการไล่อ่าน `UPROPERTY` ของตนเอง) และ Garbage Collection (การอ้างอิงที่ GC ติดตามกับการอ้างอิงที่ไม่ติดตาม)

## เริ่มต้น

1. ดาวน์โหลด `ch04.zip` จากหน้า Releases แล้วแตกไฟล์ (หรือใช้โฟลเดอร์ `companion/HAPBook/` ที่แท็ก `ch04`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) Rider จะสร้างโมเดลโปรเจกต์จากไฟล์ `.uproject` โดยไม่ต้องใช้ไฟล์โซลูชัน หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" เรื่อง .NET runtime ก่อน ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` ใน File Explorer เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันที่ได้ด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แผนที่เริ่มต้น `L_Book` จะเปิดขึ้นโดยอัตโนมัติ ในขั้นนี้ Output Log จะมีบรรทัด `[Reflection] Constructor: ... (IsTemplate=true)` ปรากฏอยู่แล้วก่อนกด Play ซึ่งเป็นการสร้าง CDO ขณะโหลดโมดูล
5. ในแผง *Place Actors* ค้นหา `ReflectionDemoActor` แล้วลากไปวางในแผนที่ `L_Book` จากนั้นค้นหา `GcDemoActor` แล้ววางเช่นกัน ต้องวางทั้งสอง Actor
6. กด *Play*
7. เปิดหน้าต่าง *Window → Output Log* พิมพ์ `Reflection` ในช่องกรอง เปรียบเทียบกับบรรทัดในหัวข้อ "จุดตรวจสอบผลลัพธ์" แล้วเปลี่ยนคำกรองเป็น `GC`
8. บรรทัด `[GC] After collection` จะปรากฏหลังบรรทัด `Before` ประมาณ 2 วินาที (ค่า `ReportDelaySeconds` ของ Actor) ผู้อ่านต้องรอให้ครบก่อนหยุด Play

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

ไฟล์ `HAPBook/.vsconfig` ระบุองค์ประกอบของ Build Tools ที่ต้องติดตั้งอย่างครบถ้วน สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch02` (บทที่ 3 ไม่มีโค้ด)

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายสองข้อจากการอ่านชุดคำสั่ง (1) สมาชิกตัวใดของ `AReflectionDemoActor` จะ **ไม่** ปรากฏในรายการ Property และเพราะเหตุใด (2) วัตถุ `UGcDemoData` ชิ้นใดในสองชิ้นจะรอดจากการเก็บกวาด และเพราะเหตุใด จากนั้นจึงเปรียบเทียบกับ Output Log

กรองด้วยคำว่า `Reflection` ต้องเห็นบรรทัดต่อไปนี้ (บรรทัด `IsTemplate=true` ปรากฏตั้งแต่ก่อนกด Play และบรรทัด `IsTemplate=false` อาจปรากฏมากกว่าหนึ่งครั้ง)

```
LogTemp: [Reflection] Constructor: ReflectionDemoActor (IsTemplate=true)
LogTemp: [Reflection] Constructor: ReflectionDemoActor (IsTemplate=false)
LogTemp: [Reflection] Property: Health (IntProperty)
LogTemp: [Reflection] Property: Codename (StrProperty)
LogTemp: [Reflection] Property: Speed (FloatProperty)
```

กรองด้วยคำว่า `GC` ต้องเห็นสองบรรทัดต่อไปนี้ โดยบรรทัดที่สองมาหลังบรรทัดแรกประมาณ 2 วินาที

```
LogTemp: [GC] Before collection: Tracked=valid, Untracked=valid
LogTemp: [GC] After collection: Tracked=valid, Untracked=INVALID
```

- `HiddenCounter` ไม่ปรากฏ เพราะไม่มี `UPROPERTY` จึงไม่ถูก UHT ลงทะเบียน ระบบ Reflection เห็นเฉพาะสิ่งที่ UHT ลงทะเบียนไว้เท่านั้น ชื่อชนิดในวงเล็บคือชื่อคลาส `FProperty` ของแต่ละสมาชิก (`FIntProperty`, `FStrProperty`, `FFloatProperty` โดยตัดคำนำหน้า F ออก)
- บรรทัด `IsTemplate=true` คือคอนสตรัคเตอร์ของ Class Default Object ซึ่งทำงานขณะโหลดโมดูล ก่อนที่ World ใด ๆ จะมีอยู่ นี่คือเหตุผลที่คอนสตรัคเตอร์ห้ามเรียก `GetWorld()` บรรทัด `IsTemplate=false` คืออินสแตนซ์จริง ปรากฏได้หลายครั้ง (ตอนวางในแผนที่ และตอน Play-In-Editor คัดลอกแผนที่ไปเล่น)
- `TrackedData` รอด เพราะถูกถือด้วย `UPROPERTY() TObjectPtr` ซึ่ง GC มองเห็นจาก Root Set ส่วนวัตถุที่สอง `INVALID` เพราะไม่มีการอ้างอิงอย่างเข้มที่ใดเลย (ตัวแปรภายใน `BeginPlay` สิ้นอายุไปแล้ว และ `TWeakObjectPtr` ไม่รั้งวัตถุไว้) จึงไม่สามารถเข้าถึงได้จาก Root Set และถูกเก็บกวาดในรอบ Full Purge ที่ `ForceGarbageCollection(true)` ร้องขอ ซึ่งเอนจินดำเนินการในรอบ Tick ของเฟรมถัดไป

การทดลองเพิ่มเติม: เพิ่ม `UPROPERTY(EditAnywhere) bool bArmed = false;` ต่อท้าย `Speed` ในไฟล์ Header แล้วปิด Editor คอมไพล์ใหม่ และ Play บรรทัด `Property: bArmed (BoolProperty)` จะปรากฏต่อจาก `Speed` ตามลำดับการประกาศ

## ปัญหาที่พบบ่อย

- **เพิ่มไฟล์คลาสใหม่แล้ว Editor ไม่รู้จัก `ReflectionDemoActor` หรือ `GcDemoActor` ในแผง Place Actors** — Live Coding ไม่รองรับการเพิ่ม `UCLASS` ใหม่หรือการแก้ไข `UPROPERTY` ในไฟล์ Header ให้ปิด Editor สั่ง Build ใหม่จาก Rider แล้วเปิด Editor อีกครั้ง
- **`error: ... .generated.h must be the last include`** — บรรทัด `#include "GcDemoActor.generated.h"` (หรือของคลาสอื่น) ต้องเป็น `#include` บรรทัดสุดท้ายของไฟล์ Header ให้ย้าย `#include` อื่นขึ้นไปไว้ก่อนหน้า
- **คอมไพล์ไม่ผ่านโดยแจ้งข้อผิดพลาดที่บรรทัด `UCLASS()` หรือชื่อคลาส** — ขาดมาโคร `GENERATED_BODY()` ในบรรทัดแรกของตัวคลาส มาโครนี้จำเป็นสำหรับทุกคลาสที่กำกับด้วย `UCLASS()` เพราะเป็นจุดที่ UHT แทรกโค้ดสนับสนุน
- **บรรทัด `Constructor: ... (IsTemplate=true)` ปรากฏตั้งแต่ก่อนกด Play** — เป็นพฤติกรรมที่ถูกต้อง นี่คือการสร้าง Class Default Object ขณะเอนจินโหลดโมดูล `HAPBook` และเป็นหลักฐานว่าคอนสตรัคเตอร์ทำงานก่อนที่ World จะมีอยู่
- **ไม่เห็นบรรทัด `[GC] After collection`** — บรรทัดนี้มาหลังบรรทัด `Before` ประมาณ 2 วินาที หากหยุด Play ก่อนเวลา ตัวจับเวลาจะถูกยกเลิก ให้ Play แล้วรออย่างน้อย 3 วินาที
- **บรรทัด `After` แสดง `Untracked=valid`** — การเก็บกวาดยังไม่เกิดขึ้นในรอบนั้น เพราะ `ForceGarbageCollection` เป็นการร้องขอให้เอนจินเก็บกวาด "ในโอกาสถัดไป" และเอนจินอาจเลื่อนออกไปหากขณะนั้นมีการโหลดแบบไม่ประสานเวลา (Async Loading) หรือมีการล็อก GC อยู่ ให้หยุดแล้ว Play ใหม่ ผลที่คงที่คือวัตถุที่ไม่มีการอ้างอิงอย่างเข้มจะถูกเก็บกวาดในรอบแรกที่ GC ทำงานจริง เพราะไม่สามารถเข้าถึงได้จาก Root Set ไม่ใช่เรื่องของโอกาส
- **เปิด `HAPBook.uproject` ด้วย Rider ไม่ได้ หรือ UnrealBuildTool เริ่มทำงานไม่สำเร็จ ทั้งที่ไฟล์โซลูชันยังเปิดได้** — Rider เรียก UnrealBuildTool ผ่าน `dotnet.exe` ที่อยู่ใน PATH ของระบบ ส่วน UnrealBuildTool ของ UE 5.8 ต้องการ .NET runtime รุ่นที่ระบุในไฟล์ `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` (ค่า `framework.version`) วิธีวินิจฉัย: รัน `dotnet --list-runtimes` ใน Command Prompt หากไม่มีรุ่นหลักที่ตรงกับค่าดังกล่าว ให้แก้ด้วยวิธีใดวิธีหนึ่ง (1) วิธีหลัก: ใน Rider เปิด *Settings → Build, Execution, Deployment → Toolset and Build* แล้วตั้ง ".NET CLI executable path" เป็น `Engine\Binaries\ThirdParty\DotNet\<รุ่น>\win-x64\dotnet.exe` ของเอนจิน จากนั้นเปิด Rider ใหม่ (2) ทางเลือก: ติดตั้ง .NET SDK x64 รุ่นที่ตรงกันจาก dotnet.microsoft.com เปิดเครื่องใหม่ แล้วสร้างไฟล์โปรเจกต์ใหม่ (*Generate project files*)
- **เปิดโปรเจกต์แล้ว Rider เปิดหน้าต่างที่สองขึ้นมาเอง** — ค่า *Editor Preferences → General → Source Code → Source Code Editor* ใน Unreal Editor ต้องตรงกับวิธีเปิด กล่าวคือ "Rider Uproject" เมื่อเปิดผ่านไฟล์ `.uproject` และ "Rider" เมื่อเปิดผ่านไฟล์โซลูชัน หากไม่ตรงกัน Editor จะเปิด Rider อีกหน้าต่างหนึ่งเมื่อสั่งเปิดโค้ด
