# บทที่ 12 — ระบบสืบค้นสภาพแวดล้อม

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 12 คือแท็ก `ch12` บทนี้ให้ศัตรูคิดเชิงพื้นที่ด้วย Environment Query System (EQS) สองคำถาม คำถามแรก `EQS_TacticalPoint` เลือกจุดยืนที่มีแนวสายตาถึงผู้เล่นและห่างประมาณ 600 หน่วย คำถามที่สอง `EQS_SearchHidden` เลือกจุดใกล้ตำแหน่งที่พบล่าสุดที่ศัตรูมองไม่เห็น ฝั่ง C++ มี Test ที่เขียนเอง `UEnvQueryTest_DistanceBand` และ Context สามคลาส: `UEnvQueryContext_Target` (ตัวช่วยสาธิตในตัวแก้ไข: Actor ที่ติด Tag `EQSTeachingAid`) กับคลาสลูกสองคลาส `UEnvQueryContext_PerceivedTarget` (คีย์ `TargetActor`) และ `UEnvQueryContext_LastKnownLocation` (คีย์ `LastKnownLocation`) ซึ่งใช้ตัวช่วยสาธิตเมื่อผู้ถามไม่มี Blackboard Controller ได้ผู้สังเกตคีย์ผลของ Query ที่บันทึกบรรทัด `[EQS]` และวาดทรงกลมดีบัก (เครื่องมือวัด) และการจำแนกการมาถึงจุดยืนและจุดซ่อน การเปลี่ยนแปลงของ Behavior Tree ทั้งหมดอยู่ใน `BT_Enemy_EQS` (สำเนาของ `BT_Enemy`) กับ Blackboard `BB_Enemy_EQS` (Parent = `BB_Enemy`) ส่วน `BT_Enemy` และ `BB_Enemy` ไม่เปลี่ยน ศัตรูที่วางใน `L_Ch12` เลือก `BT_Enemy_EQS` ผ่าน *Behavior Tree Asset* ของอินสแตนซ์ แผนที่ `L_Ch12` เป็นสำเนาของ `L_Ch11`

## เริ่มต้น

โปรเจกต์ประกอบเก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch12` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch12.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch12` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch12` ซึ่งมี `BP_Enemy` หนึ่งตัว (กา *Perception Enabled* และตั้ง *Behavior Tree Asset* เป็น `BT_Enemy_EQS` ที่อินสแตนซ์แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, `TP_Target` (ตัวช่วยสาธิตในตัวแก้ไข: Tag `EQSTeachingAid` และยกจากพื้น 100 หน่วย), `BP_EQSTester` (*Query Template* = `EQS_TacticalPoint`, กา *Run Query On Selection Changed*), หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone` และ `EnemySpawner` (*Spawn Count* 0) ของบทก่อน เมื่อกด Play ตัวละครผู้เล่นเป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของผู้อ่านคือสิ่งเร้าที่ AI รับรู้

บทนี้สร้างเป็นสี่ขั้น แท็ก `ch12` คือสถานะหลังขั้นที่ 4: `EQS_TacticalPoint` ใช้ DistanceBand (ขั้นที่ 2) และ Context `EnvQueryContext_PerceivedTarget` (ขั้นที่ 3) แล้ว การทดลองแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — อ่าน Query (ในตัวแก้ไข ไม่ต้อง Play):** คลิกเลือก `BP_EQSTester` ในแผนที่ ทรงกลมของ Query ปรากฏรอบ `TP_Target` (Testing Pawn ไม่มี Blackboard Context จึงคืนตัวช่วยสาธิต) ทำการกระทำที่ 1, 2, 3 และ 5 ของตาราง "การตรวจ Query แบบทำนายก่อนดู" ในบททีละข้อ เขียนคำทำนายก่อนดู แล้วคืนค่าก่อนข้อถัดไป ในแท็กนี้จุดคะแนนสูงสุดอยู่บนวงแหวนประมาณ 600 หน่วยรอบ `TP_Target` เพราะ Query มี DistanceBand ของขั้นที่ 2 แทน Distance ของขั้นที่ 1 แล้ว
6. **ขั้นที่ 2 — Test ที่เขียนเอง:** เปิด `EQS_TacticalPoint` เลือก Test DistanceBand ตั้ง *Preferred Distance* เป็น 1000 แล้ว Save ดูว่าวงแหวนของจุดคะแนนสูงขยายออก ขณะที่จุดสีน้ำเงินไม่เปลี่ยน แล้วคืนค่าเป็น 600 และ Save
7. **ขั้นที่ 3 — จุดยืนเทียบกับผู้เล่นที่รับรู้ได้:** กด Play เดินเข้าขอบเขตการมองเห็นของศัตรูในที่โล่ง ยืนนิ่ง ศัตรูต้องหยุดลาดตระเวน ทรงกลมสีเขียวปรากฏห่างจากผู้เล่นประมาณ 600 หน่วย และศัตรูเดินไปหยุดที่นั่น เดินไปยืนอีกที่หนึ่งที่ศัตรูยังมองเห็น ศัตรูย้ายจุดยืนตามหลังหนึ่งวินาที ระหว่างนั้นกด Apostrophe (`'`) แล้วแป้นตัวเลข 3 เพื่อดูตารางของ Query ที่ศัตรูรันจริงในหมวด EQS ของ Gameplay Debugger
8. **ขั้นที่ 4 — ค้นหาเมื่อแนวสายตาขาด:** ใน Play เดียวกัน ให้ศัตรูเห็นผู้เล่น แล้ววิ่งไปหลบหลังบล็อกที่สูงกว่าตัวละคร ศัตรูต้องเดินไปยังตำแหน่งที่พบล่าสุด ทรงกลมสีส้มปรากฏที่จุดหนึ่งที่มองไม่เห็นจากตำแหน่งนั้น ศัตรูเดินไปตรวจ หยุดสองวินาที แล้วกลับไปลาดตระเวน จากนั้นหลบอยู่ต่อแล้วกระโดดหนึ่งครั้งภายในระยะ 1500 ศัตรูต้องเดินมายังจุดที่กระโดดโดยไม่มีการค้นหาจุดซ่อน

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch11` บทนี้เพิ่มไฟล์ใหม่สี่คู่ แก้ `EnemyAIController.{h,cpp}` และ `EnemyCharacter.h` เฉพาะส่วนที่กำกับว่า "บทที่ 12" และไม่แตะ `HAPBook.Build.cs` (EQS ทั้งหมด รวมถึง `EQSTestingPawn` อยู่ในโมดูล `AIModule` ซึ่งมีอยู่แล้ว) ปลั๊กอิน Environment Query Editor ซึ่งจำเป็นต่อการสร้าง Asset ของ Query เปิดใช้โดยปริยายใน UE 5.8

## จุดตรวจสอบผลลัพธ์

**ขั้นที่ 1 และ 2 (ในตัวแก้ไข):** ไม่มีบรรทัดใน Output Log จุดตรวจคือภาพของ EQS Testing Pawn เทียบกับคำทำนาย: ตารางอยู่รอบ `TP_Target` ไม่ใช่รอบ Testing Pawn จุดที่บล็อกบังจากมุมของ `TP_Target` เป็นสีน้ำเงินเข้มพร้อมป้าย Trace จุดคะแนนสูงอยู่บนวงแหวนตามค่า *Preferred Distance* ทางด้านของ Testing Pawn และการเปลี่ยน *Preferred Distance* ไม่เปลี่ยนชุดจุดสีน้ำเงิน

**ขั้นที่ 3 — จุดยืน:** สามบรรทัดนี้ตามลำดับ (กรอง Output Log ด้วย `[EQS]` และ `[Perception]`; บรรทัด Teams ของบทที่ 11 ปรากฏระหว่างบรรทัดที่หนึ่งกับสอง) บรรทัดแรกปรากฏก่อนบรรทัด `[AI] Possessed` ของบทที่ 7 และบรรทัดที่สามปรากฏซ้ำเมื่อจุดที่เลือกเปลี่ยน ก่อนกด Play ผู้อ่านควรทำนายว่าศัตรูจะหยุดห่างจากผู้เล่นประมาณเท่าใด

```
LogTemp: [EQS] BT_Enemy_EQS: observing query results
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
LogTemp: [EQS] Engage: tactical point chosen
```

**ขั้นที่ 4 — ค้นหา:** สามบรรทัดนี้ตามลำดับเมื่อหลบพ้นแนวสายตา ไม่มีบรรทัด `[AI] Reached waypoint` ที่จุดซ่อน ก่อนหลบผู้อ่านควรทำนายว่าทรงกลมสีส้มจะอยู่ที่ใดเทียบกับบล็อกที่ใช้หลบ

```
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
LogTemp: [EQS] Search: checking hidden spot
```

ที่มาของแต่ละบรรทัด

- บรรทัด `observing`: จาก `OnPossess()` เมื่อ Blackboard ของ Behavior Tree ที่รันมีคีย์ `TacticalLocation` หรือ `SearchLocation` ชื่อในบรรทัดคือ Behavior Tree ของอินสแตนซ์ จึงยืนยันว่า `L_Ch12` รัน `BT_Enemy_EQS`
- บรรทัด `Engage`: จาก `OnQueryResultChanged()` เมื่อ Run EQS Query ของกิ่ง `Take Position` เขียน `TacticalLocation` (ผู้สังเกตถูกเรียกเฉพาะเมื่อค่าเปลี่ยน; การล้างคีย์เมื่อ Query ล้มเหลวไม่ให้บรรทัด) ทรงกลมสีเขียวอยู่ที่ค่าเดียวกับที่ Move To ถัดไปอ่าน
- บรรทัด `Sight gained`/`Sight lost`: บรรทัดของบทที่ 11 ทุกอักขระ
- บรรทัด `Investigate`: บรรทัดของบทที่ 8 ทุกอักขระ จาก `WasInvestigateArrival()` เมื่อศัตรูถึง `AlertLocation` (= ตำแหน่งที่พบล่าสุดเมื่อแนวสายตาขาด) Decorator ของ `Investigate` เป็น Lower Priority จึงไม่ยุติกิ่งของตนเอง และการค้นหาทำงานต่อหลังบรรทัดนี้
- บรรทัด `Search`: จาก `OnQueryResultChanged()` เมื่อ Run EQS Query ของส่วน `Search` เขียน `SearchLocation` ทรงกลมสีส้มอยู่ที่ค่านั้น ส่วนนี้ทำงานเฉพาะเมื่อ `AlertLocation` เท่ากับ `LastKnownLocation` (Decorator Compare BBEntries) การได้ยินเสียงจึงไม่มีบรรทัดนี้

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08`, `L_Ch09`, `L_Ch10` แล้ว `L_Ch11` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[EQS]` ใดเลย ใน `L_Ch11` ศัตรูยังวิ่งเข้าหาผู้เล่นจนเหลือ 150 ตามบทที่ 11: ศัตรูในแผนที่เหล่านั้นรัน `BT_Enemy` (ค่าของคลาส) ซึ่ง Blackboard ไม่มีคีย์ของบทนี้ ผู้สังเกตจึงไม่ถูกลงทะเบียน และการจำแนกการมาถึงของบทนี้คืนเท็จเสมอ

## ปัญหาที่พบบ่อย

- **กับดักของ Bool Match: จุดที่มองเห็นเป้าหมายชัดเจนเป็นสีน้ำเงิน และจุดหลังบล็อกได้คะแนน** — Bool Match ของ Trace ใน `EQS_TacticalPoint` ยังกาอยู่ (ค่าเริ่มต้นของ Test ทุกรายการ) ซึ่งหมายถึง *require hit* = ผ่านเมื่อเส้นถูกบัง ให้เอาเครื่องหมายออกและตรวจว่าคำอธิบายบน Node อ่านว่า *require not hit* ใน `EQS_SearchHidden` เป็นตรงกันข้าม: ต้องกาไว้ (*require hit*) หากไม่กา ศัตรูจะ "ค้นหา" จุดในที่โล่งที่ตนมองเห็นอยู่แล้ว โดยบรรทัด `Search` ยังปรากฏตามปกติ
- **กับดักของ Context ผู้เล่น: ตารางปรากฏรอบ Testing Pawn (หรือรอบศัตรูใน Gameplay Debugger) แทนรอบเป้าหมาย** — ช่อง *Generate Around* (หรือ *Context*/*Distance To* ของ Test) ยังเป็นค่าเริ่มต้น `EnvQueryContext_Querier` ทุกช่องของ Generator และ Test มีค่าเริ่มต้นเป็นผู้ถาม ให้ตั้งเป็น Context ของเป้าหมายตามบท (ใน `EQS_TacticalPoint` ช่องเดียวที่เป็นผู้ถามคือ Pathfinding; ใน `EQS_SearchHidden` คือ Trace และ Pathfinding)
- **Query ได้ 0 รายการ (Testing Pawn ไม่แสดงทรงกลมใด หรือศัตรูวิ่งเข้าหาผู้เล่นจนเหลือ 150 โดยไม่มีบรรทัด `Engage`)** — Context ไม่ให้ข้อมูล ในตัวแก้ไข: ไม่มี Actor ที่ติด Tag `EQSTeachingAid` ในแผนที่ (สะกดไม่ตรงกับ `TeachingAidTag` ทุกอักขระ หรือ `TP_Target` ถูกลบ) ขณะเล่น: Context ทั้งสามช่องของ `EQS_TacticalPoint` ยังเป็น `EnvQueryContext_Target` และ `TP_Target` ถูกลบ (แบบฝึกหัดข้อ 7) อีกสาเหตุคือตารางทั้งตารางฉายลง NavMesh ไม่ได้ (กด `P` ต้องเห็นพื้นสีเขียวรอบเป้าหมาย) เมื่อ Query ได้ 0 รายการ กิ่ง `Engage` ใช้ `Chase` เป็นทางสำรอง พฤติกรรมจึงดูเหมือนบทที่ 11 ดูจำนวนรายการได้จากหมวด EQS ของ Gameplay Debugger
- **ทุกจุดใน Testing Pawn มีคะแนนเท่ากัน** — Test ที่ควรให้คะแนนถูกตั้งเป็น *Filter Only* (Filter Only ไม่ให้คะแนน รายการที่ผ่านทุกตัวกรองจึงเสมอกัน และ Single Best Item เลือกรายการแรกในกลุ่มที่เท่ากัน) ให้ตรวจ *Test Purpose* ของ Distance/DistanceBand และ Pathfinding ว่าเป็น *Score Only*
- **ทุกจุดเป็นสีน้ำเงินทันทีหลังเพิ่ม Distance หรือ DistanceBand** — *Test Purpose* ยังเป็นค่าเริ่มต้น *Filter and Score* ซึ่งมี *Filter Type* Range และขอบทั้งสองเป็น 0 จึงตัดทุกรายการที่มีค่ามากกว่า 0 ป้ายบนทรงกลมสีน้ำเงินบอกชื่อ Test ที่ทำให้ไม่ผ่าน ให้ตั้งเป็น *Score Only*
- **ทุกจุดเป็นสีน้ำเงินพร้อมป้าย Pathfinding** — Testing Pawn ไม่ได้ยืนบน NavMesh (ลอยสูงหรืออยู่นอกพื้นสีเขียว) เส้นทางจากผู้ถามจึงหาไม่ได้ และ *Skip Unreachable* ของ Pathfinding (ค่าเริ่มต้นกาไว้) ตัดรายการที่ไม่มีเส้นทางออกแม้ Test จะเป็น Score Only ให้วาง Testing Pawn บนพื้นสีเขียว
- **Testing Pawn ไม่แสดงอะไรเลย** — *Query Template* ของ `BP_EQSTester` ที่วางในแผนที่ว่างหรือชี้ Asset ผิด หรือ Query ได้ 0 รายการ (ข้อก่อนหน้า) หรือเอาเครื่องหมาย *Draw Failed Items* ออกขณะที่ทุกรายการไม่ผ่าน
- **ย้าย `TP_Target` แล้วภาพไม่เปลี่ยน** — Testing Pawn รัน Query ใหม่เฉพาะเมื่อตัวเองถูกย้าย เมื่อ Asset ของ Query ถูกบันทึก หรือเมื่อการเลือกเปลี่ยนโดยกา *Run Query On Selection Changed* ไว้ ให้คลิกเลือก Actor อื่น หรือขยับ Testing Pawn เล็กน้อย การย้าย Context ไม่แจ้ง Pawn เอง
- **ไม่พบ DistanceBand ในรายการ Add Test หรือไม่พบ Context ของบทในรายการให้เลือก** — โค้ด C++ ยังไม่ได้คอมไพล์ในสถานะล่าสุด สั่ง Build ใน Rider ให้เสร็จ แล้วเปิด Unreal Editor ใหม่ (ดู "ปัญหาที่พบบ่อย" ของ `docs/ch07.md` เรื่องคลาสใหม่กับ Live Coding)
- **ไม่มีบรรทัด `observing` และศัตรูวิ่งเข้าหาผู้เล่นจนเหลือ 150 เหมือนบทที่ 11** — อินสแตนซ์ของ `BP_Enemy` ใน `L_Ch12` ยังรัน `BT_Enemy`: *Behavior Tree Asset* ในหมวด *AI* ของแผง Details (เลือก Actor ในแผนที่) ยังไม่ได้ตั้งเป็น `BT_Enemy_EQS` หรือ Build ก่อนที่ `BehaviorTreeAsset` จะเป็น `EditAnywhere` (ช่องจึงไม่ปรากฏที่อินสแตนซ์) หรือ Blackboard ของ `BT_Enemy_EQS` ไม่มีคีย์ `TacticalLocation`
- **บรรทัด `Engage` ปรากฏ แต่ศัตรูไปยืนรอบ `TP_Target` แทนรอบผู้เล่น** — Context ของ `EQS_TacticalPoint` ยังเป็น `EnvQueryContext_Target` ซึ่งคืนตัวช่วยสาธิตเสมอโดยไม่ดูผู้ถาม (แบบฝึกหัดข้อ 7) ให้ตั้งทั้งสามช่องเป็น `EnvQueryContext_PerceivedTarget`
- **Node ใน `BT_Enemy_EQS` แสดงคีย์เป็นสีแดงหรือไม่มีคีย์ใหม่ให้เลือก** — Node ROOT ของ `BT_Enemy_EQS` ยังชี้ `BB_Enemy` (ตั้ง *Blackboard Asset* เป็น `BB_Enemy_EQS`) หรือ *Parent* ของ `BB_Enemy_EQS` ไม่ได้ตั้งเป็น `BB_Enemy` (คีย์ของบทก่อนหน้าจึงหายไปจาก Blackboard ลูก)
- **หลบแล้วศัตรูเดินไปยังตำแหน่งที่พบล่าสุด หยุดสองวินาที และไม่มีบรรทัด `Search`** — ส่วน `Search` ไม่ทำงาน: Decorator Compare BBEntries ตั้งคีย์ผิด (ต้องเป็น `AlertLocation` กับ `LastKnownLocation` และ *Is Equal To*) หรือ `BB_Enemy_EQS` ไม่มีคีย์ `SearchLocation` หรือ Query ไม่พบจุดซ่อน (Run EQS Query ล้มเหลว และ Selector ไปยัง Wait 2.0 ซึ่งเป็นผลที่ออกแบบไว้) ดูหมวด EQS ของ Gameplay Debugger
- **กระโดดแล้วมีบรรทัด `Search`** — Decorator Compare BBEntries หายไปจาก `Search` หรือตั้ง *Is Not Equal To* การค้นหาต้องเกิดเฉพาะเมื่อแนวสายตาขาด
- **หลังการค้นหา มีบรรทัด `[AI] Reached waypoint` ที่จุดซ่อน หรือศัตรูข้ามจุดลาดตระเวน** — `WasSearchArrival()` ไม่ถูกตรวจใน `OnMoveCompleted()` ก่อนการเลื่อนจุดลาดตระเวน (หรือไม่ล้าง `SearchLocation` หลังใช้)
- **ศัตรูใน `L_Ch11` เริ่มยืนห่าง 600 หรือค้นหาจุดซ่อน** — แก้ `BT_Enemy` แทน `BT_Enemy_EQS` หรือตั้ง *Behavior Tree Asset* ใน Class Defaults ของ `BP_Enemy` แทนอินสแตนซ์ใน `L_Ch12` ค่าของคลาสมีผลกับศัตรูทุกแผนที่ ให้คืน `BT_Enemy` ในคลาส และตั้ง `BT_Enemy_EQS` เฉพาะอินสแตนซ์
- **มองไม่เห็นทรงกลมสีเขียวหรือสีส้ม** — ทรงกลมอยู่ 3 วินาทีแล้วหายไป หรือรันในบิลด์ Shipping/Test ซึ่งไม่วาดดีบัก ทรงกลมเป็นเครื่องมือวัดเท่านั้น
