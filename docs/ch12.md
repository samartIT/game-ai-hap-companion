# บทที่ 12 — ระบบสืบค้นสภาพแวดล้อม

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 12 คือแท็ก (Tag) `ch12` บทนี้ใช้ Environment Query System (EQS) กับสองคำถาม คำถามแรก `EQS_TacticalPoint` เลือกจุดที่มีแนวสายตา (Line of Sight) ถึงเป้าหมายและห่างประมาณ 600 หน่วย ซึ่งประกอบและตรวจในตัวแก้ไข (Editor) ด้วย EQS Testing Pawn เทียบกับตัวช่วยสาธิต (Editor Teaching Aid) `TP_Target` คำถามที่สอง `EQS_SearchHidden` เลือกจุดใกล้ตำแหน่งที่พบล่าสุด (Last Known Location) ที่ศัตรู (Enemy) มองไม่เห็น ซึ่ง Enemy ใช้ขณะเล่นเมื่อมองไม่เห็นเป้าหมายแล้ว (Sight Lost) ฝั่ง C++ มีตัวทดสอบ (Test) ที่เขียนเอง `UEnvQueryTest_DistanceBand` และ Context: `UEnvQueryContext_Target` (Editor Teaching Aid: Actor ที่ติด Tag `EQSTeachingAid`) กับคลาสลูก (Derived Class) `UEnvQueryContext_LastKnownLocation` (คีย์ (Key) `LastKnownLocation`) ซึ่งใช้ Editor Teaching Aid เมื่อผู้เรียกใช้ Query (Querier) ไม่มี Blackboard และ Derived Class `UEnvQueryContext_PerceivedTarget` (Key `TargetActor`) ซึ่งมีไว้สำหรับแบบฝึกหัดข้อ 9 เท่านั้น Controller ได้ผู้สังเกตคีย์ `SearchLocation` ที่บันทึกบรรทัด `[EQS]` และวาดทรงกลม Debug (เครื่องมือวัด) และการจำแนกการมาถึงจุดซ่อน (Hiding Spot) การเปลี่ยนแปลงของ Behavior Tree ทั้งหมดอยู่ใน `BT_Enemy_EQS` (สำเนาของ `BT_Enemy` ที่ `Investigate` มีส่วน `Search`; `Chase` ไม่เปลี่ยน) กับ Blackboard `BB_Enemy_EQS` (Parent = `BB_Enemy`) ส่วน `BT_Enemy` และ `BB_Enemy` ไม่เปลี่ยน Enemy ที่วางใน `L_Ch12` เลือก `BT_Enemy_EQS` ผ่าน *Behavior Tree Asset* ของอินสแตนซ์ (Instance) แผนที่ `L_Ch12` เป็นสำเนาของ `L_Ch11`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch12` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch12.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch12` แล้วใช้โฟลเดอร์ (Folder) `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch12` ซึ่งมี `BP_Enemy` หนึ่งตัว (เลือก *Perception Enabled* และตั้ง *Behavior Tree Asset* เป็น `BT_Enemy_EQS` ที่ Instance แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, `TP_Target` (Editor Teaching Aid: Tag `EQSTeachingAid` และยกจากพื้น 100 หน่วย), `BP_EQSTester` (*Query Template* = `EQS_TacticalPoint`, เลือก *Run Query On Selection Changed*), หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone` และ `EnemySpawner` (*Spawn Count* 0) ของบทก่อน เมื่อกด Play แล้ว Player เป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของ Player คือ Stimulus ที่ AI รับรู้

บทนี้สร้างเป็นสามขั้น Tag `ch12` คือสถานะหลังขั้นที่ 3: `EQS_TacticalPoint` ใช้ DistanceBand ของขั้นที่ 2 และกรอบอ้างอิง (Context) ทั้งสามช่องเป็น `EnvQueryContext_Target` การทดลองแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — อ่าน Query (ใน Editor ไม่ต้อง Play):** คลิกเลือก `BP_EQSTester` ในแผนที่ ทรงกลมของ Query ปรากฏรอบ `TP_Target` ทำการกระทำที่ 1, 2, 3 และ 5 ของตาราง "การตรวจ Query แบบทำนายก่อนดู" ในบททีละข้อ เขียนคำทำนายก่อนดู แล้วคืนค่าก่อนข้อถัดไป ใน Tag นี้จุดคะแนนสูงสุดอยู่บนวงแหวนประมาณ 600 หน่วยรอบ `TP_Target` เพราะ Query มี DistanceBand ของขั้นที่ 2 แทน Distance ของขั้นที่ 1 แล้ว
6. **ขั้นที่ 2 — Test ที่เขียนเอง:** เปิด `EQS_TacticalPoint` เลือก Test DistanceBand ตั้ง *Preferred Distance* เป็น 1000 แล้ว Save ดูว่าวงแหวนของจุดคะแนนสูงขยายออก ขณะที่จุดสีน้ำเงินไม่เปลี่ยน แล้วคืนค่าเป็น 600 และ Save
7. **ขั้นที่ 3 — ค้นหาเมื่อมองไม่เห็นเป้าหมายแล้ว:** กด Play จากนั้นบังคับตัวละครผู้เล่น (Player) ให้เข้าไปในที่ที่ Enemy มองเห็น (Enemy ไล่ตามด้วยกิ่ง (Branch) `Chase` ของบทที่ 11) แล้วให้ Player วิ่งไปหลบหลังบล็อก (Block) ที่สูงกว่าตัวละคร (Character) Enemy ต้องเดินไปยัง Last Known Location ทรงกลมสีส้มปรากฏที่จุดหนึ่งที่มองไม่เห็นจากตำแหน่งนั้น Enemy เดินไปตรวจ หยุดสองวินาที แล้วกลับไปลาดตระเวน จากนั้นให้ Player หลบอยู่ต่อแล้วกระโดดหนึ่งครั้งภายในระยะ 1500 Enemy ต้องเดินมายังจุดที่กระโดดโดยไม่มีการค้นหา Hiding Spot ระหว่างนั้นกด Apostrophe (`'`) แล้วแป้นตัวเลข 3 เพื่อดูตารางของ Query ที่ Enemy ทำการรัน (Run) จริงในหมวด EQS ของ Gameplay Debugger

## จุดตรวจสอบผลลัพธ์

**ขั้นที่ 1 และ 2 (ใน Editor):** ไม่มีบรรทัดใน Output Log จุดตรวจคือภาพของ EQS Testing Pawn เทียบกับคำทำนาย: ตารางอยู่รอบ `TP_Target` ไม่ใช่รอบ Testing Pawn จุดที่ Block บังจากมุมของ `TP_Target` เป็นสีน้ำเงินเข้มพร้อมป้าย Trace จุดคะแนนสูงอยู่บนวงแหวนตามค่า *Preferred Distance* ทางด้านของ Testing Pawn และการเปลี่ยน *Preferred Distance* ไม่เปลี่ยนชุดจุดสีน้ำเงิน

**ขั้นที่ 3 — ค้นหา:** สามบรรทัดนี้ตามลำดับเมื่อ Player หลบจน Enemy มองไม่เห็นเป้าหมายแล้ว (กรอง Output Log ด้วย `[EQS]`, `[Perception]` และ `[BT]`) ไม่มีบรรทัด `[AI] Reached waypoint` ที่ Hiding Spot ก่อนให้ Player หลบ ผู้อ่านควรทำนายว่าทรงกลมสีส้มจะอยู่ที่ใดเทียบกับ Block ที่ใช้หลบ

```
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
LogTemp: [EQS] Search: checking hidden spot
```

ที่มาของแต่ละบรรทัด

- บรรทัด `Sight lost`: บรรทัดของบทที่ 11 ทุกอักขระ ตัวรับสิ่งเร้าเขียน `LastKnownLocation`, `AlertLocation` และ `Alerted` แล้วล้าง `TargetActor` Decorator (Both) บน `Chase` ยุติ Branch ของตนเอง
- บรรทัด `Investigate`: บรรทัดของบทที่ 8 ทุกอักขระ จาก `WasInvestigateArrival()` เมื่อ Enemy ถึง `AlertLocation` (= Last Known Location เมื่อมองไม่เห็นเป้าหมายแล้ว) Decorator ของ `Investigate` เป็น Lower Priority จึงไม่ยุติ Branch ของตนเอง และการค้นหาทำงานต่อหลังบรรทัดนี้
- บรรทัด `Search`: จาก `OnSearchLocationChanged()` เมื่อ Run EQS Query ของส่วน `Search` เขียน `SearchLocation` ทรงกลมสีส้มอยู่ที่ค่านั้น ส่วนนี้ทำงานเฉพาะเมื่อ `AlertLocation` เท่ากับ `LastKnownLocation` (Decorator Compare BBEntries) การได้ยิน (Hearing) เสียง (Noise) จึงไม่มีบรรทัดนี้

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08`, `L_Ch09`, `L_Ch10` แล้ว `L_Ch11` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[EQS]` ใดเลย ใน `L_Ch11` Enemy ยังวิ่งเข้าหา Player จนเหลือ 150 ตามบทที่ 11: Enemy ในแผนที่เหล่านั้นทำการ Run `BT_Enemy` (ค่าของคลาส (Class)) ซึ่ง Blackboard ไม่มี Key ของบทนี้ ผู้สังเกตจึงไม่ถูกลงทะเบียน และการจำแนกการมาถึงของบทนี้คืนเท็จเสมอ Enemy ใน `L_Ch12` ไล่ตามแบบเดียวกัน เพราะ `Chase` ของ `BT_Enemy_EQS` คือสำเนาที่ไม่ถูกแก้

## ปัญหาที่พบบ่อย

- **กับดักของ Bool Match: จุดที่มองเห็นเป้าหมายชัดเจนเป็นสีน้ำเงิน และจุดหลัง Block ได้คะแนน** — Bool Match ของ Trace ใน `EQS_TacticalPoint` ยังถูกเลือกอยู่ (ค่าเริ่มต้น (Default Value) ของ Test ทุกรายการ) ซึ่งหมายถึง *require hit* = ผ่านเมื่อเส้นถูกบัง ให้ไม่เลือก Bool Match และตรวจว่าคำอธิบายบน Node อ่านว่า *require not hit* ใน `EQS_SearchHidden` เป็นตรงกันข้าม: ต้องเลือกไว้ (*require hit*) หากไม่เลือก Enemy จะ "ค้นหา" จุดในที่โล่งที่ตนมองเห็นอยู่แล้ว โดยบรรทัด `Search` ยังปรากฏตามปกติ
- **Querier กับ Query: ตารางปรากฏรอบ Testing Pawn (หรือรอบ Enemy ใน Gameplay Debugger) แทนรอบเป้าหมาย** — Querier คือ Actor ที่ทำการ Run Query (Testing Pawn ใน Editor หรือร่าง (Pawn) ของ Enemy ขณะเล่น) ไม่ใช่ Asset ของ Query และทุกช่องของตัวกำเนิดรายการ (Generator) และ Test มี Default Value เป็น `EnvQueryContext_Querier` ช่อง *Generate Around* (หรือ *Context*/*Distance To* ของ Test) ที่ยังเป็น Default Value จึงวัดเทียบกับตัวผู้ทำการ Run เอง ให้ตั้งเป็น Context ตามบท (ใน `EQS_TacticalPoint` ช่องเดียวที่เป็น Querier คือ Pathfinding; ใน `EQS_SearchHidden` คือ Trace และ Pathfinding)
- **Query ได้ 0 รายการ (Item; Testing Pawn ไม่แสดงทรงกลมใด หรือ Enemy หยุดสองวินาทีที่ Last Known Location โดยไม่มีบรรทัด `Search`)** — Context ไม่ให้ข้อมูล ใน Editor: ไม่มี Actor ที่ติด Tag `EQSTeachingAid` ในแผนที่ (สะกดไม่ตรงกับ `TeachingAidTag` ทุกอักขระ หรือ `TP_Target` ถูกลบ) ขณะเล่น: Context ของ `EQS_SearchHidden` ยังเป็น `EnvQueryContext_Target` และ `TP_Target` ถูกลบ (แบบฝึกหัดข้อ 7) อีกสาเหตุคือตารางทั้งตารางฉายลง NavMesh ไม่ได้ (กด `P` ต้องเห็นพื้นสีเขียวรอบจุดศูนย์กลาง) เมื่อ Query ได้ 0 Item Selector ภายใน `Investigate` ไปยัง Wait 2.0 ของบทที่ 8 ดูจำนวน Item ได้จากหมวด EQS ของ Gameplay Debugger
- **Query ได้ 0 Item ทั้งที่ `TP_Target` มี Tag `EQSTeachingAid` แล้ว** — Tag ถูกใส่ในช่อง *Tags* ผิดช่อง แผง Details ของ `TP_Target` มีช่องชื่อ *Tags* สองแห่ง ช่องที่ถูกคือ *Tags* ในส่วน Advanced ของหมวด *Actor* (`AActor::Tags`) ซึ่ง `GetAllActorsWithTag()` อ่านผ่าน `ActorHasTag()` ช่อง *Tags* ในหมวด Misc ไม่ใช่อาร์เรย์ (Array) นี้ ให้ลบค่าออกจากช่องนั้นแล้วใส่ในช่องของหมวด Actor
- **ทรงกลมสีส้มอยู่ใกล้ `TP_Target` แทนใกล้จุดที่ Player หลบ** — *Generate Around* หรือ *Distance To* ของ `EQS_SearchHidden` ยังชี้ `EnvQueryContext_Target` ซึ่งคืน Editor Teaching Aid เสมอโดยไม่ดู Querier (แบบฝึกหัดข้อ 7) ให้ตั้งทั้งสองช่องเป็น `EnvQueryContext_LastKnownLocation` ตามข้อ 3 และ 6 ของขั้นที่ 3
- **ทุกจุดใน Testing Pawn มีคะแนนเท่ากัน** — Test ที่ควรให้คะแนนถูกตั้งเป็น *Filter Only* (Filter Only ไม่ให้คะแนน Item ที่ผ่านทุกตัวกรองจึงเสมอกัน และ Single Best Item เลือก Item แรกในกลุ่มที่เท่ากัน) ให้ตรวจ *Test Purpose* ของ Distance/DistanceBand และ Pathfinding ว่าเป็น *Score Only*
- **ทุกจุดเป็นสีน้ำเงินทันทีหลังเพิ่ม Distance หรือ DistanceBand** — *Test Purpose* ยังเป็น Default Value *Filter and Score* ซึ่งมี *Filter Type* Range และขอบทั้งสองเป็น 0 จึงตัดทุก Item ที่มีค่ามากกว่า 0 ป้ายบนทรงกลมสีน้ำเงินบอกชื่อ Test ที่ทำให้ไม่ผ่าน ให้ตั้งเป็น *Score Only*
- **จุดคะแนนสูงสุดไม่เอนไปทางด้านของ Testing Pawn (คะแนนเหมือนไม่มี Pathfinding)** — Testing Pawn ไม่ได้ยืนบน NavMesh (ลอยสูงหรืออยู่นอกพื้นสีเขียว) เส้นทางจาก Querier จึงหาไม่ได้ Pathfinding ที่เป็น *Score Only* ไม่ตัด Item ที่ไปไม่ถึง แต่ให้คะแนนส่วนนี้เป็น 0 ทุก Item (ข้อความ *score unreachable as 0* บน Node) ให้วาง Testing Pawn บนพื้นสีเขียว หากจุดเป็นสีน้ำเงินพร้อมป้าย Pathfinding แสดงว่า Test นี้ถูกตั้งเป็นตัวกรอง (*Filter Only* หรือ *Filter and Score*) ซึ่ง *Skip Unreachable* (Default Value เลือกไว้) ตัด Item ที่ไปไม่ถึงทิ้ง
- **Testing Pawn ไม่แสดงอะไรเลย** — *Query Template* ของ `BP_EQSTester` ที่วางในแผนที่ว่างหรือชี้ Asset ผิด หรือ Query ได้ 0 Item (ข้อก่อนหน้า) หรือไม่ได้เลือก *Draw Failed Items* ขณะที่ทุก Item ไม่ผ่าน
- **ย้าย `TP_Target` แล้วภาพไม่เปลี่ยน** — Testing Pawn ทำการ Run Query ใหม่เฉพาะเมื่อตัวเองถูกย้าย เมื่อ Asset ของ Query ถูกบันทึก หรือเมื่อการเลือก Actor เปลี่ยนโดยเลือก *Run Query On Selection Changed* ไว้ ให้คลิกเลือก Actor อื่น หรือขยับ Testing Pawn เล็กน้อย การย้าย Context ไม่แจ้ง Pawn เอง
- **ไม่พบ DistanceBand ในรายการ Add Test หรือไม่พบ Context ของบทในรายการให้เลือก** — C++ Code ยังไม่ผ่านการคอมไพล์ (Compile) ในสถานะล่าสุด สั่ง Build ใน Rider ให้เสร็จ แล้วเปิด Unreal Editor ใหม่ (ดู "ปัญหาที่พบบ่อย" ของ `docs/ch07.md` เรื่อง Class ใหม่กับ Live Coding)
- **Enemy ตามทันเสมอ จึงไม่มีบรรทัด `Sight lost` และไม่มีการค้นหา** — Enemy เร็วกว่า Player: *Max Walk Speed* ของ `BP_Enemy` ยังเป็น Default Value 600 ขณะที่ Player เดินที่ 500 ให้ตั้งเป็น 400 ตามขั้นตอนใน Component CharacterMovement ของสูตรการสร้าง `BP_Enemy` ในบทที่ 7 และหลบหลัง Block ที่บัง Line of Sight ไม่ใช่วิ่งออกให้ไกล (*Lose Sight Radius* 2000 มากกว่า *Sight Radius* 1500 โดยเจตนา)
- **หลบแล้ว Enemy เดินไปยัง Last Known Location หยุดสองวินาที และไม่มีบรรทัด `Search`** — ส่วน `Search` ไม่ทำงาน: Instance ของ `BP_Enemy` ใน `L_Ch12` ยังทำการ Run `BT_Enemy` (*Behavior Tree Asset* ในหมวด *AI* ของแผง Details ยังไม่ได้ตั้งเป็น `BT_Enemy_EQS` หรือ Build ก่อนที่ `BehaviorTreeAsset` จะเป็น `EditAnywhere` ช่องจึงไม่ปรากฏที่ Instance) หรือ Decorator Compare BBEntries ตั้ง Key ผิด (ต้องเป็น `AlertLocation` กับ `LastKnownLocation` และ *Is Equal To*) หรือ `BB_Enemy_EQS` ไม่มี Key `SearchLocation` หรือ Query ไม่พบ Hiding Spot (Run EQS Query ล้มเหลว และ Selector ไปยัง Wait 2.0 ซึ่งเป็นผลที่ออกแบบไว้) ดูหมวด EQS ของ Gameplay Debugger
- **Node ใน `BT_Enemy_EQS` แสดง Key เป็นสีแดงหรือไม่มี Key ใหม่ให้เลือก** — Node ROOT ของ `BT_Enemy_EQS` ยังชี้ `BB_Enemy` (ตั้ง *Blackboard Asset* เป็น `BB_Enemy_EQS`) หรือ *Parent* ของ `BB_Enemy_EQS` ไม่ได้ตั้งเป็น `BB_Enemy` (Key ของบทก่อนหน้าจึงหายไปจาก Blackboard ลูก)
- **กระโดดแล้วมีบรรทัด `Search`** — Decorator Compare BBEntries หายไปจาก `Search` หรือตั้ง *Is Not Equal To* การค้นหาต้องเกิดเฉพาะเมื่อมองไม่เห็นเป้าหมายแล้ว
- **หลังการค้นหา มีบรรทัด `[AI] Reached waypoint` ที่ Hiding Spot หรือ Enemy ข้ามจุดลาดตระเวน (Patrol Point)** — `WasSearchArrival()` ไม่ถูกตรวจใน `OnMoveCompleted()` ก่อนการเลื่อน Patrol Point (หรือไม่ล้าง `SearchLocation` หลังใช้)
- **แผนที่ก่อนหน้า (`L_Ch07`–`L_Ch11`) ทำการ Run Behavior Tree ของบทนี้ (Enemy ค้นหา Hiding Spot)** — *Behavior Tree Asset* ถูกตั้งใน Class Defaults ของ Blueprint `BP_Enemy` แทน Instance ที่วางใน `L_Ch12` ค่าของ Class มีผลกับ Enemy ทุกแผนที่ ให้คืน `BT_Enemy` ใน Class แล้วเลือก Enemy ในแผง Outliner ของ `L_Ch12` และตั้ง `BT_Enemy_EQS` ที่ Instance ปุ่มลูกศรวนกลับ (*Reset to Default*) ข้างช่องยืนยันว่าค่าของ Instance ต่างจากค่าของ Class อีกสาเหตุหนึ่งคือแก้ `BT_Enemy` แทน `BT_Enemy_EQS`
- **มองไม่เห็นทรงกลมสีส้ม** — ทรงกลมอยู่ 3 วินาทีแล้วหายไป หรือทำการ Run ในบิลด์ Shipping/Test ซึ่งไม่วาด Debug ทรงกลมเป็นเครื่องมือวัดเท่านั้น
