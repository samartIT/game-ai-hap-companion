# บทที่ 12 — ระบบสืบค้นสภาพแวดล้อม

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 12 คือแท็ก `ch12` บทนี้ใช้ Environment Query System (EQS) กับสองคำถาม คำถามแรก `EQS_TacticalPoint` เลือกจุดที่มีแนวสายตาถึงเป้าหมายและห่างประมาณ 600 หน่วย ซึ่งประกอบและตรวจในตัวแก้ไขด้วย EQS Testing Pawn เทียบกับตัวช่วยสาธิต `TP_Target` คำถามที่สอง `EQS_SearchHidden` เลือกจุดใกล้ตำแหน่งที่พบล่าสุดที่ศัตรูมองไม่เห็น ซึ่งศัตรูใช้ขณะเล่นเมื่อมองไม่เห็นเป้าหมายแล้ว (Sight Lost) ฝั่ง C++ มี Test ที่เขียนเอง `UEnvQueryTest_DistanceBand` และ Context: `UEnvQueryContext_Target` (ตัวช่วยสาธิตในตัวแก้ไข: Actor ที่ติด Tag `EQSTeachingAid`) กับคลาสลูก `UEnvQueryContext_LastKnownLocation` (คีย์ `LastKnownLocation`) ซึ่งใช้ตัวช่วยสาธิตเมื่อ Querier (ผู้เรียกใช้ Query) ไม่มี Blackboard และคลาสลูก `UEnvQueryContext_PerceivedTarget` (คีย์ `TargetActor`) ซึ่งมีไว้สำหรับแบบฝึกหัดข้อ 9 เท่านั้น Controller ได้ผู้สังเกตคีย์ `SearchLocation` ที่บันทึกบรรทัด `[EQS]` และวาดทรงกลมดีบัก (เครื่องมือวัด) และการจำแนกการมาถึงจุดซ่อน การเปลี่ยนแปลงของ Behavior Tree ทั้งหมดอยู่ใน `BT_Enemy_EQS` (สำเนาของ `BT_Enemy` ที่ `Investigate` มีส่วน `Search`; `Chase` ไม่เปลี่ยน) กับ Blackboard `BB_Enemy_EQS` (Parent = `BB_Enemy`) ส่วน `BT_Enemy` และ `BB_Enemy` ไม่เปลี่ยน ศัตรูที่วางใน `L_Ch12` เลือก `BT_Enemy_EQS` ผ่าน *Behavior Tree Asset* ของอินสแตนซ์ แผนที่ `L_Ch12` เป็นสำเนาของ `L_Ch11`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch12` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch12.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch12` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch12` ซึ่งมี `BP_Enemy` หนึ่งตัว (เลือก *Perception Enabled* และตั้ง *Behavior Tree Asset* เป็น `BT_Enemy_EQS` ที่อินสแตนซ์แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, `TP_Target` (ตัวช่วยสาธิตในตัวแก้ไข: Tag `EQSTeachingAid` และยกจากพื้น 100 หน่วย), `BP_EQSTester` (*Query Template* = `EQS_TacticalPoint`, เลือก *Run Query On Selection Changed*), หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone` และ `EnemySpawner` (*Spawn Count* 0) ของบทก่อน เมื่อกด Play ตัวละครผู้เล่นเป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของตัวละครผู้เล่นคือสิ่งเร้าที่ AI รับรู้

บทนี้สร้างเป็นสามขั้น แท็ก `ch12` คือสถานะหลังขั้นที่ 3: `EQS_TacticalPoint` ใช้ DistanceBand ของขั้นที่ 2 และ Context ทั้งสามช่องเป็น `EnvQueryContext_Target` การทดลองแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — อ่าน Query (ในตัวแก้ไข ไม่ต้อง Play):** คลิกเลือก `BP_EQSTester` ในแผนที่ ทรงกลมของ Query ปรากฏรอบ `TP_Target` ทำการกระทำที่ 1, 2, 3 และ 5 ของตาราง "การตรวจ Query แบบทำนายก่อนดู" ในบททีละข้อ เขียนคำทำนายก่อนดู แล้วคืนค่าก่อนข้อถัดไป ในแท็กนี้จุดคะแนนสูงสุดอยู่บนวงแหวนประมาณ 600 หน่วยรอบ `TP_Target` เพราะ Query มี DistanceBand ของขั้นที่ 2 แทน Distance ของขั้นที่ 1 แล้ว
6. **ขั้นที่ 2 — Test ที่เขียนเอง:** เปิด `EQS_TacticalPoint` เลือก Test DistanceBand ตั้ง *Preferred Distance* เป็น 1000 แล้ว Save ดูว่าวงแหวนของจุดคะแนนสูงขยายออก ขณะที่จุดสีน้ำเงินไม่เปลี่ยน แล้วคืนค่าเป็น 600 และ Save
7. **ขั้นที่ 3 — ค้นหาเมื่อมองไม่เห็นเป้าหมายแล้ว:** กด Play จากนั้นบังคับตัวละครผู้เล่น (Player) ให้เข้าไปในที่ที่ศัตรู (AI) มองเห็น (ศัตรูไล่ตามด้วย Branch (กิ่ง) `Chase` ของบทที่ 11) แล้ววิ่งไปหลบหลังบล็อกที่สูงกว่าตัวละคร ศัตรูต้องเดินไปยังตำแหน่งที่พบล่าสุด ทรงกลมสีส้มปรากฏที่จุดหนึ่งที่มองไม่เห็นจากตำแหน่งนั้น ศัตรูเดินไปตรวจ หยุดสองวินาที แล้วกลับไปลาดตระเวน จากนั้นให้ตัวละครผู้เล่นหลบอยู่ต่อแล้วกระโดดหนึ่งครั้งภายในระยะ 1500 ศัตรูต้องเดินมายังจุดที่กระโดดโดยไม่มีการค้นหาจุดซ่อน ระหว่างนั้นกด Apostrophe (`'`) แล้วแป้นตัวเลข 3 เพื่อดูตารางของ Query ที่ศัตรูรันจริงในหมวด EQS ของ Gameplay Debugger

## จุดตรวจสอบผลลัพธ์

**ขั้นที่ 1 และ 2 (ในตัวแก้ไข):** ไม่มีบรรทัดใน Output Log จุดตรวจคือภาพของ EQS Testing Pawn เทียบกับคำทำนาย: ตารางอยู่รอบ `TP_Target` ไม่ใช่รอบ Testing Pawn จุดที่บล็อกบังจากมุมของ `TP_Target` เป็นสีน้ำเงินเข้มพร้อมป้าย Trace จุดคะแนนสูงอยู่บนวงแหวนตามค่า *Preferred Distance* ทางด้านของ Testing Pawn และการเปลี่ยน *Preferred Distance* ไม่เปลี่ยนชุดจุดสีน้ำเงิน

**ขั้นที่ 3 — ค้นหา:** สามบรรทัดนี้ตามลำดับเมื่อตัวละครผู้เล่นหลบจนศัตรูมองไม่เห็นเป้าหมายแล้ว (กรอง Output Log ด้วย `[EQS]`, `[Perception]` และ `[BT]`) ไม่มีบรรทัด `[AI] Reached waypoint` ที่จุดซ่อน ก่อนให้ตัวละครผู้เล่นหลบ ผู้อ่านควรทำนายว่าทรงกลมสีส้มจะอยู่ที่ใดเทียบกับบล็อกที่ใช้หลบ

```
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
LogTemp: [EQS] Search: checking hidden spot
```

ที่มาของแต่ละบรรทัด

- บรรทัด `Sight lost`: บรรทัดของบทที่ 11 ทุกอักขระ ตัวรับสิ่งเร้าเขียน `LastKnownLocation`, `AlertLocation` และ `Alerted` แล้วล้าง `TargetActor` Decorator (Both) บน `Chase` ยุติ Branch ของตนเอง
- บรรทัด `Investigate`: บรรทัดของบทที่ 8 ทุกอักขระ จาก `WasInvestigateArrival()` เมื่อศัตรูถึง `AlertLocation` (= ตำแหน่งที่พบล่าสุดเมื่อมองไม่เห็นเป้าหมายแล้ว) Decorator ของ `Investigate` เป็น Lower Priority จึงไม่ยุติ Branch ของตนเอง และการค้นหาทำงานต่อหลังบรรทัดนี้
- บรรทัด `Search`: จาก `OnSearchLocationChanged()` เมื่อ Run EQS Query ของส่วน `Search` เขียน `SearchLocation` ทรงกลมสีส้มอยู่ที่ค่านั้น ส่วนนี้ทำงานเฉพาะเมื่อ `AlertLocation` เท่ากับ `LastKnownLocation` (Decorator Compare BBEntries) การได้ยินเสียงจึงไม่มีบรรทัดนี้

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08`, `L_Ch09`, `L_Ch10` แล้ว `L_Ch11` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[EQS]` ใดเลย ใน `L_Ch11` ศัตรูยังวิ่งเข้าหาผู้เล่นจนเหลือ 150 ตามบทที่ 11: ศัตรูในแผนที่เหล่านั้นรัน `BT_Enemy` (ค่าของคลาส) ซึ่ง Blackboard ไม่มีคีย์ของบทนี้ ผู้สังเกตจึงไม่ถูกลงทะเบียน และการจำแนกการมาถึงของบทนี้คืนเท็จเสมอ ศัตรูใน `L_Ch12` ไล่ตามแบบเดียวกัน เพราะ `Chase` ของ `BT_Enemy_EQS` คือสำเนาที่ไม่ถูกแก้

## ปัญหาที่พบบ่อย

- **กับดักของ Bool Match: จุดที่มองเห็นเป้าหมายชัดเจนเป็นสีน้ำเงิน และจุดหลังบล็อกได้คะแนน** — Bool Match ของ Trace ใน `EQS_TacticalPoint` ยังถูกเลือกอยู่ (ค่าเริ่มต้นของ Test ทุกรายการ) ซึ่งหมายถึง *require hit* = ผ่านเมื่อเส้นถูกบัง ให้ไม่เลือก Bool Match และตรวจว่าคำอธิบายบน Node อ่านว่า *require not hit* ใน `EQS_SearchHidden` เป็นตรงกันข้าม: ต้องเลือกไว้ (*require hit*) หากไม่เลือก ศัตรูจะ "ค้นหา" จุดในที่โล่งที่ตนมองเห็นอยู่แล้ว โดยบรรทัด `Search` ยังปรากฏตามปกติ
- **Querier กับ Query: ตารางปรากฏรอบ Testing Pawn (หรือรอบศัตรูใน Gameplay Debugger) แทนรอบเป้าหมาย** — Querier คือ Actor ที่รัน Query (Testing Pawn ในตัวแก้ไข หรือ Pawn ของศัตรูขณะเล่น) ไม่ใช่ Asset ของ Query และทุกช่องของ Generator และ Test มีค่าเริ่มต้นเป็น `EnvQueryContext_Querier` ช่อง *Generate Around* (หรือ *Context*/*Distance To* ของ Test) ที่ยังเป็นค่าเริ่มต้นจึงวัดเทียบกับตัวผู้รันเอง ให้ตั้งเป็น Context ตามบท (ใน `EQS_TacticalPoint` ช่องเดียวที่เป็น Querier คือ Pathfinding; ใน `EQS_SearchHidden` คือ Trace และ Pathfinding)
- **Query ได้ 0 รายการ (Testing Pawn ไม่แสดงทรงกลมใด หรือศัตรูหยุดสองวินาทีที่ตำแหน่งที่พบล่าสุดโดยไม่มีบรรทัด `Search`)** — Context ไม่ให้ข้อมูล ในตัวแก้ไข: ไม่มี Actor ที่ติด Tag `EQSTeachingAid` ในแผนที่ (สะกดไม่ตรงกับ `TeachingAidTag` ทุกอักขระ หรือ `TP_Target` ถูกลบ) ขณะเล่น: Context ของ `EQS_SearchHidden` ยังเป็น `EnvQueryContext_Target` และ `TP_Target` ถูกลบ (แบบฝึกหัดข้อ 7) อีกสาเหตุคือตารางทั้งตารางฉายลง NavMesh ไม่ได้ (กด `P` ต้องเห็นพื้นสีเขียวรอบจุดศูนย์กลาง) เมื่อ Query ได้ 0 รายการ Selector ภายใน `Investigate` ไปยัง Wait 2.0 ของบทที่ 8 ดูจำนวนรายการได้จากหมวด EQS ของ Gameplay Debugger
- **Query ได้ 0 รายการทั้งที่ `TP_Target` มี Tag `EQSTeachingAid` แล้ว** — Tag ถูกใส่ในช่อง *Tags* ผิดช่อง แผง Details ของ `TP_Target` มีช่องชื่อ *Tags* สองแห่ง ช่องที่ถูกคือ *Tags* ในส่วน Advanced ของหมวด *Actor* (`AActor::Tags`) ซึ่ง `GetAllActorsWithTag()` อ่านผ่าน `ActorHasTag()` ช่อง *Tags* ในหมวด Misc ไม่ใช่อาร์เรย์นี้ ให้ลบค่าออกจากช่องนั้นแล้วใส่ในช่องของหมวด Actor
- **ทรงกลมสีส้มอยู่ใกล้ `TP_Target` แทนใกล้จุดที่ผู้เล่นหลบ** — *Generate Around* หรือ *Distance To* ของ `EQS_SearchHidden` ยังชี้ `EnvQueryContext_Target` ซึ่งคืนตัวช่วยสาธิตเสมอโดยไม่ดู Querier (แบบฝึกหัดข้อ 7) ให้ตั้งทั้งสองช่องเป็น `EnvQueryContext_LastKnownLocation` ตามข้อ 3 และ 6 ของขั้นที่ 3
- **ทุกจุดใน Testing Pawn มีคะแนนเท่ากัน** — Test ที่ควรให้คะแนนถูกตั้งเป็น *Filter Only* (Filter Only ไม่ให้คะแนน รายการที่ผ่านทุกตัวกรองจึงเสมอกัน และ Single Best Item เลือกรายการแรกในกลุ่มที่เท่ากัน) ให้ตรวจ *Test Purpose* ของ Distance/DistanceBand และ Pathfinding ว่าเป็น *Score Only*
- **ทุกจุดเป็นสีน้ำเงินทันทีหลังเพิ่ม Distance หรือ DistanceBand** — *Test Purpose* ยังเป็นค่าเริ่มต้น *Filter and Score* ซึ่งมี *Filter Type* Range และขอบทั้งสองเป็น 0 จึงตัดทุกรายการที่มีค่ามากกว่า 0 ป้ายบนทรงกลมสีน้ำเงินบอกชื่อ Test ที่ทำให้ไม่ผ่าน ให้ตั้งเป็น *Score Only*
- **จุดคะแนนสูงสุดไม่เอนไปทางด้านของ Testing Pawn (คะแนนเหมือนไม่มี Pathfinding)** — Testing Pawn ไม่ได้ยืนบน NavMesh (ลอยสูงหรืออยู่นอกพื้นสีเขียว) เส้นทางจาก Querier จึงหาไม่ได้ Pathfinding ที่เป็น *Score Only* ไม่ตัดรายการที่ไปไม่ถึง แต่ให้คะแนนส่วนนี้เป็น 0 ทุกรายการ (ข้อความ *score unreachable as 0* บน Node) ให้วาง Testing Pawn บนพื้นสีเขียว หากจุดเป็นสีน้ำเงินพร้อมป้าย Pathfinding แสดงว่า Test นี้ถูกตั้งเป็นตัวกรอง (*Filter Only* หรือ *Filter and Score*) ซึ่ง *Skip Unreachable* (ค่าเริ่มต้นเลือกไว้) ตัดรายการที่ไปไม่ถึงทิ้ง
- **Testing Pawn ไม่แสดงอะไรเลย** — *Query Template* ของ `BP_EQSTester` ที่วางในแผนที่ว่างหรือชี้ Asset ผิด หรือ Query ได้ 0 รายการ (ข้อก่อนหน้า) หรือไม่ได้เลือก *Draw Failed Items* ขณะที่ทุกรายการไม่ผ่าน
- **ย้าย `TP_Target` แล้วภาพไม่เปลี่ยน** — Testing Pawn รัน Query ใหม่เฉพาะเมื่อตัวเองถูกย้าย เมื่อ Asset ของ Query ถูกบันทึก หรือเมื่อการเลือก Actor เปลี่ยนโดยเลือก *Run Query On Selection Changed* ไว้ ให้คลิกเลือก Actor อื่น หรือขยับ Testing Pawn เล็กน้อย การย้าย Context ไม่แจ้ง Pawn เอง
- **ไม่พบ DistanceBand ในรายการ Add Test หรือไม่พบ Context ของบทในรายการให้เลือก** — โค้ด C++ ยังไม่ได้คอมไพล์ในสถานะล่าสุด สั่ง Build ใน Rider ให้เสร็จ แล้วเปิด Unreal Editor ใหม่ (ดู "ปัญหาที่พบบ่อย" ของ `docs/ch07.md` เรื่องคลาสใหม่กับ Live Coding)
- **ศัตรูตามทันเสมอ จึงไม่มีบรรทัด `Sight lost` และไม่มีการค้นหา** — ศัตรูเร็วกว่าผู้เล่น: *Max Walk Speed* ของ `BP_Enemy` ยังเป็นค่าเริ่มต้น 600 ขณะที่ผู้เล่นเดินที่ 500 ให้ตั้งเป็น 400 ตามขั้นตอนใน Component CharacterMovement ของสูตรการสร้าง `BP_Enemy` ในบทที่ 7 และหลบหลังบล็อกที่บังแนวสายตา ไม่ใช่วิ่งออกให้ไกล (*Lose Sight Radius* 2000 มากกว่า *Sight Radius* 1500 โดยเจตนา)
- **หลบแล้วศัตรูเดินไปยังตำแหน่งที่พบล่าสุด หยุดสองวินาที และไม่มีบรรทัด `Search`** — ส่วน `Search` ไม่ทำงาน: อินสแตนซ์ของ `BP_Enemy` ใน `L_Ch12` ยังรัน `BT_Enemy` (*Behavior Tree Asset* ในหมวด *AI* ของแผง Details ยังไม่ได้ตั้งเป็น `BT_Enemy_EQS` หรือ Build ก่อนที่ `BehaviorTreeAsset` จะเป็น `EditAnywhere` ช่องจึงไม่ปรากฏที่อินสแตนซ์) หรือ Decorator Compare BBEntries ตั้งคีย์ผิด (ต้องเป็น `AlertLocation` กับ `LastKnownLocation` และ *Is Equal To*) หรือ `BB_Enemy_EQS` ไม่มีคีย์ `SearchLocation` หรือ Query ไม่พบจุดซ่อน (Run EQS Query ล้มเหลว และ Selector ไปยัง Wait 2.0 ซึ่งเป็นผลที่ออกแบบไว้) ดูหมวด EQS ของ Gameplay Debugger
- **Node ใน `BT_Enemy_EQS` แสดงคีย์เป็นสีแดงหรือไม่มีคีย์ใหม่ให้เลือก** — Node ROOT ของ `BT_Enemy_EQS` ยังชี้ `BB_Enemy` (ตั้ง *Blackboard Asset* เป็น `BB_Enemy_EQS`) หรือ *Parent* ของ `BB_Enemy_EQS` ไม่ได้ตั้งเป็น `BB_Enemy` (คีย์ของบทก่อนหน้าจึงหายไปจาก Blackboard ลูก)
- **กระโดดแล้วมีบรรทัด `Search`** — Decorator Compare BBEntries หายไปจาก `Search` หรือตั้ง *Is Not Equal To* การค้นหาต้องเกิดเฉพาะเมื่อมองไม่เห็นเป้าหมายแล้ว
- **หลังการค้นหา มีบรรทัด `[AI] Reached waypoint` ที่จุดซ่อน หรือศัตรูข้ามจุดลาดตระเวน** — `WasSearchArrival()` ไม่ถูกตรวจใน `OnMoveCompleted()` ก่อนการเลื่อนจุดลาดตระเวน (หรือไม่ล้าง `SearchLocation` หลังใช้)
- **แผนที่ก่อนหน้า (`L_Ch07`–`L_Ch11`) รัน Behavior Tree ของบทนี้ (ศัตรูค้นหาจุดซ่อน)** — *Behavior Tree Asset* ถูกตั้งใน Class Defaults ของ Blueprint `BP_Enemy` แทนอินสแตนซ์ที่วางใน `L_Ch12` ค่าของคลาสมีผลกับศัตรูทุกแผนที่ ให้คืน `BT_Enemy` ในคลาส แล้วเลือกศัตรูในแผง Outliner ของ `L_Ch12` และตั้ง `BT_Enemy_EQS` ที่อินสแตนซ์ ปุ่มลูกศรวนกลับ (*Reset to Default*) ข้างช่องยืนยันว่าค่าของอินสแตนซ์ต่างจากค่าของคลาส อีกสาเหตุหนึ่งคือแก้ `BT_Enemy` แทน `BT_Enemy_EQS`
- **มองไม่เห็นทรงกลมสีส้ม** — ทรงกลมอยู่ 3 วินาทีแล้วหายไป หรือรันในบิลด์ Shipping/Test ซึ่งไม่วาดดีบัก ทรงกลมเป็นเครื่องมือวัดเท่านั้น
