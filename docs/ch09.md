# บทที่ 9 — การสร้าง Node แบบผสมผสาน

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 9 คือแท็ก (Tag) `ch09` บทนี้ให้ศัตรู (Enemy) ของบทที่ 8 คำนวณเองเป็นครั้งแรกด้วย Node ที่เขียนเองสามชนิด: Service `Find Target` หาหุ่น `TargetDummy` ที่ใกล้ที่สุดแล้วเขียนคีย์ (Key) `NearestTarget`/`DistanceToTarget` ทุก 0.1 วินาที, Decorator `Target In Range` (สืบทอดจาก `UBTDecorator_BlackboardBase` จึงสังเกต Key `DistanceToTarget` และ Observer Aborts ทำงาน) เปิด กิ่ง (Branch) `Face` เมื่อระยะต่ำกว่า 800 และยังไม่เคยหันหาเป้าหมายนั้น, Task `Face Target` หมุนร่าง (Pawn) หาเป้าหมาย เขียน `LastFacedTarget` แล้วคืน Succeeded Service ถูกสร้างสองครั้ง: ต้นแบบใน Blueprint (`BTService_FindTarget_BP`) และฉบับ C++ (`UBTService_FindTarget`) อัลกอริทึม (Algorithm) เดียวกัน เพื่อวัดต้นทุนของทั้งสองในฉากที่มี Enemy หลายสิบตัวจาก `EnemySpawner` ด้วย `stat unit`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch09` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch09.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch09` แล้วใช้โฟลเดอร์ (Folder) `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch09` ซึ่งมี `BP_Enemy` หนึ่งตัวกับ TargetPoint ลาดตระเวนสามจุด, หุ่น `TargetDummy` สามตัว (`Dummy_01`–`Dummy_03`) เรียงตามเส้นทาง, `BP_AlertZone` ของบทที่ 8 และ `EnemySpawner` หนึ่งตัว (ตั้ง *Spawn Count* เป็น 0 ไว้ สำหรับการเล่นปกติ) เมื่อกด Play Player ของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับ Player เดินสำรวจฉากได้ระหว่างนั้น ผลของขั้นที่ 1 อ่านจาก AI Debugger

บทนี้สร้างเป็นสี่ขั้น Tag `ch09` คือสถานะหลังขั้นที่ 3 (และมี Spawner ของขั้นที่ 4 วางไว้แล้ว) การเล่นแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — Service ใน Blueprint:** เปิด `BT_Enemy` ลบ Service `Find Target` (C++) ออกจาก Sequence ลาดตระเวนชั่วคราว แล้วเพิ่ม `BTService_FindTarget_BP` แทน (ตั้งสองตัวเลือก Key) หรือง่ายกว่านั้น เลือก `BP_Enemy` ในแผนที่แล้วตั้ง *Behavior Tree Asset* เป็น `BT_Enemy_BPService` กด Play กดปุ่ม Apostrophe (`'`) ขณะกล้องมองเห็น Enemy แผง Blackboard ของ AI Debugger ต้องแสดง `NearestTarget`/`DistanceToTarget` เปลี่ยนขณะ Enemy เดินผ่านหุ่น และข้อความ Print String ที่มุมซ้ายบนตรงกับค่านั้น ยังไม่มีบรรทัด `[Nodes]`
6. **ขั้นที่ 2 — Service ใน C++:** ตั้ง *Behavior Tree Asset* ของ `BP_Enemy` กลับเป็น `BT_Enemy` กด Play เปิด *Window → Output Log* พิมพ์ `[Nodes]` ในช่องกรอง ต้องได้บรรทัด Service ของหุ่นแต่ละตัวตามลำดับ และค่าใน AI Debugger เปลี่ยนในจังหวะเดียวกับขั้นที่ 1
7. **ขั้นที่ 3 — Decorator และ Task:** ใน Play เดียวกัน มองที่ Enemy: เมื่อ Enemy เดินเข้าใกล้หุ่นแต่ละตัว Enemy ต้องหยุด หมุนตัวหันหาหุ่นหนึ่งวินาที แล้วเดินต่อ Output Log ต้องมีบรรทัด Decorator และ Task ตามหลังบรรทัด Service ของหุ่นตัวนั้น กด `'` เพื่อดู Node ที่ทำงานอยู่กระโดดจาก Branch ลาดตระเวนไป Branch `Face`
8. **ขั้นที่ 4 — การวัด:** เปิด `BT_Enemy` ไม่เลือก *Log Target Changes* ของ Node Service C++ แล้วเลือก `EnemySpawner` ในแผนที่ (ตั้ง *Enemy Class* = `BP_Enemy`, *Dummy Class* = `TargetDummy`) ตั้งค่าตามแถว: (50, K 3) → *Spawn Count* 50, *Dummy Count* 0; (50, K 100) → 50, 97; (100, K 100) → 100, 97; (50, K 100, 0.5 s) → 50, 97 และ *Interval* ของ Service ทั้งสองฉบับ 0.5 (K = หุ่นสามตัวที่วางไว้ + *Dummy Count*) แต่ละแถววัดสองครั้ง: *Behavior Tree Override* = `BT_Enemy_BPService` แล้ว `BT_Enemy` กด Play พิมพ์ `stat unit` ในคอนโซล (Console; ปุ่ม `` ` ``) ตรวจบรรทัด `[Nodes] Spawner:` ว่า N, K และชื่อ Behavior Tree ตรงตามแถว รอ 10 วินาที อ่านค่า *Game* 30 วินาที ทางเลือกเมื่อฐานของฉากสูง: *Enemy Class* = `BP_Enemy_Bench` (ลูกของ `BP_Enemy` ที่ Anim Class = None และ Mesh ซ่อน) เสร็จแล้วกา *Log Target Changes* คืน และตั้ง *Spawn Count*/*Dummy Count* เป็น 0

## จุดตรวจสอบผลลัพธ์

จุดตรวจสอบมีหนึ่งจุดต่อขั้น (ที่ *Spawn Count* = 0)

**ขั้นที่ 1 — Service ใน Blueprint:** ไม่มีบรรทัด Output Log จุดตรวจสอบคือแผง Blackboard ของ AI Debugger: `NearestTarget` เปลี่ยนค่าสามครั้งตามลำดับที่ Enemy เดินผ่านหุ่น และ `DistanceToTarget` ลดลงเมื่อ Enemy เข้าใกล้หุ่นแล้วกระโดดขึ้นเมื่อเป้าหมายเปลี่ยน แผงนี้แสดง Key Object ด้วยชื่อภายใน (`TargetDummy_UAID_…`) ไม่ใช่ `Dummy_01` ให้ดูการเปลี่ยนของค่า ชื่อที่ตั้งไว้อยู่ในข้อความ Print String ที่มุมซ้ายบน (ขั้นนี้) และในบรรทัด `[Nodes]` (ขั้นที่ 2) (ภาพ `fig:nodes_stage1_debugger` ในบท)

**ขั้นที่ 2 — Service ใน C++:** ค่าเดียวกันใน AI Debugger และบรรทัดนี้หนึ่งครั้งต่อหุ่น ตามลำดับที่หุ่นเรียงบนเส้นทาง

```
LogTemp: [Nodes] Service: nearest target changed -> Dummy_01
```

**ขั้นที่ 3 — Decorator และ Task:** ก่อนกด Play ผู้อ่านควรทำนายว่าสามบรรทัดของหุ่นตัวแรกจะปรากฏตามลำดับใด และบรรทัดใดจะไม่ปรากฏซ้ำแม้ Enemy ยังอยู่ในระยะ Enemy หยุดหันหาหุ่นแต่ละตัวหนึ่งวินาที และ Output Log แสดงสองบรรทัดนี้ตามหลังบรรทัดของขั้นที่ 2 สำหรับ `Dummy_01` แล้วชุดเดียวกันสำหรับ `Dummy_02` และ `Dummy_03`

```
LogTemp: [Nodes] Decorator: Dummy_01 in range (800)
LogTemp: [Nodes] Task: facing Dummy_01
```

**ขั้นที่ 4 — การวัด:** ตารางแปดช่องกรอกครบ ค่าอ้างอิงของผู้เขียน (Game ms, `BP_Enemy_Bench`, Log Target Changes ปิด, ไม่มี Print String, PIE บน `L_Ch09`):

| N | K | Interval | Service ใน Blueprint | Service ใน C++ | ส่วนต่าง |
|---|---|---|---|---|---|
| 50 | 3 | 0.1 s | 17–18 | 17–18 | ≈ 0 |
| 50 | 100 | 0.1 s | 18–20 | 15–17 | ≈ 3 |
| 100 | 100 | 0.1 s | 34–36 | 25–27 | ≈ 9 |
| 50 | 100 | 0.5 s | 16–18 | 15–17 | ≈ 1 |

ค่าบนเครื่องของผู้อ่านต่างไปได้ แต่ลำดับของแถวคงเดิม: ไม่มีช่องว่างที่ K = 3, ช่องว่างราว 3 ms ที่ K = 100, ราว 9 ms ที่ N = 100 (ฐานเองเพิ่มเป็นสองเท่าตามจำนวนตัวละคร (Character)), หดเหลือราว 1 ms ที่ 0.5 s เคล็ดลับการถ่ายภาพรวม: ขณะ PIE กด F8 (Eject) เพื่อปล่อยการควบคุมตัวละครผู้เล่น (Player) แล้วดึงกล้องอิสระถอยขึ้นมุมสูงจนเห็น Enemy ทั้งหมดและแผง `stat unit` พร้อมกัน Output Log ของทุกรอบมีบรรทัด `[Nodes] Spawner: N enemies (k off-navmesh skipped), K dummies, tree = X` ยืนยันจำนวนและ Behavior Tree และ Enemy ที่สร้างเดินคนละเส้นทาง ส่วนต่างที่ K = 3 อยู่ในระดับความผันผวน (ไม่มีช่องว่าง = ผลที่คาด) ส่วนต่างที่ K = 100 มองเห็นได้

ที่มาของแต่ละบรรทัด

- บรรทัดที่ 1: จาก `TickNode()` ของ Service เมื่อผู้ชนะของการวนเป้าหมายที่เป็นไปได้ (Candidate) ต่างจากครั้งก่อน (เป้าหมายล่าสุดอยู่ในหน่วยความจำจำเพาะ จึงเป็นของ Enemy ตัวนี้เท่านั้น) ปรากฏทันทีที่ Branch ลาดตระเวนเริ่มและมีหุ่นในฉาก
- บรรทัดที่ 2: จาก `CalculateRawConditionValue()` ของ Decorator เมื่อผลเปลี่ยนเป็นจริง คือเมื่อ `DistanceToTarget` ที่ Service เพิ่งเขียนต่ำกว่า 800 เป็นครั้งแรกสำหรับหุ่นตัวนี้ ในการเรียกเดียวกัน คลาสฐาน (Base Class) ร้องขอการยุติ Branch ลาดตระเวน (Lower Priority)
- บรรทัดที่ 3: จาก `ExecuteTask()` ของ Task ในรอบ Tick ถัดไปของ Behavior Tree หลังการยุติถูกประมวลผลและ Branch `Face` เริ่ม จากนั้น Wait 1.0 → Sequence สำเร็จ → Decorator เป็นเท็จ (`LastFacedTarget` = หุ่นตัวนี้) → Branch ลาดตระเวนเดินต่อไปยังจุดเดิม
- สี่บรรทัด `[AI]` ของบทที่ 7 ยังปรากฏครบ (คำขอที่ถูกยุติไม่เลื่อนดัชนี) และ `L_Ch07`/`L_Ch08` ต้องให้ผลเดิมทุกอักขระ

การทดลองเพิ่มเติม: เปิด `L_Ch07` แล้ว `L_Ch08` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระและไม่มีบรรทัด `[Nodes]` ใด (ไม่มี `TargetDummy` ในแผนที่ Service จึงล้าง Key และไม่บันทึก) จากนั้นใน `L_Ch09` เปลี่ยน *Interval* ของ Service เป็น 1.0 แล้ว Play ใหม่ (แบบฝึกหัดข้อ 4 ของบทที่ 9)

## ปัญหาที่พบบ่อย

- **มีบรรทัด Service แต่ไม่มีบรรทัด Decorator และ Task Enemy เดินผ่านหุ่นโดยไม่หัน** — ตัวเลือก Key ของ Decorator หรือ Task ยังเป็น None หรือชี้ Key ผิด (Menu แสดงเฉพาะ Key ที่ผ่านตัวกรอง หากไม่เห็น Key ที่ต้องการ แสดงว่าชนิดหรือ Base Class ของ Key ใน `BB_Enemy` ผิด: `NearestTarget`/`LastFacedTarget` ต้องเป็น Object ที่มี Base Class `TargetDummy`) หรือ Decorator ถูกวางบน Task แทนที่จะวางบน Sequence `Face`
- **มีบรรทัด Decorator แต่ไม่มี Task และ Enemy เดินต่อ** — *Observer Aborts* ของ Target In Range ค้างที่ None การยุติจึงไม่เกิด และ Branch `Face` จะเริ่มได้เฉพาะเมื่อการค้นหาผ่าน (หลัง Sequence ลาดตระเวนจบรอบ) ให้ตั้งเป็น *Lower Priority*
- **Enemy หันหาหุ่นแล้วถูกหมุนกลับทันทีจนแทบไม่เห็นการหัน** — `bOrientRotationToMovement` ของ `AEnemyCharacter` หมุน Pawn ตามทิศเดินทันทีที่มีความเร็ว หาก Wait 1.0 สั้นเกินกว่าที่ Pawn จะหยุดนิ่งให้เห็น ให้ตั้ง *Wait Time* ของ Node Wait ใน Branch `Face` เป็น 2.0 (บรรทัด Output Log ไม่เปลี่ยน)
- **Enemy หันแล้วหันซ้ำทุกวินาที ไม่ลาดตระเวนต่อ** — *Last Faced Target Key* ของ Decorator หรือของ Task ไม่ได้ตั้ง (ค่าที่ Task เขียนไม่ตรงกับ Key ที่ Decorator อ่าน) เงื่อนไข "ยังไม่เคยหัน" จึงเป็นจริงเสมอ
- **ไม่มีบรรทัดใดเลย** — Service ไม่ได้แนบกับ Sequence ลาดตระเวน หรือไม่มี `TargetDummy` ในแผนที่ หรือ *Dummy Name* ของทุกตัวยังเป็น `Dummy` (บรรทัดจะปรากฏแต่ชื่อไม่ตรง)
- **สมาชิก (Member) `Dummy Name` เห็นในแผง Details แต่ลากจาก `Best` แล้วไม่มี Node *Get Dummy Name*** — `UPROPERTY` ของ Member นั้นขาด `BlueprintReadOnly`/`BlueprintReadWrite` (`EditAnywhere` เปิดเฉพาะแผง Details) ให้เพิ่ม Specifier ใน `TargetDummy.h` แล้ว Build ใหม่ (รุ่นก่อน 2026-10-03 ของ File นี้ขาดอยู่)
- **Print String หรือ Output Log แสดงชื่อยาวที่มีเลขต่อท้าย เช่น `TargetDummy_C_UAID_...` หรือ `TargetDummy_3`** — Graph อ่าน *Get Object Name* (ชื่อภายใน ไม่ซ้ำกันในระดับ) แทน Member `DummyName` ของหุ่น ให้ต่อ *Get Dummy Name* ของ `Best` เข้า Print String และอย่าใช้ *Get Display Name* ซึ่งมีเฉพาะในตัวแก้ไข (Editor; ไม่มีในเกมที่ Package แล้ว)
- **Enemy ทุกตัวจาก Spawner หันพร้อมกันหรือหันหาหุ่นตัวเดียวกันทั้งที่อยู่คนละที่** — มีสถานะต่อ AI ถูกเก็บเป็นตัวแปรสมาชิก (Member Variable) ของ Node (เช่น เมื่อผู้อ่านดัดแปลง Service แล้วย้าย `LastNearest` ออกจาก `FBTFindTargetMemory`) ดูคำเตือนในหัวข้อ "กลไกร่วมของ Node ที่เขียนเอง" ของบท
- **ค่า Game ของทั้งสองฉบับเท่ากันทุก N** — ลืมเปลี่ยน *Behavior Tree Override* ระหว่างการวัด หรือ `BT_Enemy_BPService` ยังใช้ Service C++ (ต้อง Duplicate ก่อนสลับ Service ใน `BT_Enemy`) หรือ *Log Target Changes* ของ Node Service C++ ใน `BT_Enemy` ยังกาอยู่ (การบันทึก Output Log มีต้นทุน ส่วน Service ใน Blueprint ไม่มีการบันทึกให้ปิด)
- **`EnemySpawner` ที่วางแล้วไม่มี Location/Rotation/Scale ในแผง Details และ Enemy ทั้งตารางเกิดที่จุดกำเนิดของโลกของเกม (Game World)** — C++ Class ไม่มี Root Component (รุ่นก่อนการแก้ไข หรือผู้อ่านลบ `Root` ออก) Actor ที่ไม่มี Root Component ไม่มี Transform จึงวางหรือย้ายไม่ได้ ให้ตรวจว่า ตัวสร้าง (Constructor) สร้าง `USceneComponent` และเรียก `SetRootComponent` แล้ว Build ใหม่ และวาง Spawner ใหม่
- **Spawner สร้าง Enemy แต่ทุกตัวยืนนิ่ง** — จุดเกิดนอก NavMesh (บรรทัด `[Nodes] Spawner:` รายงาน `off-navmesh skipped` สูง หรือ Enemy ยืนบนพื้นที่ไม่ใช่สีเขียวเมื่อกด `P`) ให้ย้าย Spawner มากลางพื้นสีเขียวหรือลด *Grid Spacing*; หรือ `GetRandomReachablePointInRadius` ไม่ได้จุดใด (*Patrol Radius* เล็กกว่าช่องว่างรอบจุดเกิด) ให้เพิ่ม *Patrol Radius*; หรือรุ่นเก่าของ Spawner ที่ยังใช้ *Patrol Points* ร่วมกัน ให้ Build ใหม่
- **Enemy ทั้งฝูงเดินไปกองที่จุดเดียวแล้วเบียดกัน** — รุ่นเก่าของ Spawner ให้ทุกตัวใช้ TargetPoint สามจุดเดียวกัน ทั้งฝูงจึงบรรจบที่รัศมียอมรับของจุดแรก รุ่นที่ 2 สุ่มเส้นทางต่อตัว ให้ Build ใหม่และตรวจว่า `[Nodes] Spawner:` เป็นรูปแบบใหม่ (มี `dummies` และ `tree =`)
- **ส่วนต่างระหว่างสองฉบับเป็นศูนย์ที่ K = 3** — เป็นผลที่คาด: สามรอบลูป (Loop) ต่อ Tick เป็นเศษของฐาน 50 ตัวที่เดินด้วยแอนิเมชัน (Animation) ให้อ่านแถว K = 100 ก่อนสรุป และหากฐานเองสูงกว่า 15 ms ให้ใช้ `BP_Enemy_Bench`
- **`TargetDummy` ที่วางในแผนที่มองไม่เห็น มีแต่ป้ายชื่อ** — Mesh ของหุ่นคือ `/Engine/BasicShapes/Cylinder` ของเอนจิ้น (Engine) หากโหลดไม่สำเร็จ (Output Log มีคำเตือน `Failed to find object`) ให้ตั้ง *Static Mesh* ขององค์ประกอบ (Component) `Mesh` ที่อินสแตนซ์ (Instance) เป็น `Cylinder` ด้วยมือ (เปิด *Show Engine Content* ใน Content Browser) พฤติกรรมไม่เปลี่ยน เพราะ Service อ่านเฉพาะตำแหน่งของ Actor
