# บทที่ 2 — ข้อกำหนดในการเขียนโปรแกรมภาษา C++ ใน Unreal Engine

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 2 คือแท็ก (Tag) `ch02` บทนี้เพิ่มคลาสสาธิตสองคลาส (Class) เข้าไปในโมดูล (Module) `HAPBook` ซึ่งรวบรวมข้อกำหนดของ Unreal C++ ที่บทที่ 2 อธิบายไว้ในที่เดียว ได้แก่ ระบบคำนำหน้า (Prefix), `int32`, `FString` และมาโคร (Macro) `TEXT()`, `TArray`, `UPROPERTY`, `UFUNCTION`, `TObjectPtr` และการสร้างวัตถุ (Object) ด้วย `NewObject`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch02` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch02.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch02` แล้วใช้โฟลเดอร์ (Folder) `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" เรื่อง .NET runtime ก่อน ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` ใน File Explorer เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ที่ได้ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor (ปุ่ม Run ใน Rider หรือดับเบิลคลิก `HAPBook.uproject`) แล้วเปิดแผนที่ `Content/Maps/L_Ch02` (ดับเบิลคลิกใน Content Browser) แผนที่นี้มี `ConventionsDemoActor` วางไว้แล้ว
5. กด *Play* เมื่อกด Play แล้ว Player ของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับ Player เดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `Conventions` ในช่องกรอง (Filter)
7. เปรียบเทียบสองบรรทัดที่ปรากฏกับกล่อง "ผลลัพธ์การทำงาน (Console Output)" ในหัวข้อ "ตัวอย่างประกอบ: คลาสสาธิตข้อกำหนดของ Unreal C++" ของบทที่ 2

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools (Build Tools for Visual Studio) พร้อมเวิร์กโหลด (Workload) "Desktop development with C++" และ ".NET desktop build tools" (ขั้นตอนอยู่ในภาคผนวก ก ของงานเขียน)
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

File `HAPBook/.vsconfig` เป็นรายการองค์ประกอบสำหรับ Visual Studio ฉบับเต็มที่เอนจิ้น (Engine) สร้างมากับ Project Rider ไม่ได้ใช้ File นี้ Project นี้สร้างจาก Template Third Person (C++) ของ Epic ใน Unreal Engine 5.8 โดยไม่ดัดแปลงและไม่มี Starter Content แล้วเพิ่มพื้นเปล่า `Content/Maps/L_Book` สำหรับใช้เป็น Template ดังนั้นใน `Source/HAPBook/` จึงมี Class ของแม่แบบ (Template) อยู่ก่อนแล้ว ทั้งสาม Class ได้แก่ `AHAPBookCharacter`, `AHAPBookGameMode` และ `AHAPBookPlayerController` (File `HAPBookCharacter.*`, `HAPBookGameMode.*`, `HAPBookPlayerController.*`) พร้อม Blueprint ลูกใน `Content/ThirdPerson/Blueprints/` และแผนที่ `Content/ThirdPerson/Lvl_ThirdPerson` ซึ่งใช้ตั้งแต่ส่วนที่ 3 (บทที่ 7) เป็นต้นไป โฟลเดอร์ย่อย `Source/HAPBook/Variant_Combat/`, `Variant_Platforming/`, `Variant_SideScrolling/` และ `Content/Variant_*/` เป็นตัวอย่างแนวเกมของ Epic ที่มากับ Template ไม่ได้ใช้ในงานเขียน ผู้อ่านบทที่ 2–6 ไม่ต้องสนใจ Folder เหล่านี้ Class ของบทนี้และบทต่อ ๆ ไปอยู่ที่รากของ `Source/HAPBook/` เคียงข้าง Class ของ Template และชื่อ Class ทุก Class เป็นไปตามระบบ Prefix เดียวกัน (`A` สำหรับ Actor, `U` สำหรับ UObject)

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายผลลัพธ์จากการอ่านชุดคำสั่งก่อน ได้แก่ ผลรวมของ `Scores` `{80, 90, 100}` มีค่าเท่าใด และชื่อ Class ของ Object ที่ `NewObject` สร้างขึ้นจะขึ้นต้นด้วย Prefix ตัวใด จากนั้นจึงเปรียบเทียบกับ Output Log ซึ่งต้องแสดงสองบรรทัดต่อไปนี้ทุกอักขระ

```
LogTemp: [Conventions] Name: Sentinel-01 | Health: 100 | Scores: 3 items (sum 270)
LogTemp: [Conventions] Data object created via NewObject: UConventionsData (Level=2)
```

- บรรทัดที่ 1 ยืนยันค่าเริ่มต้น (Default Value) ของ Member `FString`, `int32` และ `TArray<int32>` และผลของ `GetScoreSum()` (80 + 90 + 100 = 270)
- บรรทัดที่ 2 ยืนยันว่า `NewObject<UConventionsData>(this)` สร้าง Object สำเร็จ ชื่อ Class ประกอบด้วย Prefix U และค่า `Level` ที่ประกาศไว้ใน `UPROPERTY` ถูกอ่านได้ (2)

การทดลองเพิ่มเติม: เลือก Actor ที่วางไว้ในแผนที่ แล้วแก้ค่า `Health` หรือ `DisplayName` ในแผง Details ก่อนกด Play บรรทัดที่ 1 จะเปลี่ยนตามค่าที่แก้ นี่คือผลของ `UPROPERTY(EditAnywhere)` ที่เปิดเผย Member สู่ตัวแก้ไข (Editor) ผ่านระบบ Reflection

## ปัญหาที่พบบ่อย

- **แก้ไขไฟล์ Header (Header File) แล้ว Live Coding ไม่รับการเปลี่ยนแปลง หรือ Editor แสดงพฤติกรรมเดิม** — Live Coding รองรับการแก้ไขใน File `.cpp` เป็นหลัก การเพิ่มหรือแก้ไข `UPROPERTY`/`UFUNCTION` ใน Header File ต้องปิด Editor แล้วสั่ง Build ใหม่จาก Rider จากนั้นจึงเปิด Editor อีกครั้ง
- **`error: #include "...generated.h" must be the last include`** — บรรทัด `#include "ConventionsDemoActor.generated.h"` (หรือของ Class อื่น) ต้องเป็น `#include` บรรทัดสุดท้ายของ Header File เสมอ ให้ย้าย `#include` อื่นขึ้นไปไว้ก่อนหน้า
- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch02` และได้กด *Play* แล้ว หากผู้อ่านลบ `ConventionsDemoActor` ออกจากแผนที่ไป ให้ค้นหาในแผง *Place Actors* แล้วลากกลับไปวางใหม่ `BeginPlay()` ทำงานเฉพาะเมื่อเริ่มเล่นเท่านั้น ไม่ทำงานขณะแก้ไขแผนที่
- **ไม่เห็นหน้าต่าง Output Log** — เปิดจาก Menu *Window → Output Log* และตรวจสอบว่าช่องกรองไม่ได้พิมพ์ข้อความอื่นค้างไว้
- **มีข้อความถามเวอร์ชัน Engine เมื่อเปิด `.uproject` หรือเสนอให้แปลง Project** — ให้เลือก Unreal Engine 5.8 หากเครื่องมีหลายเวอร์ชัน ให้คลิกขวาที่ `HAPBook.uproject` เลือก *Switch Unreal Engine version…* แล้วเลือก 5.8 ก่อนเปิด
- **Rider เปิดแล้วไม่แสดง Solution หรือไม่พบไฟล์ Source (Source File)** — คลิกขวาที่ `HAPBook.uproject` ใน File Explorer แล้วเลือก *Generate project files* จากนั้นเปิด File `.uproject` ด้วย Rider อีกครั้ง (Solution File `.slnx` ที่ Engine สร้างขึ้นไม่ได้รวมอยู่ใน Companion เพราะสร้างใหม่ได้เสมอ)
- **เปิด `HAPBook.uproject` ด้วย Rider ไม่ได้ หรือ UnrealBuildTool เริ่มทำงานไม่สำเร็จ ทั้งที่ Solution File ยังเปิดได้** — Rider เรียก UnrealBuildTool ผ่าน `dotnet.exe` ที่อยู่ใน PATH ของระบบ ส่วน UnrealBuildTool ของ UE 5.8 ต้องการ .NET runtime รุ่นที่ระบุใน File `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` (ค่า `framework.version`) วิธีวินิจฉัย: ทำการรัน (Run) `dotnet --list-runtimes` ใน Command Prompt หากไม่มีรุ่นหลักที่ตรงกับค่าดังกล่าว ให้แก้ด้วยวิธีใดวิธีหนึ่ง (1) วิธีหลัก: ใน Rider เปิด *Settings → Build, Execution, Deployment → Toolset and Build* แล้วตั้ง ".NET CLI executable path" เป็น `Engine\Binaries\ThirdParty\DotNet\<รุ่น>\win-x64\dotnet.exe` ของ Engine จากนั้นเปิด Rider ใหม่ (2) ทางเลือก: ติดตั้ง .NET SDK x64 รุ่นที่ตรงกันจาก dotnet.microsoft.com เปิดเครื่องใหม่ แล้วสร้าง Project File ใหม่ (*Generate project files*)
- **เปิด Project แล้ว Rider เปิดหน้าต่างที่สองขึ้นมาเอง** — ค่า *Editor Preferences → General → Source Code → Source Code Editor* ใน Unreal Editor ต้องตรงกับวิธีเปิด กล่าวคือ "Rider Uproject" เมื่อเปิดผ่าน File `.uproject` และ "Rider" เมื่อเปิดผ่าน Solution File หากไม่ตรงกัน Editor จะเปิด Rider อีกหน้าต่างหนึ่งเมื่อสั่งเปิด Code
