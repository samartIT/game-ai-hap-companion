# บทที่ 2 — ข้อกำหนดในการเขียนโปรแกรมภาษา C++ ใน Unreal Engine

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 2 คือแท็ก `ch02` บทนี้เพิ่มคลาสสาธิตสองคลาสเข้าไปในโมดูล `HAPBook` ซึ่งรวบรวมข้อกำหนดของ Unreal C++ ที่บทที่ 2 อธิบายไว้ในที่เดียว ได้แก่ ระบบคำนำหน้า, `int32`, `FString` และมาโคร `TEXT()`, `TArray`, `UPROPERTY`, `UFUNCTION`, `TObjectPtr` และการสร้างวัตถุด้วย `NewObject`

## เริ่มต้น

โปรเจกต์ประกอบเก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch02` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch02.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch02` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" เรื่อง .NET runtime ก่อน ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` ใน File Explorer เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันที่ได้ด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor (ปุ่ม Run ใน Rider หรือดับเบิลคลิก `HAPBook.uproject`) แล้วเปิดแผนที่ `Content/Maps/L_Ch02` (ดับเบิลคลิกใน Content Browser) แผนที่นี้มี `ConventionsDemoActor` วางไว้แล้ว
5. กด *Play* เมื่อกด Play ตัวละครผู้เล่นของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับตัวละครผู้เล่นเดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `Conventions` ในช่องกรอง (Filter)
7. เปรียบเทียบสองบรรทัดที่ปรากฏกับกล่อง "ผลลัพธ์การทำงาน (Console Output)" ในหัวข้อ "ตัวอย่างประกอบ: คลาสสาธิตข้อกำหนดของ Unreal C++" ของบทที่ 2

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

ไฟล์ `HAPBook/.vsconfig` ระบุองค์ประกอบของ Build Tools ที่ต้องติดตั้งอย่างครบถ้วน (Visual Studio Installer จะเสนอให้ติดตั้งองค์ประกอบที่ขาดเมื่อเปิดโปรเจกต์) โปรเจกต์นี้สร้างจาก Template Third Person (C++) ของ Epic ใน Unreal Engine 5.8 โดยไม่ดัดแปลงและไม่มี Starter Content แล้วเพิ่มพื้นเปล่า `Content/Maps/L_Book` สำหรับใช้เป็นแม่แบบ ดังนั้นใน `Source/HAPBook/` จึงมีคลาสของ Template อยู่ก่อนแล้วสามคลาส ได้แก่ `AHAPBookCharacter`, `AHAPBookGameMode` และ `AHAPBookPlayerController` (ไฟล์ `HAPBookCharacter.*`, `HAPBookGameMode.*`, `HAPBookPlayerController.*`) พร้อม Blueprint ลูกใน `Content/ThirdPerson/Blueprints/` และแผนที่ `Content/ThirdPerson/Lvl_ThirdPerson` ซึ่งใช้ตั้งแต่ส่วนที่ 3 (บทที่ 7) เป็นต้นไป โฟลเดอร์ย่อย `Source/HAPBook/Variant_Combat/`, `Variant_Platforming/`, `Variant_SideScrolling/` และ `Content/Variant_*/` เป็นตัวอย่างแนวเกมของ Epic ที่มากับ Template ไม่ได้ใช้ในงานเขียน ผู้อ่านบทที่ 2–6 ไม่ต้องสนใจโฟลเดอร์เหล่านี้ คลาสของบทนี้และบทต่อ ๆ ไปอยู่ที่รากของ `Source/HAPBook/` เคียงข้างคลาสของ Template และชื่อคลาสทุกคลาสเป็นไปตามระบบคำนำหน้าเดียวกัน (`A` สำหรับ Actor, `U` สำหรับ UObject)

## ไฟล์และตัวอย่างชุดคำสั่ง

| ไฟล์ (ใน `Source/HAPBook/`) | ตัวอย่างชุดคำสั่งในบทที่ 2 | เนื้อหา |
|---|---|---|
| `ConventionsData.h` | 2.3, 2.6 (ใช้เป็นชนิดของสมาชิก `Data`) | `UConventionsData : UObject` คำนำหน้า U, `UPROPERTY int32 Level = 2` |
| `ConventionsData.cpp` | — | ไฟล์นิยามว่าง (คลาสไม่มีตรรกะเพิ่มเติม) |
| `ConventionsDemoActor.h` | 2.3, 2.6 | `AConventionsDemoActor : AActor` คำนำหน้า A, สมาชิก `int32`/`FString`/`TArray<int32>`, `TObjectPtr<UConventionsData> Data`, `UFUNCTION(BlueprintCallable) GetScoreSum()` |
| `ConventionsDemoActor.cpp` | 2.7 | Constructor (กำหนด `Scores`), `GetScoreSum()`, `BeginPlay()` ที่สร้าง `Data` ด้วย `NewObject` และบันทึก Output Log |

ตัวอย่างชุดคำสั่งที่ 2.1, 2.4 และ 2.5 ของบทที่ 2 (`TArray` เทียบกับ `std::vector`, `StandardPlayer`, `AUnrealPlayer`) เป็นตัวอย่างเชิงเปรียบเทียบเพื่ออธิบายแนวคิด ไม่มีไฟล์ในโปรเจกต์ ตัวอย่างชุดคำสั่งที่ 2.2 (การประกาศสมาชิกด้วย Raw Pointer แบบดั้งเดิม) แสดงรูปแบบที่ไม่ควรใช้ในโค้ดใหม่ จึงไม่ปรากฏในไฟล์ใด ๆ ส่วนฟังก์ชัน `Inspect()` ในตัวอย่างชุดคำสั่งที่ 2.3 เป็นเพียงตัวอย่างการแปลงชนิดโดยปริยาย ไม่มีในคลาสจริง

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายผลลัพธ์จากการอ่านชุดคำสั่งก่อน ได้แก่ ผลรวมของ `Scores` `{80, 90, 100}` มีค่าเท่าใด และชื่อคลาสของวัตถุที่ `NewObject` สร้างขึ้นจะขึ้นต้นด้วยคำนำหน้าตัวใด จากนั้นจึงเปรียบเทียบกับ Output Log ซึ่งต้องแสดงสองบรรทัดต่อไปนี้ทุกอักขระ

```
LogTemp: [Conventions] Name: Sentinel-01 | Health: 100 | Scores: 3 items (sum 270)
LogTemp: [Conventions] Data object created via NewObject: UConventionsData (Level=2)
```

- บรรทัดที่ 1 ยืนยันค่าเริ่มต้นของสมาชิก `FString`, `int32` และ `TArray<int32>` และผลของ `GetScoreSum()` (80 + 90 + 100 = 270)
- บรรทัดที่ 2 ยืนยันว่า `NewObject<UConventionsData>(this)` สร้างวัตถุสำเร็จ ชื่อคลาสประกอบด้วยคำนำหน้า U และค่า `Level` ที่ประกาศไว้ใน `UPROPERTY` ถูกอ่านได้ (2)

การทดลองเพิ่มเติม: เลือก Actor ที่วางไว้ในแผนที่ แล้วแก้ค่า `Health` หรือ `DisplayName` ในแผง Details ก่อนกด Play บรรทัดที่ 1 จะเปลี่ยนตามค่าที่แก้ นี่คือผลของ `UPROPERTY(EditAnywhere)` ที่เปิดเผยสมาชิกสู่ Editor ผ่านระบบ Reflection

## ปัญหาที่พบบ่อย

- **แก้ไขไฟล์ Header แล้ว Live Coding ไม่รับการเปลี่ยนแปลง หรือ Editor แสดงพฤติกรรมเดิม** — Live Coding รองรับการแก้ไขในไฟล์ `.cpp` เป็นหลัก การเพิ่มหรือแก้ไข `UPROPERTY`/`UFUNCTION` ในไฟล์ Header ต้องปิด Editor แล้วสั่ง Build ใหม่จาก Rider จากนั้นจึงเปิด Editor อีกครั้ง
- **`error: #include "...generated.h" must be the last include`** — บรรทัด `#include "ConventionsDemoActor.generated.h"` (หรือของคลาสอื่น) ต้องเป็น `#include` บรรทัดสุดท้ายของไฟล์ Header เสมอ ให้ย้าย `#include` อื่นขึ้นไปไว้ก่อนหน้า
- **ไม่มีบรรทัดใดใน Output Log** — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch02` และได้กด *Play* แล้ว หากผู้อ่านลบ `ConventionsDemoActor` ออกจากแผนที่ไป ให้ค้นหาในแผง *Place Actors* แล้วลากกลับไปวางใหม่ `BeginPlay()` ทำงานเฉพาะเมื่อเริ่มเล่นเท่านั้น ไม่ทำงานขณะแก้ไขแผนที่
- **ไม่เห็นหน้าต่าง Output Log** — เปิดจากเมนู *Window → Output Log* และตรวจสอบว่าช่องกรองไม่ได้พิมพ์ข้อความอื่นค้างไว้
- **มีข้อความถามเวอร์ชันเอนจิ้นเมื่อเปิด `.uproject` หรือเสนอให้แปลงโปรเจกต์** — ให้เลือก Unreal Engine 5.8 หากเครื่องมีหลายเวอร์ชัน ให้คลิกขวาที่ `HAPBook.uproject` เลือก *Switch Unreal Engine version…* แล้วเลือก 5.8 ก่อนเปิด
- **Rider เปิดแล้วไม่แสดงโซลูชันหรือไม่พบไฟล์ Source** — คลิกขวาที่ `HAPBook.uproject` ใน File Explorer แล้วเลือก *Generate project files* จากนั้นเปิดไฟล์ `.uproject` ด้วย Rider อีกครั้ง (ไฟล์โซลูชัน `.slnx` ที่เอนจิ้นสร้างขึ้นไม่ได้รวมอยู่ในชุดโค้ดประกอบ เพราะสร้างใหม่ได้เสมอ)
- **เปิด `HAPBook.uproject` ด้วย Rider ไม่ได้ หรือ UnrealBuildTool เริ่มทำงานไม่สำเร็จ ทั้งที่ไฟล์โซลูชันยังเปิดได้** — Rider เรียก UnrealBuildTool ผ่าน `dotnet.exe` ที่อยู่ใน PATH ของระบบ ส่วน UnrealBuildTool ของ UE 5.8 ต้องการ .NET runtime รุ่นที่ระบุในไฟล์ `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` (ค่า `framework.version`) วิธีวินิจฉัย: รัน `dotnet --list-runtimes` ใน Command Prompt หากไม่มีรุ่นหลักที่ตรงกับค่าดังกล่าว ให้แก้ด้วยวิธีใดวิธีหนึ่ง (1) วิธีหลัก: ใน Rider เปิด *Settings → Build, Execution, Deployment → Toolset and Build* แล้วตั้ง ".NET CLI executable path" เป็น `Engine\Binaries\ThirdParty\DotNet\<รุ่น>\win-x64\dotnet.exe` ของเอนจิ้น จากนั้นเปิด Rider ใหม่ (2) ทางเลือก: ติดตั้ง .NET SDK x64 รุ่นที่ตรงกันจาก dotnet.microsoft.com เปิดเครื่องใหม่ แล้วสร้างไฟล์โปรเจกต์ใหม่ (*Generate project files*)
- **เปิดโปรเจกต์แล้ว Rider เปิดหน้าต่างที่สองขึ้นมาเอง** — ค่า *Editor Preferences → General → Source Code → Source Code Editor* ใน Unreal Editor ต้องตรงกับวิธีเปิด กล่าวคือ "Rider Uproject" เมื่อเปิดผ่านไฟล์ `.uproject` และ "Rider" เมื่อเปิดผ่านไฟล์โซลูชัน หากไม่ตรงกัน Editor จะเปิด Rider อีกหน้าต่างหนึ่งเมื่อสั่งเปิดโค้ด
