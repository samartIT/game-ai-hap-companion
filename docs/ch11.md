# บทที่ 11 — การจำแนกฝ่ายและการรับรู้ภัยคุกคาม

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 11 คือแท็ก (Tag) `ch11` บทนี้ให้ศัตรู (Enemy) มองเห็นก่อน แล้วจึงรู้ว่าใครเป็นใคร AI Perception อยู่ใน Blueprint ลูก `BP_EnemyAIController` ของคลาส (Class) C++ `AEnemyAIController`: Component AIPerception ที่เพิ่มด้วย *Add* พร้อม Sense Sight (1500/2000/ครึ่งมุม 70) และ Hearing (1500) ซึ่งตั้งในแผง Details ของ Blueprint และ `BP_Enemy` ใช้ Controller นี้ผ่าน *AI Controller Class* ฝั่ง C++ ของ Controller ถือเฉพาะสิ่งที่ Blueprint ทำไม่ได้หรือสิ่งที่ถือนโยบาย ได้แก่ ฝ่าย (Team) 2 กับตัวตัดสินความสัมพันธ์ฝ่าย (Attitude Solver; Team เดียวกัน Friendly ต่าง Team Hostile ไม่มี Team Neutral) ตัวรับสิ่งเร้าที่บันทึกทุกสิ่งที่เห็นแต่เขียน Blackboard เฉพาะเมื่อความสัมพันธ์เป็นปรปักษ์ (Hostile) และสวิตช์ (Switch) ที่เปิดหรือถอนผู้รับรู้ (Listener) ตาม *Perception Enabled* ของ Enemy ที่วางในแผนที่ ขั้นที่ 1 (เลือก Detect Neutrals) Enemy เห็นผู้เล่น (Player) และหุ่นแต่ไม่สนใจสิ่งใด ขั้นที่ 2 Player ได้ C++ Class `AHAPPlayerCharacter` (ลูกของ `AHAPBookCharacter` ของ Template) เป็น Team 1 ผ่านการ Reparent ของ `BP_ThirdPersonCharacter` และเมื่อไม่เลือก Detect Neutrals Sight เห็นเฉพาะ Player ขั้นที่ 3 เพิ่มคีย์ (Key) `TargetActor`/`LastKnownLocation` และกิ่ง (Branch) `Chase` (Observer Aborts Both) Enemy ไล่ตาม และเมื่อเสียสายตาเดินไปยังตำแหน่งที่พบล่าสุด (Last Known Location) ด้วย Branch `Investigate` ของบทที่ 8 ขั้นที่ 4 ให้ Player ก่อเสียง (Noise) เมื่อกระโดด แผนที่ `L_Ch11` เป็นสำเนาของ `L_Ch10` ที่ไม่มี `BP_HazardZone`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch11` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch11.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch11` แล้วใช้โฟลเดอร์ (Folder) `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch11` ซึ่งมี `BP_Enemy` หนึ่งตัว (เลือก *Perception Enabled* แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone` และ `EnemySpawner` (*Spawn Count* 0) ของบทก่อน และไม่มี `BP_HazardZone` เมื่อกด Play Player เป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของ Player คือ Stimulus ที่ AI รับรู้

บทนี้สร้างเป็นสี่ขั้น Tag `ch11` คือสถานะหลังขั้นที่ 4: `BP_ThirdPersonCharacter` ถูก Reparent แล้ว (ขั้นที่ 2) และ Detect Neutrals ใน `BP_EnemyAIController` ไม่ได้เลือก (ขั้นที่ 2) การเล่นแต่ละขั้นทำดังนี้ (กรอง Output Log ด้วย `[Perception]`)

5. **ขั้นที่ 1 — การมองเห็น (Sight):** เปิด `BP_EnemyAIController` เลือกองค์ประกอบ (Component) `AIPerception` ในแผง Details ที่ *Senses Config* [0] *Detection by Affiliation* เลือก *Detect Neutrals* แล้วทำการคอมไพล์ (Compile) และ Save จากนั้น Play โดยยังไม่บังคับ Player ให้เข้าใกล้ Enemy ภายในรอบแรกต้องได้บรรทัด Sight gained ของหุ่นตัวแรกที่เข้าขอบเขตการมองเห็น (Sight Cone) และเมื่อ Player เดินเข้า Sight Cone บรรทัดของ Player Enemy ไม่เดินเข้าหาหุ่น ใน Tag นี้ Player ถูก Reparent แล้ว จึงเป็น Hostile และ Enemy ไล่ตาม Player ส่วนหุ่นถูกบันทึกแต่ไม่ถูกสนใจ ซึ่งแสดงกฎ "เฉพาะ Hostile" ของตัวรับ หากต้องการเห็นสภาพของขั้นที่ 1 ตามบททุกประการ (Enemy ไม่สนใจทั้ง Player และหุ่น) ให้เปิด `BP_ThirdPersonCharacter` เลือก *File → Reparent Blueprint* เลือก `HAPBookCharacter` ชั่วคราว Compile และ Save แล้ว Play
6. **ขั้นที่ 2 — Team ในฐานะตัวกรอง:** หาก Reparent กลับเป็น `HAPBookCharacter` ไว้ในข้อก่อน ให้ Reparent เป็น `HAPPlayerCharacter` อีกครั้งและยืนยัน *Team Id* 1 ใน Class Defaults จากนั้นไม่เลือก *Detect Neutrals* ใน `BP_EnemyAIController` แล้ว Compile และ Save แล้ว Play ต้องได้บรรทัด Teams ในวินาทีแรก Enemy เดินผ่านหุ่นทั้งสามโดยไม่มีบรรทัดใด และเมื่อ Player เดินเข้า Sight Cone บรรทัด Sight gained ของ Player เพียงบรรทัดเดียว
7. **ขั้นที่ 3 — ความจำและการไล่ตาม:** ใน Play เดียวกัน เมื่อ Enemy เห็น Player Enemy ต้องหันมาไล่ตามทันทีและหยุดห่างประมาณ 150 เมื่อถึงตัว จากนั้นบังคับ Player ให้วิ่งไปหลบหลังกำแพงหรือบล็อก (Block) ของฉาก Enemy ต้องเดินไปยัง Last Known Location หยุดสองวินาที แล้วกลับไปลาดตระเวน ระหว่างไล่ตามกด Apostrophe (`'`) แล้วแป้นตัวเลข 4 เพื่อดูวงกลมสองวงและ Sight Cone ในหมวด Perception ของ Gameplay Debugger
8. **ขั้นที่ 4 — การได้ยิน (Hearing):** Play แล้วบังคับ Player ให้เดินไปยืนหลังกำแพงที่ Enemy มองไม่เห็นภายในระยะ 1500 จากเส้นทางลาดตระเวน รอให้ Enemy เข้าใกล้ แล้วให้ Player กระโดดหนึ่งครั้ง (Space) ต้องได้บรรทัด Heard ทันที ตามด้วยบรรทัด Patrol aborted ของบทที่ 8 Enemy เดินมายังจุดที่กระโดด หยุดสองวินาที แล้วกลับไปลาดตระเวน

## จุดตรวจสอบผลลัพธ์

จุดตรวจสอบมีหนึ่งจุดต่อขั้น (กรอง Output Log ด้วย `[Perception]` แล้ว `[BT]`)

**ขั้นที่ 1 — Sight:** สองบรรทัดนี้ในลำดับใดก็ได้ (หุ่นตัวแรกอาจเป็น `Dummy_02` หรือ `Dummy_03` ตามทิศที่ Enemy หันเมื่อเริ่ม) ก่อนกด Play ผู้อ่านควรทำนายว่า Enemy จะรายงานสิ่งใดบ้างในรอบแรก และจะเดินเข้าหาสิ่งใดหรือไม่ เมื่อ Player ยังไม่มี Team Enemy ไม่เดินเข้าหาทั้ง Player และหุ่น เพราะตัวรับเขียนความรู้เฉพาะเรื่องสิ่งที่เป็น Hostile

```
LogTemp: [Perception] Sight gained: Dummy_01
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
```

**ขั้นที่ 2 — Team ในฐานะตัวกรอง:** บรรทัด Teams หนึ่งครั้งในวินาทีแรก (Tick ถัดจาก `BeginPlay()` ของ Controller) จากนั้นหุ่นเงียบทั้งรอบ และบรรทัดของ Player เมื่อ Player เข้า Sight Cone หากบรรทัด Teams อ่านว่า `player=255 attitude=Neutral` Blueprint ของ Player ยังไม่ได้ Reparent และบรรทัดที่สองจะไม่ปรากฏ

```
LogTemp: [Perception] Teams: enemy=2 player=1 attitude=Hostile
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
```

**ขั้นที่ 3 — ความจำและการไล่ตาม:** สามบรรทัดนี้ตามลำดับ ก่อนให้ Player หลบ ผู้อ่านควรทำนายว่า Enemy จะหยุดทันทีที่ Player หายไป หรือเดินต่อไปที่ใด ไม่มีบรรทัด `Patrol aborted` ระหว่างบรรทัดที่สองกับสาม และไม่มีบรรทัด `[AI] Reached waypoint` ระหว่างการไล่ตาม

```
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
```

**ขั้นที่ 4 — Hearing:** บรรทัดนี้ทันทีที่ Player กระโดด ตามด้วย `[BT] Patrol aborted by Observer Aborts (Lower Priority)` และ `[BT] Investigate: reached AlertLocation, Alerted cleared` ของบทที่ 8 เมื่อ Enemy ถึงจุดที่กระโดด

```
LogTemp: [Perception] Heard: BP_ThirdPersonCharacter_C -> investigating noise
```

ที่มาของแต่ละบรรทัด

- บรรทัด Sight gained: จาก `OnTargetPerceptionUpdated()` เมื่อ `WasSuccessfullySensed()` จริง Sense Sight สร้าง Query ให้คู่ Listener–แหล่งที่ผ่านตัวกรอง Team (ขั้นที่ 1: ทุกคู่ เพราะทุกสิ่งเป็นกลาง (Neutral) และ Detect Neutrals เลือกไว้; ขั้นที่ 2: เฉพาะคู่ Hostile) ทำ Line Trace สำเร็จ แล้วลงทะเบียนสิ่งเร้า (Stimulus) ตัวรับบันทึกบรรทัดนี้สำหรับทุกสิ่ง แล้วเขียน `LastKnownLocation` และ `TargetActor` เฉพาะเมื่อ `GetTeamAttitudeTowards()` ตอบ Hostile ชื่อคือ `DummyName` ของหุ่น หรือชื่อ Class ของ Blueprint (`PerceivedName()`)
- บรรทัด Teams: จาก `LogTeamAttitude()` สามค่าผ่านเส้นทางจริงของเอนจิ้น (Engine): `TeamID` ของ Controller, `FGenericTeamId::GetTeamIdentifier(PlayerPawn)` (Cast Pawn เป็น Interface) และ `GetTeamAttitudeTowards(*PlayerPawn)` ซึ่งผ่าน Attitude Solver ของบท
- บรรทัด Sight lost: ฟังก์ชัน (Function) เดียวกันกับ Stimulus `SensingFailed` ที่ Sight ลงทะเบียนเองเมื่อ Line Trace ล้มเหลว เฉพาะเป้าหมาย Hostile ตัวรับเขียน `LastKnownLocation` และ `AlertLocation` ตั้ง `Alerted` แล้วล้าง `TargetActor` (ลำดับนี้ทำให้ตัวตรวจ Patrol aborted ของบทที่ 8 ไม่พิมพ์ข้อความที่ไม่จริง) สิ่งที่ไม่ใช่ Hostile หายจากสายตาโดยไม่มีบรรทัด
- บรรทัด Investigate: บรรทัดของบทที่ 8 ทุกอักขระ จาก `WasInvestigateArrival()` ใน `OnMoveCompleted()`
- บรรทัด Heard: สาขา Hearing ของ Function เดียวกัน Make Noise ของ Player → `AActor::MakeNoiseDelegate` (ชี้ไปยัง `UAIPerceptionSystem::MakeNoiseImpl` ตั้งแต่ Sense Hearing ตัวแรกของโปรเซสถูกสร้าง) → `FAINoiseEvent` (รหัส Team 1 ของร่าง (Pawn) ของ Player) → Sense Hearing ตรวจระยะ 1500 ทั้งสองฝั่ง เทียบ Team 2 กับ 1 ได้ Hostile → Stimulus ที่ตำแหน่ง Noise โดยไม่หน่วง (`SpeedOfSoundSq` = 0) → ตัวรับได้ Hostile อีกครั้งและเขียน `AlertLocation`/`Alerted`

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08`, `L_Ch09` แล้ว `L_Ch10` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[Perception]` ใดเลย: Enemy ในแผนที่เหล่านั้นใช้ `BP_EnemyAIController` เช่นกัน (มี Component AIPerception) แต่ *Perception Enabled* เป็นเท็จ ตอน Possess Controller จึงถอน Listener ออกจากระบบกลาง ไม่มี Query ไม่มี Line Trace และ Branch `Chase` ของ `BT_Enemy` (Asset ร่วม) ไม่เคยถูกเลือกเพราะไม่มีสิ่งใดเขียน `TargetActor` การกระโดดในแผนที่เหล่านั้นก็ไม่มีบรรทัด เพราะไม่มี Listener ที่ลงทะเบียนอยู่ จากนั้นใน `L_Ch11` ตั้ง *Lose Sight Radius* เป็น 1000 ใน `BP_EnemyAIController` (ไม่ต้อง Build) แล้วให้ Player ยืนนิ่งที่ระยะประมาณ 1200 ตรงหน้า Enemy (แบบฝึกหัดข้อ 6 ของบทที่ 11)

## ปัญหาที่พบบ่อย

- **หา Perception ในแผง Details ไม่พบ (ไม่มี Senses Config ให้ตั้ง)** — กำลังดู C++ Class `EnemyAIController` ซึ่งไม่มี Component AIPerception ให้เปิด `BP_EnemyAIController` ใน `Content/AI` แล้วเลือก Component `AIPerception` ในแผง Components
- **Output Log มีคำเตือน `Perception Enabled but the controller has no AIPerception component`** — *AI Controller Class* ใน Class Defaults ของ `BP_Enemy` ยังเป็น `EnemyAIController` (C++ Class) ให้ตั้งเป็น `BP_EnemyAIController` แล้ว Compile และ Save
- **ขั้นที่ 1: ไม่มีบรรทัดใดเลย แม้เดินตรงหน้า Enemy** — *Perception Enabled* ไม่ได้เลือกที่ `BP_Enemy` ที่วางใน `L_Ch11` (เป็นค่าของอินสแตนซ์ (Instance) ไม่อยู่ใน Class Defaults; เลือก Actor ในแผนที่แล้วดูหมวด *Perception* ของแผง Details) หรือ *Detect Neutrals* ใน `BP_EnemyAIController` ไม่ได้เลือกในขั้นที่ 1 (ยังไม่มี Team ทุกสิ่งเป็น Neutral ค่าเริ่มต้น (Default Value) Enemies เท่านั้นจึงมองไม่เห็นสิ่งใด) หรือ *Senses Config* ว่าง (Component ที่ไม่มี Sense ไม่ลงทะเบียนเป็น Listener)
- **ขั้นที่ 1: เห็น Player แต่ไม่เห็นหุ่น** — หุ่นไม่ได้ลงทะเบียนเป็นแหล่งสิ่งเร้า (Stimuli Source): `RegisterForSense` ถูกเรียกในตัวสร้าง (Constructor; ไม่มี World จึงไม่ทำอะไร) แทน `BeginPlay()` หรือ `StimuliSource` ไม่ถูกสร้าง หุ่นไม่ใช่ Pawn จึงไม่ถูกลงทะเบียนอัตโนมัติ
- **ขั้นที่ 1: Enemy หันมาเดินตาม Player** — Player มี Team อยู่แล้ว: `BP_ThirdPersonCharacter` ถูก Reparent เป็น `HAPPlayerCharacter` (สถานะของ Tag `ch11`) Player จึงเป็น Hostile และตัวรับเขียนความรู้ ในขั้นที่ 1 ตามบท Player มีคลาสแม่ (Parent Class) เป็น `HAPBookCharacter` ตามที่แม่แบบ (Template) ส่งมา
- **ขั้นที่ 2: Enemy ไม่สนใจ Player** — Player ยังไม่มี Team: ยังไม่ได้ Reparent `BP_ThirdPersonCharacter` เป็น `HAPPlayerCharacter` (File → Reparent Blueprint แล้ว Compile และ Save) หรือ *Team Id* ใน Class Defaults ถูกเปลี่ยนเป็น 2 (Team เดียวกับ Enemy = Friendly) หรือ 255 (`NoTeam` = Neutral) บรรทัด Teams บอกค่าที่ Engine เห็น หาก *Detect Neutrals* ยังเลือกไว้ บรรทัด Sight gained ของ Player จะยังปรากฏ แต่ Enemy ไม่ทำอะไรเพราะ Player เป็น Neutral การคง Detect Neutrals ไว้ไม่ใช่สาเหตุ สาเหตุคือ Team
- **ขั้นที่ 2 เป็นต้นไป: ยังมีบรรทัด Sight gained ของหุ่น** — *Detect Neutrals* ใน `BP_EnemyAIController` ยังเลือกไว้หลังขั้นที่ 1 พฤติกรรมยังถูกต้อง (ตัวรับเพิกเฉยต่อหุ่นซึ่งเป็น Neutral) แต่ระบบเสีย Query และ Line Trace ให้หุ่น ให้ไม่เลือกแล้ว Compile และ Save (ใน Tag `ch11` ช่องนี้ไม่ได้เลือก)
- **ขั้นที่ 2: เห็น Player แล้ว Enemy ยังลาดตระเวนต่อ แต่พอหลบ Enemy เดินไปยัง Last Known Location** — เป็นผลที่คาดเมื่อสร้างตามบทถึงขั้นที่ 2: Key `TargetActor`/`LastKnownLocation` และ Branch `Chase` ยังไม่มี (ขั้นที่ 3) การเขียน Key ที่ Blackboard ไม่มีจึงไม่มีผล ส่วนสาขา "หาย" เขียน Key ของบทที่ 8 ซึ่ง Branch `Investigate` อ่านอยู่แล้ว
- **บรรทัด Teams ถูกต้องแต่ไม่มีบรรทัด Sight gained แม้ยืนตรงหน้า** — *Detect Enemies* ไม่ได้เลือก หรือ Player ยืนนอก Sight Cone (ครึ่งมุม 70 องศา: ด้านข้างและด้านหลังของ Enemy มองไม่เห็น) หรืออยู่ไกลกว่า 1500 ให้เปิด Gameplay Debugger (`'` แล้วแป้น 4) ดู Sight Cone และวงกลม
- **Sight Cone ใน Gameplay Debugger ชี้ไปด้านหลัง Enemy (หรือไปทางหุ่นที่ผ่านมาแล้ว) ขณะ Enemy เดิน และ Enemy ไม่เห็น Player ที่อยู่ตรงหน้า** — มีจุดสนใจ (Focus) ที่ถูกตั้งแล้วไม่ถูกล้าง Sight มองตาม Control Rotation ของ Controller ซึ่งชี้ไปยัง Focus ระดับ `Gameplay` ก่อนทิศเดิน ไม่ใช่ตามทิศที่ Pawn หันหน้า ให้ตรวจว่า `UBTTask_FaceTarget` ของบทที่ 9 หมุน Pawn โดยตรงโดยไม่เรียก `SetFocus` (ตัวอย่างชุดคำสั่ง Task ของบทที่ 9) และ Code หรือ Node อื่นที่ตั้ง Focus ล้าง Focus ด้วย `ClearFocus(EAIFocusPriority::Gameplay)` เมื่อหมดหน้าที่
- **เห็นแล้ว (มีบรรทัด Sight gained) แต่ไม่ไล่ตาม หรือไล่ตามหลังถึงจุดลาดตระเวน (Patrol Point) ก่อน** — Observer Aborts ของ Decorator บน Branch `Chase` ไม่ใช่ Both (Self เท่านั้น: ต้องรอให้ Branch ที่ทำงานอยู่จบ; None: ไม่ยุติเลย) หรือ Branch `Chase` ไม่ได้อยู่ซ้ายสุดของ Selector หรือ Key `TargetActor` ไม่ใช่ชนิด Object ที่มี Base Class Actor (Move To ไม่ยอมรับ) หรือสะกดชื่อ Key ไม่ตรงกับ `TargetActorKey` (`SetValue` ของ Blackboard คืนเท็จโดยไม่มีคำเตือน) หรือ Player ไม่ใช่ Hostile (ดูบรรทัด Teams)
- **Enemy ตามทันเสมอ วิ่งหนีอย่างไรก็ไม่พ้น** — Enemy เร็วกว่า Player: *Max Walk Speed* ของ `BP_Enemy` ยังเป็น Default Value 600 ขณะที่ Player เดินที่ 500 ให้ตั้งเป็น 400 ตามขั้นตอนใน Component CharacterMovement ของสูตรการสร้าง `BP_Enemy` ในบทที่ 7 และหลบหลัง Block ที่บังแนวสายตา (Line of Sight) ไม่ใช่วิ่งออกให้ไกล (*Lose Sight Radius* 2000 มากกว่า *Sight Radius* 1500 โดยเจตนา)
- **ไล่ตามตลอดไปแม้หลบหลังกำแพงแล้ว** — ไม่มีการจัดการ Stimulus ที่ `WasSuccessfullySensed()` เป็นเท็จ (สาขา "หาย" หายไป) หรือสาขานั้นไม่ได้ล้าง `TargetActor` หรือกำแพงที่ใช้หลบไม่บังแคปซูลทั้งตัว (Line Trace เล็งที่ตำแหน่ง Actor) ให้หลบหลัง Block ที่สูงกว่าตัวละคร (Character)
- **หลบแล้ว Enemy หยุดนิ่งแทนที่จะเดินไปยัง Last Known Location** — ลำดับการเขียนในสาขา "หาย" ผิด: `AlertLocation` และ `Alerted` ต้องถูกเขียนก่อนล้าง `TargetActor` มิฉะนั้น Selector ค้นหาใหม่ขณะ `Alerted` ยังเท็จ หรือ `BB_Enemy` ไม่มี Key `Alerted`/`AlertLocation` ของบทที่ 8
- **บรรทัด `Patrol aborted by Observer Aborts (Lower Priority)` ปรากฏตอน Player หลบในขั้นที่ 3** — `OnAlertedChanged()` ไม่ได้ตรวจว่า `TargetActor` ยังตั้งอยู่ (ตัวตรวจของบทที่ 8 ต้องถูกข้ามขณะไล่ตาม) หรือสาขา "หาย" ล้าง `TargetActor` ก่อนตั้ง `Alerted` (ในขั้นที่ 2 บรรทัดนี้ปรากฏได้และเป็นความจริง เพราะ Enemy ลาดตระเวนอยู่)
- **กระโดดแล้วไม่มีบรรทัด Heard** — Make Noise ไม่ได้ต่อจาก Event On Jumped (หรือ Compile ไม่ผ่าน) หรือระยะเกิน 1500 (ทั้ง *Hearing Range* ของ Listener และ *Max Range* ของ Noise) หรือ *Senses Config* ของ `BP_EnemyAIController` ไม่มี AI Hearing config หรือ Player ไม่ใช่ Hostile
- **ได้ยินแล้วแต่ Enemy ไล่ตามแทนที่จะเดินไปตรวจสอบ** — เป็นผลที่คาดเมื่อ Enemy มองเห็น Player ระหว่างเดินมา: Branch `Chase` สำคัญกว่า `Investigate` ให้ยืนหลังกำแพงต่อไปจน Enemy ถึงจุดที่กระโดด
- **กระโดดครั้งที่สองขณะ Enemy กำลังเดินมาตรวจสอบครั้งแรก Enemy ไม่เปลี่ยนจุดหมาย** — เป็นผลที่คาด: Move To ของ Branch `Investigate` ไม่ได้ตั้ง *Observe Blackboard Value* จึงเดินไปยังค่าที่อ่านตอนเริ่ม `AlertLocation` ใหม่มีผลในการค้นหาครั้งถัดไป
- **Gameplay Debugger ไม่แสดง Sight Cone และวงกลม** — กดแป้นตัวเลข 4 (หมวด Perception) ไม่ใช่ 1–3 กล้องต้องมองเห็น Enemy ขณะกด `'` และ Controller ของ Enemy ต้องเป็น `BP_EnemyAIController` หมวดนี้อยู่ที่ 4 เพราะ Engine จองช่อง 0–2 ให้ Navmesh, AI และ Behavior Tree และจัดช่องที่เหลือตามลำดับอักษร (EQS 3, Perception 4); หาก Project มีหมวดเพิ่ม ให้อ่านหมายเลขจากแถบหัวของ Debugger
- **Enemy ใน `L_Ch07`–`L_Ch10` เริ่มไล่ตาม Player** — *Perception Enabled* ถูกเลือกใน Class Defaults ของ `BP_Enemy` แทน Instance ที่วางใน `L_Ch11` (ทำได้เฉพาะเมื่อคุณสมบัติถูกเปลี่ยนจาก `EditInstanceOnly` เป็น `EditAnywhere` หรือ `EditDefaultsOnly`) ค่าของ Class มีผลกับ `BP_Enemy` ทุกตัวในทุกแผนที่ ให้คืนเป็น `EditInstanceOnly` แล้วเลือกเฉพาะ Instance ใน `L_Ch11` การเปิดต่อ Instance คือสิ่งที่ทำให้แผนที่ก่อนหน้าไม่เปลี่ยน
- **Enemy ถึงตัว Player แล้วบรรทัด `[AI] Reached waypoint` เลื่อนไป** — `WasChaseArrival()` ไม่ถูกตรวจก่อนการเลื่อนดัชนีใน `OnMoveCompleted()` (Move To ของ Branch `Chase` ที่สำเร็จต้องไม่นับเป็นการถึง Patrol Point)
- **สองบรรทัด Sight gained/lost สลับกันซ้ำทุกรอบขณะ Player ยืนนิ่ง** — *Lose Sight Radius* เล็กกว่า *Sight Radius* ใน `BP_EnemyAIController` (แบบฝึกหัดข้อ 6) หรือ Player ยืนบนขอบของสิ่งกีดขวางที่ Line Trace บังเป็นบางเฟรม (Frame)
