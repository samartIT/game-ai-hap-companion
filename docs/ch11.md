# บทที่ 11 — การจำแนกฝ่ายและการรับรู้ภัยคุกคาม

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 11 คือแท็ก `ch11` บทนี้ให้ศัตรูมองเห็นก่อน แล้วจึงรู้ว่าใครเป็นใคร ระบบรับรู้อยู่ใน Blueprint ลูก `BP_EnemyAIController` ของคลาส C++ `AEnemyAIController`: Component AIPerception ที่เพิ่มด้วย *Add* พร้อม Sense Sight (1500/2000/ครึ่งมุม 70) และ Hearing (1500) ซึ่งตั้งในแผง Details ของ Blueprint และ `BP_Enemy` ใช้ Controller นี้ผ่าน *AI Controller Class* ฝั่ง C++ ของ Controller ถือเฉพาะสิ่งที่ Blueprint ทำไม่ได้หรือสิ่งที่ถือนโยบาย ได้แก่ ฝ่าย 2 กับ Attitude Solver (ฝ่ายเดียวกัน Friendly ต่างฝ่าย Hostile ไม่มีฝ่าย Neutral) ตัวรับสิ่งเร้าที่บันทึกทุกสิ่งที่เห็นแต่เขียน Blackboard เฉพาะเมื่อความสัมพันธ์เป็น Hostile และสวิตช์ที่เปิดหรือถอน Listener ตาม *Perception Enabled* ของศัตรูที่วางในแผนที่ ขั้นที่ 1 (เลือก Detect Neutrals) ศัตรูเห็นผู้เล่นและหุ่นแต่ไม่สนใจสิ่งใด ขั้นที่ 2 ผู้เล่นได้คลาส C++ `AHAPPlayerCharacter` (ลูกของ `AHAPBookCharacter` ของ Template) เป็นฝ่าย 1 ผ่านการ Reparent ของ `BP_ThirdPersonCharacter` และเมื่อไม่เลือก Detect Neutrals Sight เห็นเฉพาะผู้เล่น ขั้นที่ 3 เพิ่มคีย์ `TargetActor`/`LastKnownLocation` และ Branch (กิ่ง) `Chase` (Observer Aborts Both) ศัตรูไล่ตาม และเมื่อเสียสายตาเดินไปยังตำแหน่งที่พบล่าสุดด้วย Branch `Investigate` ของบทที่ 8 ขั้นที่ 4 ให้ผู้เล่นก่อเสียงเมื่อกระโดด แผนที่ `L_Ch11` เป็นสำเนาของ `L_Ch10` ที่ไม่มี `BP_HazardZone`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch11` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch11.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch11` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch11` ซึ่งมี `BP_Enemy` หนึ่งตัว (เลือก *Perception Enabled* แล้ว) กับ TargetPoint ลาดตระเวนสามจุด, หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone` และ `EnemySpawner` (*Spawn Count* 0) ของบทก่อน และไม่มี `BP_HazardZone` เมื่อกด Play ตัวละครผู้เล่นเป็นส่วนหนึ่งของตัวอย่างในบทนี้ การเคลื่อนที่ของตัวละครผู้เล่นคือสิ่งเร้าที่ AI รับรู้

บทนี้สร้างเป็นสี่ขั้น แท็ก `ch11` คือสถานะหลังขั้นที่ 4: `BP_ThirdPersonCharacter` ถูก Reparent แล้ว (ขั้นที่ 2) และ Detect Neutrals ใน `BP_EnemyAIController` ไม่ได้เลือก (ขั้นที่ 2) การเล่นแต่ละขั้นทำดังนี้ (กรอง Output Log ด้วย `[Perception]`)

5. **ขั้นที่ 1 — การมองเห็น:** เปิด `BP_EnemyAIController` เลือก Component `AIPerception` ในแผง Details ที่ *Senses Config* [0] *Detection by Affiliation* เลือก *Detect Neutrals* แล้ว Compile และ Save จากนั้น Play โดยยังไม่บังคับตัวละครผู้เล่น (Player) ให้เข้าใกล้ศัตรู (AI) ภายในรอบแรกต้องได้บรรทัด Sight gained ของหุ่นตัวแรกที่เข้าขอบเขตการมองเห็น (Sight Cone) และเมื่อตัวละครผู้เล่นเดินเข้าขอบเขตการมองเห็น บรรทัดของผู้เล่น ศัตรูไม่เดินเข้าหาหุ่น ในแท็กนี้ผู้เล่นถูก Reparent แล้ว จึงเป็น Hostile และศัตรูไล่ตามผู้เล่น ส่วนหุ่นถูกบันทึกแต่ไม่ถูกสนใจ ซึ่งแสดงกฎ "เฉพาะ Hostile" ของตัวรับ หากต้องการเห็นสภาพของขั้นที่ 1 ตามบททุกประการ (ศัตรูไม่สนใจทั้งผู้เล่นและหุ่น) ให้เปิด `BP_ThirdPersonCharacter` เลือก *File → Reparent Blueprint* เลือก `HAPBookCharacter` ชั่วคราว Compile และ Save แล้ว Play
6. **ขั้นที่ 2 — ฝ่ายในฐานะตัวกรอง:** หาก Reparent กลับเป็น `HAPBookCharacter` ไว้ในข้อก่อน ให้ Reparent เป็น `HAPPlayerCharacter` อีกครั้งและยืนยัน *Team Id* 1 ใน Class Defaults จากนั้นไม่เลือก *Detect Neutrals* ใน `BP_EnemyAIController` แล้ว Compile และ Save แล้ว Play ต้องได้บรรทัด Teams ในวินาทีแรก ศัตรูเดินผ่านหุ่นทั้งสามโดยไม่มีบรรทัดใด และเมื่อตัวละครผู้เล่นเดินเข้าขอบเขตการมองเห็น บรรทัด Sight gained ของผู้เล่นเพียงบรรทัดเดียว
7. **ขั้นที่ 3 — ความจำและการไล่ตาม:** ใน Play เดียวกัน เมื่อศัตรูเห็นผู้เล่น ศัตรูต้องหันมาไล่ตามทันทีและหยุดห่างประมาณ 150 เมื่อถึงตัว จากนั้นบังคับตัวละครผู้เล่นให้วิ่งไปหลบหลังกำแพงหรือบล็อกของฉาก ศัตรูต้องเดินไปยังตำแหน่งที่พบล่าสุด หยุดสองวินาที แล้วกลับไปลาดตระเวน ระหว่างไล่ตามกด Apostrophe (`'`) แล้วแป้นตัวเลข 4 เพื่อดูวงกลมสองวงและขอบเขตการมองเห็นในหมวด Perception ของ Gameplay Debugger
8. **ขั้นที่ 4 — การได้ยิน:** Play แล้วบังคับตัวละครผู้เล่นให้เดินไปยืนหลังกำแพงที่ศัตรูมองไม่เห็นภายในระยะ 1500 จากเส้นทางลาดตระเวน รอให้ศัตรูเข้าใกล้ แล้วให้ตัวละครผู้เล่นกระโดดหนึ่งครั้ง (Space) ต้องได้บรรทัด Heard ทันที ตามด้วยบรรทัด Patrol aborted ของบทที่ 8 ศัตรูเดินมายังจุดที่กระโดด หยุดสองวินาที แล้วกลับไปลาดตระเวน

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools (Build Tools for Visual Studio) พร้อมเวิร์กโหลด "Desktop development with C++" และ ".NET desktop build tools" (ขั้นตอนอยู่ในภาคผนวก ก ของงานเขียน)
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch10` บทนี้เพิ่มไฟล์ใหม่หนึ่งคู่ แก้ `EnemyAIController.{h,cpp}`, `EnemyCharacter.h` และ `TargetDummy.{h,cpp}` เฉพาะส่วนที่กำกับว่า "บทที่ 11" (`EnemyCharacter.cpp` ได้เพียงความเห็นหนึ่งบรรทัด) และไม่แตะ `HAPBook.Build.cs` (`IGenericTeamAgentInterface`, `UAIPerceptionComponent`, Sense ทุกชนิด และ `UAIPerceptionStimuliSourceComponent` อยู่ในโมดูล `AIModule` ซึ่งมีอยู่แล้ว) ไฟล์ของ Epic (`HAPBookCharacter.*`) ไม่ถูกแก้ ไม่มีบรรทัดใดใน C++ สร้าง Component AIPerception หรือตั้งค่าของ Sense

## จุดตรวจสอบผลลัพธ์

จุดตรวจสอบมีหนึ่งจุดต่อขั้น (กรอง Output Log ด้วย `[Perception]` แล้ว `[BT]`)

**ขั้นที่ 1 — การมองเห็น:** สองบรรทัดนี้ในลำดับใดก็ได้ (หุ่นตัวแรกอาจเป็น `Dummy_02` หรือ `Dummy_03` ตามทิศที่ศัตรูหันเมื่อเริ่ม) ก่อนกด Play ผู้อ่านควรทำนายว่าศัตรูจะรายงานสิ่งใดบ้างในรอบแรก และจะเดินเข้าหาสิ่งใดหรือไม่ เมื่อผู้เล่นยังไม่มีฝ่าย ศัตรูไม่เดินเข้าหาทั้งผู้เล่นและหุ่น เพราะตัวรับเขียนความรู้เฉพาะเรื่องสิ่งที่เป็น Hostile

```
LogTemp: [Perception] Sight gained: Dummy_01
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
```

**ขั้นที่ 2 — ฝ่ายในฐานะตัวกรอง:** บรรทัด Teams หนึ่งครั้งในวินาทีแรก (Tick ถัดจาก `BeginPlay()` ของ Controller) จากนั้นหุ่นเงียบทั้งรอบ และบรรทัดของผู้เล่นเมื่อตัวละครผู้เล่นเข้าขอบเขตการมองเห็น หากบรรทัด Teams อ่านว่า `player=255 attitude=Neutral` Blueprint ของผู้เล่นยังไม่ได้ Reparent และบรรทัดที่สองจะไม่ปรากฏ

```
LogTemp: [Perception] Teams: enemy=2 player=1 attitude=Hostile
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
```

**ขั้นที่ 3 — ความจำและการไล่ตาม:** สามบรรทัดนี้ตามลำดับ ก่อนให้ตัวละครผู้เล่นหลบ ผู้อ่านควรทำนายว่าศัตรูจะหยุดทันทีที่ตัวละครผู้เล่นหายไป หรือเดินต่อไปที่ใด ไม่มีบรรทัด `Patrol aborted` ระหว่างบรรทัดที่สองกับสาม และไม่มีบรรทัด `[AI] Reached waypoint` ระหว่างการไล่ตาม

```
LogTemp: [Perception] Sight gained: BP_ThirdPersonCharacter_C
LogTemp: [Perception] Sight lost: BP_ThirdPersonCharacter_C -> investigating last known location
LogTemp: [BT] Investigate: reached AlertLocation, Alerted cleared
```

**ขั้นที่ 4 — การได้ยิน:** บรรทัดนี้ทันทีที่ตัวละครผู้เล่นกระโดด ตามด้วย `[BT] Patrol aborted by Observer Aborts (Lower Priority)` และ `[BT] Investigate: reached AlertLocation, Alerted cleared` ของบทที่ 8 เมื่อศัตรูถึงจุดที่กระโดด

```
LogTemp: [Perception] Heard: BP_ThirdPersonCharacter_C -> investigating noise
```

ที่มาของแต่ละบรรทัด

- บรรทัด Sight gained: จาก `OnTargetPerceptionUpdated()` เมื่อ `WasSuccessfullySensed()` จริง Sense Sight สร้าง Query ให้คู่ Listener–แหล่งที่ผ่านตัวกรองฝ่าย (ขั้นที่ 1: ทุกคู่ เพราะทุกสิ่งเป็น Neutral และ Detect Neutrals เลือกไว้; ขั้นที่ 2: เฉพาะคู่ Hostile) ทำ Line Trace สำเร็จ แล้วลงทะเบียนสิ่งเร้า ตัวรับบันทึกบรรทัดนี้สำหรับทุกสิ่ง แล้วเขียน `LastKnownLocation` และ `TargetActor` เฉพาะเมื่อ `GetTeamAttitudeTowards()` ตอบ Hostile ชื่อคือ `DummyName` ของหุ่น หรือชื่อคลาสของ Blueprint (`PerceivedName()`)
- บรรทัด Teams: จาก `LogTeamAttitude()` สามค่าผ่านเส้นทางจริงของเอนจิ้น: `TeamID` ของ Controller, `FGenericTeamId::GetTeamIdentifier(PlayerPawn)` (Cast Pawn เป็น Interface) และ `GetTeamAttitudeTowards(*PlayerPawn)` ซึ่งผ่าน Attitude Solver ของบท
- บรรทัด Sight lost: ฟังก์ชันเดียวกันกับสิ่งเร้า `SensingFailed` ที่ Sight ลงทะเบียนเองเมื่อ Line Trace ล้มเหลว เฉพาะเป้าหมาย Hostile ตัวรับเขียน `LastKnownLocation` และ `AlertLocation` ตั้ง `Alerted` แล้วล้าง `TargetActor` (ลำดับนี้ทำให้ตัวตรวจ Patrol aborted ของบทที่ 8 ไม่พิมพ์ข้อความที่ไม่จริง) สิ่งที่ไม่ใช่ Hostile หายจากสายตาโดยไม่มีบรรทัด
- บรรทัด Investigate: บรรทัดของบทที่ 8 ทุกอักขระ จาก `WasInvestigateArrival()` ใน `OnMoveCompleted()`
- บรรทัด Heard: สาขา Hearing ของฟังก์ชันเดียวกัน Make Noise ของผู้เล่น → `AActor::MakeNoiseDelegate` (ชี้ไปยัง `UAIPerceptionSystem::MakeNoiseImpl` ตั้งแต่ Sense Hearing ตัวแรกของโปรเซสถูกสร้าง) → `FAINoiseEvent` (รหัสฝ่าย 1 ของ Pawn ผู้เล่น) → Sense Hearing ตรวจระยะ 1500 ทั้งสองฝั่ง เทียบฝ่าย 2 กับ 1 ได้ Hostile → สิ่งเร้าที่ตำแหน่งเสียงโดยไม่หน่วง (`SpeedOfSoundSq` = 0) → ตัวรับได้ Hostile อีกครั้งและเขียน `AlertLocation`/`Alerted`

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08`, `L_Ch09` แล้ว `L_Ch10` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ และไม่มีบรรทัด `[Perception]` ใดเลย: ศัตรูในแผนที่เหล่านั้นใช้ `BP_EnemyAIController` เช่นกัน (มี Component AIPerception) แต่ *Perception Enabled* เป็นเท็จ ตอน Possess Controller จึงถอน Listener ออกจากระบบกลาง ไม่มี Query ไม่มี Line Trace และ Branch `Chase` ของ `BT_Enemy` (Asset ร่วม) ไม่เคยถูกเลือกเพราะไม่มีสิ่งใดเขียน `TargetActor` การกระโดดในแผนที่เหล่านั้นก็ไม่มีบรรทัด เพราะไม่มี Listener ที่ลงทะเบียนอยู่ จากนั้นใน `L_Ch11` ตั้ง *Lose Sight Radius* เป็น 1000 ใน `BP_EnemyAIController` (ไม่ต้อง Build) แล้วให้ตัวละครผู้เล่นยืนนิ่งที่ระยะประมาณ 1200 ตรงหน้าศัตรู (แบบฝึกหัดข้อ 6 ของบทที่ 11)

## ปัญหาที่พบบ่อย

- **หาระบบรับรู้ในแผง Details ไม่พบ (ไม่มี Senses Config ให้ตั้ง)** — กำลังดูคลาส C++ `EnemyAIController` ซึ่งไม่มี Component AIPerception ให้เปิด `BP_EnemyAIController` ใน `Content/AI` แล้วเลือก Component `AIPerception` ในแผง Components
- **Output Log มีคำเตือน `Perception Enabled but the controller has no AIPerception component`** — *AI Controller Class* ใน Class Defaults ของ `BP_Enemy` ยังเป็น `EnemyAIController` (คลาส C++) ให้ตั้งเป็น `BP_EnemyAIController` แล้ว Compile และ Save
- **ขั้นที่ 1: ไม่มีบรรทัดใดเลย แม้เดินตรงหน้าศัตรู** — *Perception Enabled* ไม่ได้เลือกที่ `BP_Enemy` ที่วางใน `L_Ch11` (เป็นค่าของอินสแตนซ์ ไม่อยู่ใน Class Defaults; เลือก Actor ในแผนที่แล้วดูหมวด *Perception* ของแผง Details) หรือ *Detect Neutrals* ใน `BP_EnemyAIController` ไม่ได้เลือกในขั้นที่ 1 (ยังไม่มีฝ่าย ทุกสิ่งเป็น Neutral ค่าเริ่มต้น Enemies เท่านั้นจึงมองไม่เห็นสิ่งใด) หรือ *Senses Config* ว่าง (Component ที่ไม่มี Sense ไม่ลงทะเบียนเป็น Listener)
- **ขั้นที่ 1: เห็นผู้เล่นแต่ไม่เห็นหุ่น** — หุ่นไม่ได้ลงทะเบียนเป็นแหล่งสิ่งเร้า: `RegisterForSense` ถูกเรียกใน Constructor (ไม่มี World จึงไม่ทำอะไร) แทน `BeginPlay()` หรือ `StimuliSource` ไม่ถูกสร้าง หุ่นไม่ใช่ Pawn จึงไม่ถูกลงทะเบียนอัตโนมัติ
- **ขั้นที่ 1: ศัตรูหันมาเดินตามผู้เล่น** — ผู้เล่นมีฝ่ายอยู่แล้ว: `BP_ThirdPersonCharacter` ถูก Reparent เป็น `HAPPlayerCharacter` (สถานะของแท็ก `ch11`) ผู้เล่นจึงเป็น Hostile และตัวรับเขียนความรู้ ในขั้นที่ 1 ตามบท ผู้เล่นมีคลาสแม่เป็น `HAPBookCharacter` ตามที่ Template ส่งมา
- **ขั้นที่ 2: ศัตรูไม่สนใจผู้เล่น** — ผู้เล่นยังไม่มีฝ่าย: ยังไม่ได้ Reparent `BP_ThirdPersonCharacter` เป็น `HAPPlayerCharacter` (File → Reparent Blueprint แล้ว Compile และ Save) หรือ *Team Id* ใน Class Defaults ถูกเปลี่ยนเป็น 2 (ฝ่ายเดียวกับศัตรู = Friendly) หรือ 255 (`NoTeam` = Neutral) บรรทัด Teams บอกค่าที่เอนจิ้นเห็น หาก *Detect Neutrals* ยังเลือกไว้ บรรทัด Sight gained ของผู้เล่นจะยังปรากฏ แต่ศัตรูไม่ทำอะไรเพราะผู้เล่นเป็น Neutral การคง Detect Neutrals ไว้ไม่ใช่สาเหตุ สาเหตุคือฝ่าย
- **ขั้นที่ 2 เป็นต้นไป: ยังมีบรรทัด Sight gained ของหุ่น** — *Detect Neutrals* ใน `BP_EnemyAIController` ยังเลือกไว้หลังขั้นที่ 1 พฤติกรรมยังถูกต้อง (ตัวรับเพิกเฉยต่อหุ่นซึ่งเป็น Neutral) แต่ระบบเสีย Query และ Line Trace ให้หุ่น ให้ไม่เลือกแล้ว Compile และ Save (ในแท็ก `ch11` ช่องนี้ไม่ได้เลือก)
- **ขั้นที่ 2: เห็นผู้เล่นแล้วศัตรูยังลาดตระเวนต่อ แต่พอหลบ ศัตรูเดินไปยังตำแหน่งที่พบล่าสุด** — เป็นผลที่คาดเมื่อสร้างตามบทถึงขั้นที่ 2: คีย์ `TargetActor`/`LastKnownLocation` และ Branch `Chase` ยังไม่มี (ขั้นที่ 3) การเขียนคีย์ที่ Blackboard ไม่มีจึงไม่มีผล ส่วนสาขา "หาย" เขียนคีย์ของบทที่ 8 ซึ่ง Branch `Investigate` อ่านอยู่แล้ว
- **บรรทัด Teams ถูกต้องแต่ไม่มีบรรทัด Sight gained แม้ยืนตรงหน้า** — *Detect Enemies* ไม่ได้เลือก หรือผู้เล่นยืนนอกขอบเขตการมองเห็น (ครึ่งมุม 70 องศา: ด้านข้างและด้านหลังของศัตรูมองไม่เห็น) หรืออยู่ไกลกว่า 1500 ให้เปิด Gameplay Debugger (`'` แล้วแป้น 4) ดูขอบเขตการมองเห็นและวงกลม
- **ขอบเขตการมองเห็นใน Gameplay Debugger ชี้ไปด้านหลังศัตรู (หรือไปทางหุ่นที่ผ่านมาแล้ว) ขณะศัตรูเดิน และศัตรูไม่เห็นผู้เล่นที่อยู่ตรงหน้า** — มีจุดสนใจ (Focus) ที่ถูกตั้งแล้วไม่ถูกล้าง Sight มองตาม Control Rotation ของ Controller ซึ่งชี้ไปยังจุดสนใจระดับ `Gameplay` ก่อนทิศเดิน ไม่ใช่ตามทิศที่ร่างหันหน้า ให้ตรวจว่า `UBTTask_FaceTarget` ของบทที่ 9 หมุนร่างโดยตรงโดยไม่เรียก `SetFocus` (ตัวอย่างชุดคำสั่ง Task ของบทที่ 9) และโค้ดหรือ Node อื่นที่ตั้งจุดสนใจล้างจุดสนใจด้วย `ClearFocus(EAIFocusPriority::Gameplay)` เมื่อหมดหน้าที่
- **เห็นแล้ว (มีบรรทัด Sight gained) แต่ไม่ไล่ตาม หรือไล่ตามหลังถึงจุดลาดตระเวนก่อน** — Observer Aborts ของ Decorator บน Branch `Chase` ไม่ใช่ Both (Self เท่านั้น: ต้องรอให้ Branch ที่ทำงานอยู่จบ; None: ไม่ยุติเลย) หรือ Branch `Chase` ไม่ได้อยู่ซ้ายสุดของ Selector หรือคีย์ `TargetActor` ไม่ใช่ชนิด Object ที่มี Base Class Actor (Move To ไม่ยอมรับ) หรือสะกดชื่อคีย์ไม่ตรงกับ `TargetActorKey` (`SetValue` ของ Blackboard คืนเท็จโดยไม่มีคำเตือน) หรือผู้เล่นไม่ใช่ Hostile (ดูบรรทัด Teams)
- **ศัตรูตามทันเสมอ วิ่งหนีอย่างไรก็ไม่พ้น** — ศัตรูเร็วกว่าผู้เล่น: *Max Walk Speed* ของ `BP_Enemy` ยังเป็นค่าเริ่มต้น 600 ขณะที่ผู้เล่นเดินที่ 500 ให้ตั้งเป็น 400 ตามขั้นตอนใน Component CharacterMovement ของสูตรการสร้าง `BP_Enemy` ในบทที่ 7 และหลบหลังบล็อกที่บังแนวสายตา ไม่ใช่วิ่งออกให้ไกล (*Lose Sight Radius* 2000 มากกว่า *Sight Radius* 1500 โดยเจตนา)
- **ไล่ตามตลอดไปแม้หลบหลังกำแพงแล้ว** — ไม่มีการจัดการสิ่งเร้าที่ `WasSuccessfullySensed()` เป็นเท็จ (สาขา "หาย" หายไป) หรือสาขานั้นไม่ได้ล้าง `TargetActor` หรือกำแพงที่ใช้หลบไม่บังแคปซูลทั้งตัว (Line Trace เล็งที่ตำแหน่ง Actor) ให้หลบหลังบล็อกที่สูงกว่าตัวละคร
- **หลบแล้วศัตรูหยุดนิ่งแทนที่จะเดินไปยังตำแหน่งที่พบล่าสุด** — ลำดับการเขียนในสาขา "หาย" ผิด: `AlertLocation` และ `Alerted` ต้องถูกเขียนก่อนล้าง `TargetActor` มิฉะนั้น Selector ค้นหาใหม่ขณะ `Alerted` ยังเท็จ หรือ `BB_Enemy` ไม่มีคีย์ `Alerted`/`AlertLocation` ของบทที่ 8
- **บรรทัด `Patrol aborted by Observer Aborts (Lower Priority)` ปรากฏตอนผู้เล่นหลบในขั้นที่ 3** — `OnAlertedChanged()` ไม่ได้ตรวจว่า `TargetActor` ยังตั้งอยู่ (ตัวตรวจของบทที่ 8 ต้องถูกข้ามขณะไล่ตาม) หรือสาขา "หาย" ล้าง `TargetActor` ก่อนตั้ง `Alerted` (ในขั้นที่ 2 บรรทัดนี้ปรากฏได้และเป็นความจริง เพราะศัตรูลาดตระเวนอยู่)
- **กระโดดแล้วไม่มีบรรทัด Heard** — Make Noise ไม่ได้ต่อจาก Event On Jumped (หรือ Compile ไม่ผ่าน) หรือระยะเกิน 1500 (ทั้ง *Hearing Range* ของ Listener และ *Max Range* ของเสียง) หรือ *Senses Config* ของ `BP_EnemyAIController` ไม่มี AI Hearing config หรือผู้เล่นไม่ใช่ Hostile
- **ได้ยินแล้วแต่ศัตรูไล่ตามแทนที่จะเดินไปตรวจสอบ** — เป็นผลที่คาดเมื่อศัตรูมองเห็นผู้เล่นระหว่างเดินมา: Branch `Chase` สำคัญกว่า `Investigate` ให้ยืนหลังกำแพงต่อไปจนศัตรูถึงจุดที่กระโดด
- **กระโดดครั้งที่สองขณะศัตรูกำลังเดินมาตรวจสอบครั้งแรก ศัตรูไม่เปลี่ยนจุดหมาย** — เป็นผลที่คาด: Move To ของ Branch `Investigate` ไม่ได้ตั้ง *Observe Blackboard Value* จึงเดินไปยังค่าที่อ่านตอนเริ่ม `AlertLocation` ใหม่มีผลในการค้นหาครั้งถัดไป
- **Gameplay Debugger ไม่แสดงขอบเขตการมองเห็นและวงกลม** — กดแป้นตัวเลข 4 (หมวด Perception) ไม่ใช่ 1–3 กล้องต้องมองเห็นศัตรูขณะกด `'` และ Controller ของศัตรูต้องเป็น `BP_EnemyAIController` หมวดนี้อยู่ที่ 4 เพราะเอนจิ้นจองช่อง 0–2 ให้ Navmesh, AI และ Behavior Tree และจัดช่องที่เหลือตามลำดับอักษร (EQS 3, Perception 4); หากโปรเจกต์มีหมวดเพิ่ม ให้อ่านหมายเลขจากแถบหัวของ Debugger
- **ศัตรูใน `L_Ch07`–`L_Ch10` เริ่มไล่ตามผู้เล่น** — *Perception Enabled* ถูกเลือกใน Class Defaults ของ `BP_Enemy` แทนอินสแตนซ์ที่วางใน `L_Ch11` (ทำได้เฉพาะเมื่อคุณสมบัติถูกเปลี่ยนจาก `EditInstanceOnly` เป็น `EditAnywhere` หรือ `EditDefaultsOnly`) ค่าของคลาสมีผลกับ `BP_Enemy` ทุกตัวในทุกแผนที่ ให้คืนเป็น `EditInstanceOnly` แล้วเลือกเฉพาะอินสแตนซ์ใน `L_Ch11` การเปิดต่ออินสแตนซ์คือสิ่งที่ทำให้แผนที่ก่อนหน้าไม่เปลี่ยน
- **ศัตรูถึงตัวผู้เล่นแล้วบรรทัด `[AI] Reached waypoint` เลื่อนไป** — `WasChaseArrival()` ไม่ถูกตรวจก่อนการเลื่อนดัชนีใน `OnMoveCompleted()` (Move To ของ Branch `Chase` ที่สำเร็จต้องไม่นับเป็นการถึงจุดลาดตระเวน)
- **สองบรรทัด Sight gained/lost สลับกันซ้ำทุกรอบขณะผู้เล่นยืนนิ่ง** — *Lose Sight Radius* เล็กกว่า *Sight Radius* ใน `BP_EnemyAIController` (แบบฝึกหัดข้อ 6) หรือผู้เล่นยืนบนขอบของสิ่งกีดขวางที่ Line Trace บังเป็นบางเฟรม
