# บทที่ 10 — สถาปัตยกรรมตัวละครและระบบความเสียหาย

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 10 คือแท็ก `ch10` บทนี้ให้ร่างของศัตรูและของผู้เล่นบาดเจ็บได้ด้วย Component เดียวกัน: `UHealthComponent` (C++) ถือ `MaxHealth`/`CurrentHealth` ผูก `OnTakeAnyDamage` ของเจ้าของใน `BeginPlay()` แล้วส่งต่อเป็น Delegate `OnHealthChanged`/`OnDeath` ที่ Blueprint ผูกได้ ความเสียหายมาจาก `BP_HazardZone` ในฉากซึ่งเรียก Apply Damage 25 ชนิด `DamageType_Hazard` กับ Actor ใดก็ตามที่เข้าเขต (ไม่ Cast) ศัตรูที่พลังชีวิตถึงศูนย์หยุด Behavior Tree ปิดการชนและการเคลื่อนที่ แล้วถูกทำลายใน 3 วินาที ส่วน `BP_ThirdPersonCharacter` ของ Template ได้รับ Component เดียวกันผ่าน Add Component (Max Health 200) และแสดงพลังชีวิตบนหน้าจอจาก Event Graph ในแผนที่ `L_Ch10` ซึ่งเป็นสำเนาของ `L_Ch09`

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch10` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch10.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch10` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solutionด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch10` ซึ่งมี `BP_Enemy` หนึ่งตัวกับ TargetPoint ลาดตระเวนสามจุด, หุ่น `Dummy_01`–`Dummy_03`, `BP_AlertZone`, `EnemySpawner` (*Spawn Count* 0) ของบทก่อน และ `BP_HazardZone` คร่อมเส้นทางลาดตระเวนระหว่าง TargetPoint สองจุด เมื่อกด Play ตัวละครผู้เล่นของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับตัวละครผู้เล่นเดินสำรวจฉากได้ระหว่างนั้น

บทนี้สร้างเป็นสี่ขั้น แท็ก `ch10` คือสถานะหลังขั้นที่ 4 การเล่นแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — Component บนศัตรู:** กด Play เปิด *Window → Output Log* พิมพ์ `[Damage]` ในช่องกรอง ต้องได้บรรทัด ready ของ `BP_Enemy_C` หนึ่งบรรทัด (และของ `BP_ThirdPersonCharacter_C` อีกหนึ่ง เพราะแท็กนี้ผ่านขั้นที่ 4 แล้ว) ศัตรู (AI) ลาดตระเวนตามเดิม
6. **ขั้นที่ 2 — ความเสียหายจากโลกของเกม:** ใน Play เดียวกัน มองที่ศัตรูซึ่งเดินผ่านกล่องของ `BP_HazardZone` ทุกครั้งที่ศัตรูเข้าเขตต้องมีบรรทัด took หนึ่งบรรทัด พลังชีวิตลด 100 → 75 → 50 → 25 รอบละหนึ่งบรรทัด พฤติกรรมของศัตรูไม่เปลี่ยน
7. **ขั้นที่ 3 — การตาย:** ในรอบที่สี่ ศัตรูหยุดกลางเขตทันที มีบรรทัด `0.00/100.00` ตามด้วย died ร่างหยุดนิ่งสามวินาทีแล้วหายไป ไม่มีบรรทัด `[AI]` หรือ `[Nodes]` ใดเพิ่มหลังจากนั้น
8. **ขั้นที่ 4 — ผู้เล่น:** เริ่ม Play ใหม่ แล้วบังคับตัวละครผู้เล่น (Player) ให้เดินเข้ากล่องของ `BP_HazardZone` หนึ่งครั้ง มุมซ้ายบนต้องแสดง `Health 175.0/200.0` สองวินาที และ Output Log ต้องมีบรรทัด took ของ `BP_ThirdPersonCharacter_C`

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)

- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch09` บทนี้เพิ่มไฟล์ใหม่สองคู่ แก้ `EnemyCharacter.{h,cpp}` เฉพาะส่วนที่กำกับว่า "บทที่ 10" และไม่แตะ `EnemyAIController.*`, Node ของบทที่ 9 หรือ `HAPBook.Build.cs` (`UActorComponent` และ `UDamageType` อยู่ในโมดูล `Engine`; `UBrainComponent` อยู่ใน `AIModule` ซึ่งมีอยู่แล้ว)

## จุดตรวจสอบผลลัพธ์

จุดตรวจสอบมีหนึ่งจุดต่อขั้น (กรอง Output Log ด้วย `[Damage]`)

**ขั้นที่ 1 — Component บนศัตรู:** บรรทัดนี้หนึ่งครั้ง หลังบรรทัด `[AI] Possessed ...` ของบทที่ 7 (Controller ถูกสร้างใน `PostInitializeComponents()` ก่อน `BeginPlay()` ของ Component)

```
LogTemp: [Damage] BP_Enemy_C health 100/100 (ready)
```

**ขั้นที่ 2 — ความเสียหายจากโลกของเกม:** ก่อนกด Play ผู้อ่านควรทำนายค่าในบรรทัดที่สาม และสิ่งที่จะเกิดในรอบที่สี่ สามบรรทัดนี้ห่างกันหนึ่งรอบการลาดตระเวน

```
LogTemp: [Damage] BP_Enemy_C took 25.00 (Hazard) -> 75.00/100.00
LogTemp: [Damage] BP_Enemy_C took 25.00 (Hazard) -> 50.00/100.00
LogTemp: [Damage] BP_Enemy_C took 25.00 (Hazard) -> 25.00/100.00
```

**ขั้นที่ 3 — การตาย:** ในรอบที่สี่ สองบรรทัดนี้ติดกัน ศัตรูหยุดกลางเขต ตัวละครผู้เล่นเดินทะลุร่างได้ และร่างหายไปหลังสามวินาที

```
LogTemp: [Damage] BP_Enemy_C took 25.00 (Hazard) -> 0.00/100.00
LogTemp: [Damage] BP_Enemy_C died
```

**ขั้นที่ 4 — ผู้เล่น:** บรรทัด `[Damage] BP_ThirdPersonCharacter_C health 200/200 (ready)` ตอนเริ่ม และเมื่อตัวละครผู้เล่นเดินเข้าเขตเอง บรรทัดนี้พร้อมข้อความ `Health 175.0/200.0` ที่มุมซ้ายบน

```
LogTemp: [Damage] BP_ThirdPersonCharacter_C took 25.00 (Hazard) -> 175.00/200.00
```

ที่มาของแต่ละบรรทัด

- บรรทัด ready: จาก `BeginPlay()` ของ Component หลังผูก `OnTakeAnyDamage` ของเจ้าของ จำนวนเต็มเพราะยังไม่มีการคำนวณ
- บรรทัด took: จาก `HandleTakeAnyDamage()` เส้นทางคือ Apply Damage (Blueprint ของเขต) → `UGameplayStatics::ApplyDamage` → `APawn::TakeDamage` (`ShouldTakeDamage` ผ่าน) → `AActor::TakeDamage` → `OnTakeAnyDamage.Broadcast` → Component `Hazard` คือชื่อคลาส `DamageType_Hazard` ตัดคำนำหน้า
- บรรทัด died: จากฟังก์ชันเดียวกันก่อน `OnDeath.Broadcast()` ลำดับการตายใน `HandleDeath()` ของศัตรูไม่บันทึกบรรทัดใด
- บรรทัดของผู้เล่น: ฟังก์ชันเดียวกัน เจ้าของต่างกัน ค่า 200 มาจาก Class Defaults ของ Blueprint ข้อความบนหน้าจอมาจาก Event Graph ที่รับ `OnHealthChanged`

การทดลองเพิ่มเติม: เปิด `L_Ch07`, `L_Ch08` แล้ว `L_Ch09` แล้ว Play ทีละแผนที่ ต้องได้บรรทัดเดิมของบทนั้นทุกอักขระ บวกบรรทัด ready หนึ่งบรรทัดต่อศัตรูหนึ่งตัว (และของผู้เล่นหนึ่งบรรทัด) และไม่มีบรรทัด took ใด เพราะ Component ถูกสร้างใน Constructor ของ `AEnemyCharacter` ที่ทุกแผนที่ใช้ร่วมกัน แต่ไม่มี `BP_HazardZone` ในแผนที่เหล่านั้น จากนั้นใน `L_Ch10` ตั้ง *Base Damage* ของ `BP_HazardZone` เป็น 40 แล้ว Play ใหม่ (แบบฝึกหัดข้อ 4 ของบทที่ 10)

## ปัญหาที่พบบ่อย

- **ศัตรูเดินผ่านเขตแล้วไม่มีบรรทัด took และพลังชีวิตไม่ลด** — *Can Be Damaged* ของ `BP_Enemy` (แผง Details หมวด Actor) ไม่ได้เลือก (`APawn::ShouldTakeDamage` ปฏิเสธก่อนถึง Component) หรือ Box Collision ของ `BP_HazardZone` ไม่สร้าง Event ทับซ้อน: *Generate Overlap Events* ต้องกา และ *Collision Presets* ต้องทับซ้อนกับ Pawn ได้ (`OverlapAllDynamic`) หากกราฟมี Cast ก่อน Apply Damage ให้ลบออก (บทนี้ส่ง Other Actor เข้า Apply Damage โดยตรง)
- **มีบรรทัด ready แต่พลังชีวิตไม่เคยเปลี่ยน แม้เขตทำงาน** — `OnTakeAnyDamage` ถูกผูกใน Constructor ของ Component แทน `BeginPlay()` (ผูกกับ CDO หรือ Actor ที่ยังสร้างไม่เสร็จ) หรือผู้อ่านเขียนทับ `TakeDamage` ในคลาสเจ้าของโดยไม่เรียก `Super::TakeDamage` (ท่อถูกตัดก่อน Broadcast — แบบฝึกหัดข้อ 6) หรือ Component ไม่ได้แนบกับ Actor ที่วางในแผนที่ (ตรวจแผง Components ของ `BP_Enemy`: ต้องเห็น `Health Component (HealthComponent)` พร้อมป้าย *Edit in C++*)
- **ศัตรูตายแล้ว (มีบรรทัด died) แต่ยังเดินลาดตระเวนต่อ** — `StopLogic()` ไม่ถูกเรียก: `HandleDeath()` ไม่ได้ผูกกับ `OnDeath` (ลืม `AddDynamic` ใน `BeginPlay()` หรือ `HandleDeath` ไม่ใช่ `UFUNCTION()` ซึ่ง `AddDynamic` ต้องการ) หรือ `GetController()` เป็นค่าว่าง ณ เวลานั้น
- **ผู้เล่นเดินเข้าเขตแล้วมีบรรทัด took ของ `BP_ThirdPersonCharacter_C` แต่ไม่มีข้อความบนหน้าจอ** — Event *On Health Changed* ไม่ได้ผูกใน `BP_ThirdPersonCharacter` (ต้องกด + ที่หมวด Events ในแผง Details ของ Component `Health` ที่เพิ่มแล้ว ไม่ใช่ Bind Event กับตัวแปรเปล่า) หรือ Print String ต่อจาก Event อื่น
- **ผู้เล่นตายแล้ว (มีบรรทัด `BP_ThirdPersonCharacter_C died`) แต่ยังเดินได้** — เป็นผลที่คาด: `BP_ThirdPersonCharacter` ไม่มี Event ใดผูกกับ `OnDeath` Component ส่งสัญญาณและหยุดรับความเสียหาย (การเข้าเขตครั้งต่อไปไม่มีบรรทัด took) แต่ความหมายของการตายเป็นของเจ้าของ ศัตรูกำหนดใน C++ ส่วนผู้เล่นยังไม่มีผู้กำหนด ดูแบบฝึกหัดข้อ 8 ของบทที่ 10
- **ชื่อ Component ของผู้เล่นเป็น `Health` ไม่ใช่ `HealthComponent`** — เป็นผลที่คาด: Editor ตัดคำว่า Component ท้ายชื่อคลาสเมื่อตั้งชื่อ Component ที่เพิ่มด้วย *Add* Event จึงชื่อ *On Health Changed (Health)* ฝั่งศัตรูชื่อ `HealthComponent` เพราะ Constructor ของ C++ ตั้งชื่อนั้นเอง
- **ผู้เล่นเดินเข้าเขตแล้วไม่มีบรรทัดใดของผู้เล่นเลย** — ยังไม่ได้ Add Component ใน `BP_ThirdPersonCharacter` (ท่อทำงาน แต่ Broadcast ไปยังตัวรับฟังของ `OnTakeAnyDamage` ศูนย์ราย) หรือ *Add* ไม่มี `Health Component` ให้เลือก เพราะ `UCLASS` ขาด `meta = (BlueprintSpawnableComponent)` ให้เพิ่มแล้ว Build ใหม่
- **บรรทัด took แสดง `(DamageType)` แทน `(Hazard)`** — *Damage Type Class* ของ Node Apply Damage ยังเป็นค่าว่าง (เอนจิ้นใช้ `UDamageType` พื้นฐานแทน) ให้เลือก `DamageType_Hazard`
- **ศัตรูได้รับความเสียหายสองครั้งต่อการเข้าเขตหนึ่งครั้ง** — Skeletal Mesh ของ `BP_Enemy` ถูกตั้ง *Generate Overlap Events* (ค่าเริ่มต้นของ `ACharacter` คือปิด) หรือมี Component การชนเพิ่มในเขต ให้คงเฉพาะแคปซูลที่สร้าง Event
- **หลังศัตรูตาย เดินเข้า `BP_AlertZone` แล้วมีคำเตือน Accessed None** — เป็นผลที่คาด: ตัวแปร `Enemy` ของเขตสัญญาณเตือนชี้ Actor ที่ถูกทำลายแล้ว เริ่ม Play ใหม่หากต้องการทดสอบบทที่ 8 ต่อ
- **Component ปรากฏในแผง Details แต่ Current Health เป็น 0.0 ใน Editor** — เป็นผลที่คาด: ค่าถูกตั้งเป็น Max Health ใน `BeginPlay()` เท่านั้น ดูค่าระหว่าง Play ได้โดยเลือก Actor ในแผง Outliner ของ PIE
