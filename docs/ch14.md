# บทที่ 14 — การวิเคราะห์และประเมินผลประสิทธิภาพเชิงปริมาณ

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 14 คือแท็ก `ch14` โปรเจกต์ประกอบของบทนี้คือชุดทดสอบ (Testbed) ของการทดลองแบบควบคุมที่เปรียบเทียบสามสถาปัตยกรรมภายใต้ภาระงานเดียวกัน ฝั่ง C++ มีคลาสใหม่สามคลาส ได้แก่ คลาสฐาน `ABenchmarkActorBase` (Actor ที่ไม่มี Mesh ถือภาระงานร่วม `RunWork()` และผล `Result`; `Tick()` ว่างโดยเจตนา) สถาปัตยกรรมแบบ B `ABenchmarkActorCpp` (Pure C++: `Tick()` เรียก `RunWork()`) และ `ABenchmarkSpawner` (Spawn (สร้างขึ้นในฉาก) Actor ทดสอบ N ตัวเป็นตาราง เขียนค่า I ให้ทุกตัว รับค่าจากบรรทัดคำสั่ง และจับเวลาการวัดด้วย CSV Profiler) ฝั่ง Blueprint มีแบบ A `BP_Arm_A` (Pure Blueprint) และแบบ C `BP_Arm_C` (Hybrid) ใน `Content/Blueprints` แผนที่ `L_Ch14` เป็นสำเนาของ `L_Book` และ `Config/DefaultEngine.ini` ตั้งเกณฑ์ของกลไกป้องกันลูปของ Blueprint ไว้ที่ 10000000 คลาส Asset และแผนที่ของบทที่ 7–13 ไม่เปลี่ยน รวมทั้ง `AEnemySpawner` ของบทที่ 9

## เริ่มต้น

โปรเจกต์ประกอบเก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch14` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch14.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch14` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์โซลูชันด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch14` ซึ่งมี `BenchmarkSpawner` หนึ่งตัววางไว้กลางพื้น (*Arm Class* = `BP_Arm_A`, *Count* 100, *Iterations* 1000, *Auto Capture* ไม่ได้เลือก) แผนที่นี้ไม่มีตัวละครผู้เล่น: *GameMode Override* ใน World Settings เป็น `GameModeBase` เมื่อกด Play ผลลัพธ์ของบทอยู่ใน Output Log

บทนี้สร้างเป็นสี่ขั้น แท็ก `ch14` คือสถานะหลังขั้นที่ 4 การทดลองแต่ละขั้นทำดังนี้

5. **ขั้นที่ 1 — คลาสฐาน แบบ B และ Spawner:** เลือก `BenchmarkSpawner` ในแผง Outliner ตั้ง *Arm Class* เป็น `BenchmarkActorCpp` กด Play แล้วกด Shift+F1 เพื่อปล่อยเคอร์เซอร์ เลือก Actor `BenchmarkActorCpp` หนึ่งตัวใน Outliner แล้วอ่านค่า *Result* ในแผง Details หมวด *Benchmark*
6. **ขั้นที่ 2 — แบบ C:** ตั้ง *Arm Class* เป็น `BP_Arm_C` กด Play แล้วอ่านค่า *Result* ของ Actor `BP_Arm_C` หนึ่งตัวแบบเดียวกัน
7. **ขั้นที่ 3 — แบบ A:** ตั้ง *Arm Class* เป็น `BP_Arm_A` กด Play แล้วอ่านค่า *Result* ของ Actor `BP_Arm_A` หนึ่งตัวแบบเดียวกัน อัตราเฟรมลดลงชัดเจนเมื่อเทียบกับสองขั้นก่อน
8. **ขั้นที่ 4 — การวัดหนึ่งเซลล์:** ปิด Unreal Editor เปิด Command Prompt ที่โฟลเดอร์ `HAPBook` แล้วพิมพ์คำสั่งในตัวอย่างชุดคำสั่งที่ 14.8 ของบท (เปลี่ยนค่า `UEBIN` หาก Unreal Engine ติดตั้งไว้ที่อื่น) รอโดยไม่แตะเมาส์และแป้นพิมพ์จนหน้าต่างของเกมปิดเอง แล้วเปิดโฟลเดอร์ `Saved/Profiling/CSV` และไฟล์ `Saved/Logs/HAPBook.log`

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools ตามองค์ประกอบใน `HAPBook/.vsconfig` (เวิร์กโหลด "Desktop development with C++" และ "Game development with C++")
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)
- โปรแกรมตารางคำนวณสำหรับเปิดไฟล์ CSV ของขั้นที่ 4

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch13` บทนี้เพิ่มไฟล์ใหม่สามคู่ Asset ของ Blueprint สองตัว แผนที่หนึ่งแผนที่ และหนึ่งบรรทัดใน `Config/DefaultEngine.ini` ไม่แตะ `HAPBook.Build.cs` (ทุกคลาสและฟังก์ชันที่ใช้อยู่ในโมดูล `Core`, `CoreUObject` และ `Engine`)

## จุดตรวจสอบผลลัพธ์

**ขั้นที่ 1 — คลาสฐาน แบบ B และ Spawner:** บรรทัดนี้หนึ่งบรรทัดเมื่อกด Play (กรอง Output Log ด้วย `[Bench]`) ค่า *Result* ของ Actor ที่เลือกเท่ากับ 1998.0 และฉากไม่มีตัวละครผู้เล่นของ Template

```
LogTemp: [Bench] Spawned 100 x BenchmarkActorCpp with 1000 iterations
```

- บรรทัด `[Bench]`: จาก `BeginPlay()` ของ `ABenchmarkSpawner` หลัง `SpawnGrid()` คืนจำนวนที่สร้างได้ ชื่อคลาสของแบบ B เป็นชื่อคลาส C++ ที่ไม่มีอักษร `A` นำหน้า
- ค่า 1998.0 = 2 × (1000 − 1): รอบที่ i = 0 ให้เวกเตอร์ศูนย์ ทุกรอบที่เหลือให้เวกเตอร์หนึ่งหน่วยทิศเดียวกันคูณ 2

**ขั้นที่ 2 — แบบ C:** บรรทัดนี้หนึ่งบรรทัด และค่า *Result* เท่ากับ 1998.0 ตรงกับแบบ B

```
LogTemp: [Bench] Spawned 100 x BP_Arm_C_C with 1000 iterations
```

- ชื่อคลาสของ Blueprint ที่คอมไพล์แล้วมีคำต่อท้าย `_C`

**ขั้นที่ 3 — แบบ A:** บรรทัดนี้หนึ่งบรรทัด ไม่มีคำเตือน `Runaway loop detected` และค่า *Result* เท่ากับ 1998.0 ตรงกับแบบ B และแบบ C ก่อนกด Play ผู้อ่านควรทำนายว่าอัตราเฟรมของแบบนี้ต่างจากสองแบบก่อนอย่างไร

```
LogTemp: [Bench] Spawned 100 x BP_Arm_A_C with 1000 iterations
```

**ขั้นที่ 4 — การวัดหนึ่งเซลล์:** หน้าต่างของเกมแสดงพื้นที่ไม่มีแสงเงาและไม่มีตัวละคร แล้วปิดเองราว 70 วินาทีหลังเปิด โฟลเดอร์ `Saved/Profiling/CSV` มีไฟล์หนึ่งไฟล์ที่ชื่อขึ้นต้นด้วย `Bench_BenchmarkActorCpp_N25_I1000` ซึ่งมีคอลัมน์ `GameThreadTime` และไฟล์ `Saved/Logs/HAPBook.log` มีบรรทัดนี้ (ในไฟล์มีเวลานำหน้า) ตามด้วยบรรทัด `Capture Ended` ของ CSV Profiler

```
LogTemp: [Bench] Spawned 25 x BenchmarkActorCpp with 1000 iterations
```

- ค่า 25 และ 1000 มาจาก `-BenchN=` และ `-BenchI=` ของบรรทัดคำสั่ง ไม่ใช่จากค่าที่บันทึกไว้ในแผนที่ (100 และ 1000)
- แถวแรกของไฟล์ CSV เป็นชื่อคอลัมน์ ถัดมาเป็นหนึ่งแถวต่อหนึ่งเฟรม ท้ายไฟล์มีแถวชื่อคอลัมน์ซ้ำและแถวข้อมูลประกอบซึ่งรวมบรรทัดคำสั่งที่ใช้เปิดโปรแกรม

## ปัญหาที่พบบ่อย

- **ทั้งสามแบบให้เวลาใกล้เคียงกันมาก** — `Tick()` ของคลาสฐานเรียก `RunWork()` (กล่องคำเตือนของหัวข้อ "สถาปัตยกรรมสามรูปแบบ") ทุกแบบจึงรันภาระงานใน C++ และแบบ Blueprint รันซ้ำอีกรอบ ให้คืน `Tick()` ของคลาสฐานเป็นตัวอย่างชุดคำสั่งที่ 14.3
- **แบบ A หรือแบบ C เร็วกว่าแบบ B และค่า *Result* เป็น 0.0** — Event Tick ไม่ทำงาน: `Tick()` ของคลาสฐานไม่ได้เรียก `Super::Tick()` หรือ Node *Event Tick* ในกราฟยังเป็น Node สีจางที่ปิดใช้งาน (ยังไม่ได้ลากสายออกจากพิน Exec)
- **ค่า *Result* ของแบบ A เป็น 2000.0** — *Last Index* ของ For Loop เป็น `Iterations` ไม่ใช่ `Iterations` ลบ 1 (For Loop ของ Blueprint รวมค่าปลาย ลูปจึงทำงานเกินหนึ่งรอบ)
- **ค่า *Result* ของแบบ A เพิ่มขึ้นทุกเฟรม** — `AccSoFar` ถูกสร้างเป็นตัวแปรสมาชิกใน *Variables* แทนตัวแปรเฉพาะที่ใน *Local Variables* ของ `RunWorkBP` ค่าจึงสะสมข้ามเฟรม
- **หา `Iterations` หรือ `Result` ในแผง My Blueprint ไม่พบ** — ทั้งสองเป็นสมาชิกที่สืบทอดจาก C++ ให้เปิด *Show Inherited Variables* ในตัวเลือกของแผง หรือคลิกขวาในกราฟแล้วพิมพ์ชื่อ
- **บรรทัด `[Bench] Arm Class not set, nothing spawned`** — *Arm Class* ของ Spawner ว่าง หรือค่า `-BenchArm=` ในบรรทัดคำสั่งชี้คลาสที่ไม่มี เส้นทางของคลาส Blueprint ต้องลงท้ายด้วย `_C` (เช่น `/Game/Blueprints/BP_Arm_A.BP_Arm_A_C`) ส่วนแบบ B คือ `/Script/HAPBook.BenchmarkActorCpp`
- **`BenchmarkActorBase` ไม่อยู่ในรายการของ *Arm Class*** — เป็นการออกแบบ: คลาสฐานเป็น `Abstract` ให้เลือกคลาสลูกใดคลาสหนึ่งในสามแบบ
- **ไม่พบ `BenchmarkSpawner` ในแผง Place Actors หรือ `BenchmarkActorBase` ในรายการคลาสฐาน** — ยังไม่ได้ Build หลังเพิ่มไฟล์ หรือเปิด Unreal Editor ค้างไว้ระหว่าง Build ให้ปิด Editor แล้ว Build ใหม่ คลาสใหม่ต้องการการเปิด Editor ใหม่
- **คำเตือน `Runaway loop detected (over 1,000,000 iterations)` ขณะวัดแบบ A** — เกณฑ์ *Maximum Loop Iteration Count* ยังเป็นค่าเริ่มต้น ให้ตั้งเป็น 10000000 ตามขั้นที่ 3 ข้อ 5 ของบท (ค่านี้อยู่ใน `Config/DefaultEngine.ini`) ตัวนับของกลไกนี้รีเซ็ตครั้งเดียวต่อเฟรม Actor ทุกตัวของแบบ A จึงใช้ตัวนับเดียวกัน
- **ตัวละครผู้เล่นของ Template ปรากฏใน `L_Ch14`** — *GameMode Override* ใน World Settings ยังว่าง ให้ตั้งเป็น `GameModeBase`
- **หน้าต่างของเกมไม่ปิดเอง และไม่มีไฟล์ CSV** — บรรทัดคำสั่งขาด `-BenchAutoCapture` (Spawner จึงไม่ส่ง `csvprofile start`) หากมีไฟล์ CSV แต่หน้าต่างไม่ปิด บรรทัดคำสั่งขาด `-ExitAfterCsvProfiling`
- **ไฟล์ CSV ชื่อ `Profile(...).csv` แทน `Bench_...`** — การบันทึกถูกเริ่มด้วยการพิมพ์ `csvprofile start` เอง ไม่ใช่โดย Spawner ไฟล์นั้นไม่มีชื่อเซลล์ ให้ตรวจเซลล์จากแถวข้อมูลประกอบท้ายไฟล์
- **รอบแรกหลัง Build ใช้เวลาเปิดนานและค่าในไฟล์ CSV กระโดดสูงบางช่วง** — การเปิดครั้งแรกด้วย `-game` คอมไพล์ Shader ของ Content ที่ยังไม่ Cook ให้เปิดหนึ่งรอบที่ไม่นับผลก่อนเริ่มวัด
- **ค่าที่วัดได้สูงและแกว่งกว่ารอบอื่น** — Unreal Editor หรือโปรแกรมอื่นยังเปิดอยู่ระหว่างวัด หรือมีการแตะเมาส์และแป้นพิมพ์ระหว่างรอบ ให้วัดรอบนั้นใหม่
