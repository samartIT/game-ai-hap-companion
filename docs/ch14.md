# บทที่ 14 — การวิเคราะห์และประเมินผลประสิทธิภาพเชิงปริมาณ

สถานะของโปรเจกต์เมื่อสิ้นสุดบทที่ 14 คือแท็ก `ch14` ส่วนของบทนี้ในชุดโค้ดประกอบ (Companion) คือชุดทดสอบ (Testbed) ของการทดลองแบบควบคุมที่เปรียบเทียบสามสถาปัตยกรรมภายใต้ภาระงานเดียวกัน ฝั่ง C++ มีคลาสใหม่สามคลาส ได้แก่ คลาสฐาน `ABenchmarkActorBase` (Actor ที่ไม่มี Mesh ถือภาระงานร่วม `RunWork()` และผล `Result`; `Tick()` ว่างโดยเจตนา) สถาปัตยกรรม C++ ล้วน `ABenchmarkActorCpp` (Pure C++: `Tick()` เรียก `RunWork()`) และ `ABenchmarkSpawner` (Spawn (สร้างขึ้นในฉาก) Actor ทดสอบ N ตัวเป็นตาราง เขียนค่า I ให้ทุกตัว รับค่าจากบรรทัดคำสั่ง และจับเวลาการวัดด้วย CSV Profiler) ฝั่ง Blueprint มี Blueprint ล้วน `BP_Arm_PureBP` (Pure Blueprint) และแบบผสม `BP_Arm_Hybrid` (Hybrid) ใน `Content/Blueprints` แผนที่ `L_Ch14` เป็นสำเนาของ `L_Book` และ `Config/DefaultEngine.ini` ตั้งเกณฑ์ของกลไกป้องกันลูปของ Blueprint ไว้ที่ 10000000 โฟลเดอร์ `Tools/` มีสคริปต์สองไฟล์สำหรับทางเลือกที่ 2: `ch14_run_all.bat` วัดครบ 54 รอบ และ `ch14_reduce.py` ลดทอนไฟล์ CSV ทั้งชุดตามระเบียบวิธีของบท คลาส Asset และแผนที่ของบทที่ 7–13 ไม่เปลี่ยน รวมทั้ง `AEnemySpawner` ของบทที่ 9

ชุดทดสอบใช้ได้สองทาง ทางเลือกที่ 1 คือสังเกตผลใน Editor (ขั้นที่ 1–3 ใช้เวลาไม่กี่นาที) ทางเลือกที่ 2 คือวัดภายใต้การควบคุมตามระเบียบวิธีที่ตารางของบทมาจาก (ขั้นที่ 4 ราว 80 นาที ไม่บังคับ) ทางเลือกที่ 1 แสดงให้เห็นผล ทางเลือกที่ 2 แสดงว่าผลนั้นมีขนาดเท่าใดและแน่นอนเพียงใด

## เริ่มต้น

ชุดโค้ดประกอบเก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ zip ของแท็ก `ch14` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้างไฟล์นี้ให้อัตโนมัติ ชื่อไฟล์เป็น `<ชื่อ repository>-ch14.zip` แล้วแตกไฟล์ (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch14` แล้วใช้โฟลเดอร์ `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือกไฟล์ `companion/HAPBook/HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solutionด้วย Rider
3. สั่ง Build (เมนู *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch14` ซึ่งมี `BenchmarkSpawner` หนึ่งตัววางไว้กลางพื้น (*Arm Class* = `BP_Arm_PureBP`, *Count* 100, *Iterations* 1000, *Auto Capture* ไม่ได้เลือก) แผนที่นี้ไม่มีตัวละครผู้เล่น: *GameMode Override* ใน World Settings เป็น `GameModeBase` เมื่อกด Play ผลลัพธ์ของบทอยู่ใน Output Log

**ทางเลือกที่ 1 — สังเกตผลใน Editor (ขั้นที่ 1–3).** ทุกขั้นใช้ Spawner ที่ N = 100, I = 1,000 และอ่านสองค่า คือเวลาของ Game Thread และค่า *Result*

5. **ขั้นที่ 1 — คลาสฐาน C++ ล้วน และ Spawner:** เลือก `BenchmarkSpawner` ในแผง Outliner ตั้ง *Arm Class* เป็น `BenchmarkActorCpp` เปิด *Window → Output Log* พิมพ์ `[Bench]` ในช่องค้นหา แล้วกด Play กดแป้น `` ` `` (แป้นทางซ้ายของเลข 1) เพื่อเปิดคอนโซล พิมพ์ `stat unit` แล้วกด Enter รอราว 5 วินาทีแล้วอ่านค่าบรรทัด *Game* จากนั้นกด Shift+F1 เพื่อปล่อยเคอร์เซอร์ เลือก Actor `BenchmarkActorCpp` หนึ่งตัวใน Outliner แล้วอ่านค่า *Result* ในแผง Details หมวด *Benchmark*
6. **ขั้นที่ 2 — แบบผสม:** ตั้ง *Arm Class* เป็น `BP_Arm_Hybrid` กด Play แล้วอ่านค่า *Game* และค่า *Result* ของ Actor `BP_Arm_Hybrid` หนึ่งตัวแบบเดียวกัน
7. **ขั้นที่ 3 — Blueprint ล้วน:** ตั้ง *Arm Class* เป็น `BP_Arm_PureBP` กด Play แล้วอ่านค่า *Game* และค่า *Result* ของ Actor `BP_Arm_PureBP` หนึ่งตัวแบบเดียวกัน

**ทางเลือกที่ 2 — วัดภายใต้การควบคุม (ขั้นที่ 4, ไม่บังคับ).** ผู้อ่านหยุดหลังขั้นที่ 3 ได้ ทางเลือกนี้มีไว้สำหรับสร้างตารางของบทซ้ำบนเครื่องของผู้อ่าน ขั้นตอนเต็มอยู่ในบท

8. **ขั้นที่ 4 — วัดทั้งตาราง:** ปิด Unreal Editor ย้ายไฟล์ CSV เดิม (ถ้ามี) ออกจาก `companion/HAPBook/Saved/Profiling/CSV/` เปิดโฟลเดอร์ `companion/HAPBook/` ใน File Explorer คลิกแถบที่อยู่ พิมพ์ `cmd` แล้วกด Enter (หากบรรทัดคำสั่งขึ้นต้นด้วย `PS` ให้พิมพ์ `cmd` อีกครั้ง) แล้วพิมพ์ตัวอย่างชุดคำสั่งที่ 14.9 ทีละบรรทัด (เปลี่ยนเส้นทางในบรรทัดแรกหาก Unreal Engine ติดตั้งไว้ที่อื่น):

   ```
   set "UE=C:\Program Files\Epic Games\UE_5.8"
   set "UEBIN=%UE%\Engine\Binaries\Win64"
   Tools\ch14_run_all.bat
   ```

   รอราว 80 นาทีโดยไม่แตะเมาส์และแป้นพิมพ์จนหน้าต่างแสดงบรรทัด `Done` ตรวจ `progress.log` ว่าไม่มี `FAILED` (บรรทัดถัดจากบรรทัด `FAILED` คือคำสั่งเต็มของรอบนั้น ให้คัดลอกไปวางในหน้าต่างเดิมแล้วกด Enter) จากนั้นในหน้าต่างเดิมพิมพ์ `python Tools\ch14_reduce.py` (ต้องมี Python 3)

**การตรวจหนึ่งรอบด้วย `stat unit` และ Unreal Insights (ไม่บังคับ).** สองรอบนี้สร้างภาพ `stat unit` และภาพของ Unreal Insights ในบท แยกจากรอบการวัดและไม่นับเป็นข้อมูล ทั้งสองเปิดจาก Command Prompt ที่โฟลเดอร์ `companion/HAPBook/` แบบเดียวกับข้อ 8

9. **`stat unit`:** พิมพ์ตัวอย่างชุดคำสั่งที่ 14.10 ทีละบรรทัด:

   ```
   set "UE=C:\Program Files\Epic Games\UE_5.8"
   set "UEBIN=%UE%\Engine\Binaries\Win64"
   "%UEBIN%\UnrealEditor.exe" "%CD%\HAPBook.uproject" ^
    /Game/Maps/L_Ch14 -game -nosplash ^
    -windowed -ResX=1280 -ResY=720 ^
    -ExecCmds="viewmode unlit, stat unit" ^
    -BenchArm=/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C ^
    -BenchN=100 -BenchI=1000
   ```

   รอราว 15 วินาทีให้ค่าในแผงนิ่ง จับภาพหน้าต่าง แล้วปิดด้วย Alt+F4 คำสั่งนี้ไม่มี `-BenchAutoCapture` และ `-ExitAfterCsvProfiling` เพราะสองพารามิเตอร์นี้ทำให้รอบกลายเป็นรอบการวัด คือเขียนไฟล์ CSV ลงโฟลเดอร์ข้อมูล และปิดหน้าต่างเองหลังราว 70 วินาที
10. **Unreal Insights:** ทำตามลำดับ
    1. เปิด `UnrealInsights.exe` ในโฟลเดอร์ `C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64` ก่อน (ดับเบิลคลิกใน File Explorer)
    2. เปิด Command Prompt ที่โฟลเดอร์ `companion/HAPBook/` แล้วพิมพ์ตัวอย่างชุดคำสั่งที่ 14.11 ทีละบรรทัด:

       ```
       set "UE=C:\Program Files\Epic Games\UE_5.8"
       set "UEBIN=%UE%\Engine\Binaries\Win64"
       "%UEBIN%\UnrealEditor.exe" "%CD%\HAPBook.uproject" ^
        /Game/Maps/L_Ch14 -game -nosplash ^
        -windowed -ResX=1280 -ResY=720 ^
        -ExecCmds="viewmode unlit" ^
        -BenchArm=/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C ^
        -BenchN=100 -BenchI=1000 ^
        -trace=default -statnamedevents
       ```

    3. ในหน้าต่างหลักของ Unreal Insights เลือก Trace ที่กำลังบันทึกอยู่ แล้วกด *Open Trace*
    4. ปล่อยให้เกมทำงานราว 30 วินาที แล้วปิดหน้าต่างของเกมด้วย Alt+F4
    5. แผง *Frames*: คลิกแท่งของเฟรมหนึ่งในช่วงที่ความสูงของแท่งคงที่ (หลังสิบวินาทีแรก)
    6. แผง *Timing*: ดูแถบ *GameThread* ตั้งแต่ `FEngineLoop::Tick` ลงไปถึงกลุ่ม Tick `TG_PrePhysics` และบล็อก Tick ของ Actor แต่ละตัว
    7. ซูมด้วยล้อเมาส์เข้าไปที่บล็อกของ Actor หนึ่งตัวจนเห็นชื่อ Node ของ Blueprint
    8. แท็บ *Log*: กรองด้วย `Bench` เพื่อยืนยันบรรทัด `[Bench] Spawned`

    Unreal Insights ต้องเปิดก่อนเกม เพราะเกมเชื่อมต่อกับ Unreal Insights ที่เปิดอยู่เองโดยอัตโนมัติ `-statnamedevents` เพิ่มขอบเขตการจับเวลาให้ทุก Node ตัวเลขใน Trace จึงใช้อ่านโครงสร้างของต้นทุน ไม่ใช้แทนค่าที่วัด

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)
- Microsoft Visual C++ Build Tools (Build Tools for Visual Studio) พร้อมเวิร์กโหลด "Desktop development with C++" และ ".NET desktop build tools" (ขั้นตอนอยู่ในภาคผนวก ก ของงานเขียน)
- .NET runtime รุ่นที่ UnrealBuildTool ของ UE 5.8 ต้องการ (ค่า `framework.version` ใน `Engine\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.runtimeconfig.json` เทียบกับ `dotnet --list-runtimes`)
- ทางเลือกที่ 2 (ไม่บังคับ): Python 3 สำหรับ `Tools/ch14_reduce.py` ซึ่งลดทอนทุกไฟล์พร้อมกัน สคริปต์ใช้เฉพาะไลบรารีมาตรฐานของ Python
- ไม่บังคับ: โปรแกรมตารางคำนวณ (Microsoft Excel หรือ Google Sheets) สำหรับแบบฝึกหัดข้อ 7 ของบท (คำนวณค่าตัวแทนของหนึ่งไฟล์ด้วยมือ) หรือสำหรับการลดทอนโดยไม่ใช้ Python

สถานะเริ่มต้นของโปรเจกต์สำหรับบทนี้คือแท็ก `ch13` บทนี้เพิ่มไฟล์ใหม่สามคู่ Asset ของ Blueprint สองตัว แผนที่หนึ่งแผนที่ สคริปต์สองไฟล์ และหนึ่งบรรทัดใน `Config/DefaultEngine.ini` ไม่แตะ `HAPBook.Build.cs` (ทุกคลาสและฟังก์ชันที่ใช้อยู่ในโมดูล `Core`, `CoreUObject` และ `Engine`)

## จุดตรวจสอบผลลัพธ์

## ปัญหาที่พบบ่อย

- **กดแป้น `` ` `` แล้วคอนโซลไม่เปิด** — หน้าต่างของเกมไม่ได้รับแป้นพิมพ์ ให้คลิกในหน้าต่างของเกมแล้วกดอีกครั้ง อีกทางหนึ่งคือพิมพ์ `stat unit` ในช่อง *Cmd* ที่ด้านล่างของ Output Log ระหว่างเล่น ซึ่งส่งคำสั่งไปยังเกมที่กำลังเล่นอยู่
- **ค่า *Game* แกว่งหรือต่างจากที่บทระบุมาก** — ขณะเล่นใน Editor ค่านี้รวมงานของ Editor และเปลี่ยนตามสิ่งที่ Editor ทำในขณะนั้น (เช่น แผงที่เปิดอยู่หรือการเลื่อนเมาส์) ให้อ่านหลังเล่นราว 5 วินาทีโดยไม่แตะ Editor ทางเลือกที่ 1 ใช้ดูขนาดโดยประมาณและลำดับของสามแบบ ตัวเลขที่ใช้รายงานมาจากทางเลือกที่ 2
- **ทั้งสามแบบให้เวลาใกล้เคียงกันมาก** — `Tick()` ของคลาสฐานเรียก `RunWork()` (กล่องคำเตือนของหัวข้อ "สถาปัตยกรรมสามรูปแบบ") ทุกแบบจึงรันภาระงานใน C++ และแบบ Blueprint รันซ้ำอีกรอบ ให้คืน `Tick()` ของคลาสฐานเป็นตัวอย่างชุดคำสั่งที่ 14.3
- **Blueprint ล้วน หรือแบบผสม เร็วกว่า C++ ล้วน และค่า *Result* เป็น 0.0** — Event Tick ไม่ทำงาน: `Tick()` ของคลาสฐานไม่ได้เรียก `Super::Tick()` หรือ Node *Event Tick* ในกราฟยังเป็น Node สีจางที่ปิดใช้งาน (ยังไม่ได้ลากสายออกจากพิน Exec)
- **ค่า *Result* ของ Blueprint ล้วน เป็น 2000.0** — *Last Index* ของ For Loop เป็น `Iterations` ไม่ใช่ `Iterations` ลบ 1 (For Loop ของ Blueprint รวมค่าปลาย ลูปจึงทำงานเกินหนึ่งรอบ)
- **ค่า *Result* ของ Blueprint ล้วน เพิ่มขึ้นทุกเฟรม** — `AccSoFar` ถูกสร้างเป็นตัวแปรสมาชิกใน *Variables* แทนตัวแปรเฉพาะที่ใน *Local Variables* ของ `RunWorkBP` ค่าจึงสะสมข้ามเฟรม
- **หา `Iterations` หรือ `Result` ในแผง My Blueprint ไม่พบ** — ทั้งสองเป็นสมาชิกที่สืบทอดจาก C++ ให้เปิด *Show Inherited Variables* ในตัวเลือกของแผง หรือคลิกขวาในกราฟแล้วพิมพ์ชื่อ
- **บรรทัด `[Bench] Arm Class "…" not found; use /Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C or /Script/HAPBook.BenchmarkActorCpp`** — ค่า `-BenchArm=` ในเครื่องหมายคำพูดคือค่าที่ Spawner ได้รับและหาคลาสไม่พบ ค่าต้องเป็นเส้นทางของคลาส ไม่ใช่ชื่อ Asset: คลาส Blueprint เขียนเป็น `/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C` (ชื่อ Asset ซ้ำหลังจุดและลงท้ายด้วย `_C`; แบบผสม คือ `/Game/Blueprints/BP_Arm_Hybrid.BP_Arm_Hybrid_C`) ส่วน C++ ล้วน คือ `/Script/HAPBook.BenchmarkActorCpp` (ชื่อคลาส C++ ไม่มีอักษร `A` นำหน้า) ค่าที่พบบ่อยว่าผิดคือ `BP_Arm_PureBP` อย่างเดียว เส้นทางที่ขาด `_C` และ Blueprint ที่บันทึกไว้นอกโฟลเดอร์ `Content/Blueprints`
- **บรรทัด `[Bench] Arm Class not set, nothing spawned`** — บรรทัดคำสั่งไม่มี `-BenchArm=` และ *Arm Class* ของ Spawner ในแผนที่ว่าง
- **หน้าต่างของเกมแสดงเฟรมละราว 10 มิลลิวินาทีและไม่มีบรรทัด `[Bench] Spawned`** — Spawner ไม่ได้สร้าง Actor ทดสอบเลย ให้ค้นหาบรรทัด `[Bench]` อื่นในไฟล์ `companion/HAPBook/Saved/Logs/HAPBook.log` ซึ่งบอกสาเหตุตามสองข้อก่อนหน้า
- **พิมพ์คำสั่งแล้วได้ข้อความแสดงข้อผิดพลาดของ PowerShell เช่น `The module '%UEBIN%' could not be loaded`** — หน้าต่างที่เปิดอยู่คือ PowerShell (บรรทัดคำสั่งขึ้นต้นด้วย `PS`) ซึ่งไม่เข้าใจ `set`, `%UEBIN%`, `%CD%` และ `^` ของ Command Prompt ให้พิมพ์ `cmd` แล้วกด Enter ก่อนพิมพ์คำสั่ง ผู้อ่านที่ต้องการใช้ PowerShell ให้ใช้รูปนี้ในบรรทัดเดียว (`--%` สั่งให้ PowerShell ส่งส่วนที่เหลือให้โปรแกรมตามตัวอักษร):
  ```
  $UEBIN = "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64"; & "$UEBIN\UnrealEditor.exe" "$PWD\HAPBook.uproject" --% /Game/Maps/L_Ch14 -game -nosplash -windowed -ResX=1280 -ResY=720 -ExecCmds="viewmode unlit" -BenchArm=/Script/HAPBook.BenchmarkActorCpp -BenchN=25 -BenchI=1000 -BenchAutoCapture -ExitAfterCsvProfiling
  ```
- **ข้อความ `is not recognized as an internal or external command` ที่ชื่อ `UnrealEditor.exe`** — ค่า `UEBIN` ไม่ชี้โฟลเดอร์ที่มี `UnrealEditor.exe`: ตรวจว่าเส้นทางในบรรทัด `set` ตรงกับที่ติดตั้ง Unreal Engine 5.8 (ค่าเริ่มต้นของ Epic Games Launcher คือ `C:\Program Files\Epic Games\UE_5.8`) ว่า `UEBIN` ลงท้ายด้วย `\Engine\Binaries\Win64` และว่าไม่มีช่องว่างรอบเครื่องหมาย `=` ในบรรทัด `set` (ช่องว่างกลายเป็นส่วนหนึ่งของชื่อตัวแปร)
- **Unreal Editor เต็มรูปแบบเปิดขึ้นแทนหน้าต่างของเกม หรือ Command Prompt ไม่แสดง `More?` หลังบรรทัดที่ลงท้ายด้วย `^`** — มีช่องว่างหลังเครื่องหมาย `^` ท้ายบรรทัด เครื่องหมายนั้นจึงใช้กับช่องว่างแทนการต่อบรรทัด และคำสั่งทำงานโดยขาดบรรทัดที่เหลือ ให้ลบช่องว่างท้ายบรรทัดแล้วพิมพ์ใหม่
- **ค่าที่คำนวณเองในตารางคำนวณ (แบบฝึกหัดข้อ 7 ของบท) ต่างจากผลของ `Tools/ch14_reduce.py` เล็กน้อย** — สูตรใช้ `=TRIMMEAN(ช่วง, 0.05)` อาร์กิวเมนต์ที่สองคือสัดส่วนรวมที่ตัดออก ค่า 0.05 ตัดเพียงร้อยละ 2.5 ต่อปลาย ระเบียบวิธีของบทตัดร้อยละ 5 ต่อปลาย คือ `=TRIMMEAN(ช่วง, 0.1)` อีกสาเหตุหนึ่งคือช่วงของสูตรรวมสองแถวท้ายไฟล์ (แถวชื่อคอลัมน์ซ้ำและแถวข้อมูลประกอบ) หรือใช้คอลัมน์ `GameThreadTime_CriticalPath` แทน `GameThreadTime`
- **ข้อความ `'python' is not recognized` เมื่อรันสคริปต์** — เครื่องไม่มี Python 3 หรือไม่ได้เพิ่มลงใน PATH ระหว่างติดตั้ง การลดทอนด้วยโปรแกรมตารางคำนวณให้ผลเดียวกัน: คำนวณค่าตัวแทนของทุกไฟล์ตามแบบฝึกหัดข้อ 7 ของบท แล้วหา `=AVERAGE` และ `=STDEV.S` ของสามรอบในแต่ละเซลล์
- **สคริปต์ลดทอนพิมพ์ `4 run(s), protocol needs 3` ท้ายบรรทัดของเซลล์ใด** — มีไฟล์ CSV เดิม (เช่น รอบที่เปิดด้วยมือหรือรอบทดลอง) อยู่ในโฟลเดอร์ระหว่างการวัด ให้ย้ายไฟล์นั้นออกจากโฟลเดอร์ แล้วพิมพ์ `python Tools\ch14_reduce.py` อีกครั้ง
- **`Tools\ch14_run_all.bat` แสดงข้อความแล้วหยุดทันที** — ข้อความบอกสาเหตุ: `UnrealEditor.exe not found` คือค่า `UEBIN` ของหน้าต่าง (หรือค่าเริ่มต้นที่ต้นไฟล์เมื่อไม่ได้ตั้ง) ไม่ตรงกับที่ติดตั้ง `HAPBook.uproject not found` คือไฟล์สคริปต์ถูกย้ายออกจาก `companion/HAPBook/Tools/` และ `An UnrealEditor.exe process is running` คือยังมี Unreal Editor เปิดอยู่
- **บรรทัด `FAILED (no exit after 180 s)` หรือ `FAILED (exited without a new CSV)` ใน `progress.log`** — รอบนั้นไม่มีไฟล์ CSV บรรทัดถัดไปของ `progress.log` คือคำสั่งเต็มของรอบนั้น ให้คัดลอกไปวางใน Command Prompt เดิม แล้วกด Enter และรอจนหน้าต่างของเกมปิดเอง (ราว 70 วินาที) หากเกิดกับทุกรอบ ให้เปิดหนึ่งรอบด้วยตัวอย่างชุดคำสั่งที่ 14.8 แล้วอ่านข้อความของ Spawner ในไฟล์ Log ตามข้อถัดไป
- **ไม่มีไฟล์ CSV ใหม่หลังรอบการวัด** — เปิด `companion/HAPBook/Saved/Logs/HAPBook.log` แล้วค้นหา `[Bench]` บรรทัด `[Bench] Spawned …` แปลว่า Spawner สร้าง Actor แล้วแต่การบันทึกไม่เริ่ม (ดูข้อ "หน้าต่างของเกมไม่ปิดเอง และไม่มีไฟล์ CSV") ส่วนบรรทัด `Arm Class "…" not found` หรือ `Arm Class not set` บอกสาเหตุตามสองข้อที่เกี่ยวกับ `-BenchArm=` ด้านบน ไฟล์ Log ถูกเขียนใหม่ทุกครั้งที่เปิดโปรแกรม (ไฟล์ของครั้งก่อนถูกเก็บเป็นไฟล์สำรองที่มีวันเวลาในชื่อ)
- **`BenchmarkActorBase` ไม่อยู่ในรายการของ *Arm Class*** — เป็นการออกแบบ: คลาสฐานเป็น `Abstract` ให้เลือกคลาสลูกใดคลาสหนึ่งในสามแบบ
- **ไม่พบ `BenchmarkSpawner` ในแผง Place Actors หรือ `BenchmarkActorBase` ในรายการคลาสฐาน** — ยังไม่ได้ Build หลังเพิ่มไฟล์ หรือเปิด Unreal Editor ค้างไว้ระหว่าง Build ให้ปิด Editor แล้ว Build ใหม่ คลาสใหม่ต้องการการเปิด Editor ใหม่
- **คำเตือน `Runaway loop detected (over 1,000,000 iterations)` ขณะวัด Blueprint ล้วน** — เกณฑ์ *Maximum Loop Iteration Count* ยังเป็นค่าเริ่มต้น ให้ตั้งเป็น 10000000 ตามขั้นที่ 3 ข้อ 5 ของบท (ค่านี้อยู่ใน `companion/HAPBook/Config/DefaultEngine.ini`) ตัวนับของกลไกนี้รีเซ็ตครั้งเดียวต่อเฟรม Actor ทุกตัวของ Blueprint ล้วน จึงใช้ตัวนับเดียวกัน
- **ตัวละครผู้เล่นของ Template ปรากฏใน `L_Ch14`** — *GameMode Override* ใน World Settings ยังว่าง ให้ตั้งเป็น `GameModeBase`
- **หน้าต่างของเกมไม่ปิดเอง และไม่มีไฟล์ CSV** — บรรทัดคำสั่งขาด `-BenchAutoCapture` (Spawner จึงไม่ส่ง `csvprofile start`) หากมีไฟล์ CSV แต่หน้าต่างไม่ปิด บรรทัดคำสั่งขาด `-ExitAfterCsvProfiling`
- **ไฟล์ CSV ชื่อ `Profile(...).csv` แทน `Bench_...`** — การบันทึกถูกเริ่มด้วยการพิมพ์ `csvprofile start` เอง ไม่ใช่โดย Spawner ไฟล์นั้นไม่มีชื่อเซลล์ ให้ตรวจเซลล์จากแถวข้อมูลประกอบท้ายไฟล์
- **รอบแรกหลัง Build ใช้เวลาเปิดนานและค่าในไฟล์ CSV กระโดดสูงบางช่วง** — การเปิดครั้งแรกด้วย `-game` คอมไพล์ Shader ของ Content ที่ยังไม่ Cook ให้เปิดหนึ่งรอบที่ไม่นับผลก่อนเริ่มวัด แล้วย้ายไฟล์ของรอบนั้นออกจากโฟลเดอร์ก่อนลดทอน
- **ค่าที่วัดได้สูงและแกว่งกว่ารอบอื่น** — Unreal Editor หรือโปรแกรมอื่นยังเปิดอยู่ระหว่างวัด หรือมีการแตะเมาส์และแป้นพิมพ์ระหว่างรอบ ให้วัดรอบนั้นใหม่
