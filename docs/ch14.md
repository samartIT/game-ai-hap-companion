# บทที่ 14 — การวิเคราะห์และประเมินผลประสิทธิภาพเชิงปริมาณ

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 14 คือแท็ก (Tag) `ch14` ส่วนของบทนี้ในชุดโค้ดประกอบ (Companion) คือชุดทดสอบ (Testbed) ของการทดลองแบบควบคุมที่เปรียบเทียบสามสถาปัตยกรรมภายใต้ภาระงาน (Workload) เดียวกัน ฝั่ง C++ มีคลาส (Class) ใหม่ทั้งสาม ได้แก่ คลาสฐาน (Base Class) `ABenchmarkActorBase` (Actor ที่ไม่มี Mesh ถือ Workload ร่วม `RunWork()` และผล `Result`; `Tick()` ว่างโดยเจตนา) สถาปัตยกรรม C++ เพียงอย่างเดียว (Pure C++) `ABenchmarkActorCpp` (`Tick()` เรียก `RunWork()`) และ `ABenchmarkSpawner` (Spawn (สร้างขึ้นในฉาก) Actor ทดสอบ N ตัวเป็นตาราง เขียนค่า I ให้ทุกตัว รับค่าจากบรรทัดคำสั่ง และจับเวลาการวัดด้วย CSV Profiler) ฝั่ง Blueprint มี Blueprint เพียงอย่างเดียว (Pure Blueprint) `BP_Arm_PureBP` และแบบผสม (Hybrid) `BP_Arm_Hybrid` ใน `Content/Blueprints` แผนที่ `L_Ch14` เป็นสำเนาของ `L_Book` และ `Config/DefaultEngine.ini` ตั้งเกณฑ์ของกลไกป้องกันลูป (Loop) ของ Blueprint ไว้ที่ 10000000 โฟลเดอร์ (Folder) `Tools/` มีสคริปต์ (Script) สองไฟล์ (File) สำหรับทางเลือกที่ 2: `ch14_run_all.bat` วัดครบ 54 รอบ และ `ch14_reduce.py` ลดทอน CSV File ทั้งชุดตามระเบียบวิธีของบท Class, Asset และแผนที่ของบทที่ 7–13 ไม่เปลี่ยน รวมทั้ง `AEnemySpawner` ของบทที่ 9

ชุดทดสอบใช้ได้สองทาง ทางเลือกที่ 1 คือสังเกตผลในตัวแก้ไข (Editor; ขั้นที่ 1–3 ใช้เวลาไม่กี่นาที) ทางเลือกที่ 2 คือวัดภายใต้การควบคุมตามระเบียบวิธีที่ตารางของบทมาจาก (ขั้นที่ 4 ราว 80 นาที ไม่บังคับ) ทางเลือกที่ 1 แสดงให้เห็นผล ทางเลือกที่ 2 แสดงว่าผลนั้นมีขนาดเท่าใดและแน่นอนเพียงใด

## เริ่มต้น

Companion เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลด zip File ของ Tag `ch14` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `<ชื่อ repository>-ch14.zip` แล้วแตก File (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch14` แล้วใช้ Folder `companion/HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `companion/HAPBook/HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch14` ซึ่งมี `BenchmarkSpawner` หนึ่งตัววางไว้กลางพื้น (*Arm Class* = `BP_Arm_PureBP`, *Count* 100, *Iterations* 1000, *Auto Capture* ไม่ได้เลือก) แผนที่นี้ไม่มี Player: *GameMode Override* ใน World Settings เป็น `GameModeBase` เมื่อกด Play ผลลัพธ์ของบทอยู่ใน Output Log

**ทางเลือกที่ 1 — สังเกตผลใน Editor (ขั้นที่ 1–3).** ทุกขั้นใช้ Spawner ที่ N = 100, I = 1,000 และอ่านสองค่า คือเวลาของ Game Thread และค่า *Result*

5. **ขั้นที่ 1 — Base Class, Pure C++ และ Spawner:** เลือก `BenchmarkSpawner` ในแผง Outliner ตั้ง *Arm Class* เป็น `BenchmarkActorCpp` เปิด *Window → Output Log* พิมพ์ `[Bench]` ในช่องค้นหา แล้วกด Play กดแป้น `` ` `` (แป้นทางซ้ายของเลข 1) เพื่อเปิดคอนโซล พิมพ์ `stat unit` แล้วกด Enter รอราว 5 วินาทีแล้วอ่านค่าบรรทัด *Game* จากนั้นกด Shift+F1 เพื่อปล่อยเคอร์เซอร์ เลือก Actor `BenchmarkActorCpp` หนึ่งตัวใน Outliner แล้วอ่านค่า *Result* ในแผง Details หมวด *Benchmark*
6. **ขั้นที่ 2 — Hybrid:** ตั้ง *Arm Class* เป็น `BP_Arm_Hybrid` กด Play แล้วอ่านค่า *Game* และค่า *Result* ของ Actor `BP_Arm_Hybrid` หนึ่งตัวแบบเดียวกัน
7. **ขั้นที่ 3 — Pure Blueprint:** ตั้ง *Arm Class* เป็น `BP_Arm_PureBP` กด Play แล้วอ่านค่า *Game* และค่า *Result* ของ Actor `BP_Arm_PureBP` หนึ่งตัวแบบเดียวกัน

**ทางเลือกที่ 2 — วัดภายใต้การควบคุม (ขั้นที่ 4, ไม่บังคับ).** ผู้อ่านหยุดหลังขั้นที่ 3 ได้ ทางเลือกนี้มีไว้สำหรับสร้างตารางของบทซ้ำบนเครื่องของผู้อ่าน ขั้นตอนเต็มอยู่ในบท

8. **ขั้นที่ 4 — วัดทั้งตาราง:** ปิด Unreal Editor ย้าย CSV File เดิม (ถ้ามี) ออกจาก `companion/HAPBook/Saved/Profiling/CSV/` เปิด Folder `companion/HAPBook/` ใน File Explorer คลิกแถบที่อยู่ พิมพ์ `cmd` แล้วกด Enter (หากบรรทัดคำสั่งขึ้นต้นด้วย `PS` ให้พิมพ์ `cmd` อีกครั้ง) แล้วพิมพ์ตัวอย่างชุดคำสั่งที่ 14.9 ทีละบรรทัด (เปลี่ยนเส้นทางในบรรทัดแรกหาก Unreal Engine ติดตั้งไว้ที่อื่น):

   ```
   set "UE=C:\Program Files\Epic Games\UE_5.8"
   set "UEBIN=%UE%\Engine\Binaries\Win64"
   Tools\ch14_run_all.bat
   ```

   รอราว 80 นาทีโดยไม่แตะเมาส์และแป้นพิมพ์จนหน้าต่างแสดงบรรทัด `Done` ตรวจ `progress.log` ว่าไม่มี `FAILED` (บรรทัดถัดจากบรรทัด `FAILED` คือคำสั่งเต็มของรอบนั้น ให้คัดลอกไปวางในหน้าต่างเดิมแล้วกด Enter) จากนั้นในหน้าต่างเดิมพิมพ์ `python Tools\ch14_reduce.py` (ต้องมี Python 3)

**การตรวจหนึ่งรอบด้วย `stat unit` และ Unreal Insights (ไม่บังคับ).** สองรอบนี้สร้างภาพ `stat unit` และภาพของ Unreal Insights ในบท แยกจากรอบการวัดและไม่นับเป็นข้อมูล ทั้งสองเปิดจาก Command Prompt ที่ Folder `companion/HAPBook/` แบบเดียวกับข้อ 8

9. **`stat unit`:** พิมพ์ตัวอย่างชุดคำสั่งที่ 14.10 ทีละบรรทัด:

   ```
   set "UE=C:\Program Files\Epic Games\UE_5.8"
   set "UEBIN=%UE%\Engine\Binaries\Win64"
   "%UEBIN%\UnrealEditor.exe" "%CD%\HAPBook.uproject" ^
    /Game/Maps/L_Ch14 -game -nosplash ^
    -windowed -ResX=1280 -ResY=720 ^
    -ExecCmds="viewmode unlit, stat unit" ^
    -BenchArm=/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C ^
    -BenchN=100 -BenchI=1000
   ```

   รอราว 15 วินาทีให้ค่าในแผงนิ่ง จับภาพหน้าต่าง แล้วปิดด้วย Alt+F4 คำสั่งนี้ไม่มี `-BenchAutoCapture` และ `-ExitAfterCsvProfiling` เพราะสองพารามิเตอร์ (Parameter) นี้ทำให้รอบกลายเป็นรอบการวัด คือเขียน CSV File ลง Folder ข้อมูล และปิดหน้าต่างเองหลังราว 70 วินาที
10. **Unreal Insights:** ทำตามลำดับ
    1. เปิด `UnrealInsights.exe` ใน Folder `C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64` ก่อน (ดับเบิลคลิกใน File Explorer)
    2. เปิด Command Prompt ที่ Folder `companion/HAPBook/` แล้วพิมพ์ตัวอย่างชุดคำสั่งที่ 14.11 ทีละบรรทัด:

       ```
       set "UE=C:\Program Files\Epic Games\UE_5.8"
       set "UEBIN=%UE%\Engine\Binaries\Win64"
       "%UEBIN%\UnrealEditor.exe" "%CD%\HAPBook.uproject" ^
        /Game/Maps/L_Ch14 -game -nosplash ^
        -windowed -ResX=1280 -ResY=720 ^
        -ExecCmds="viewmode unlit" ^
        -BenchArm=/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C ^
        -BenchN=100 -BenchI=1000 ^
        -trace=default -statnamedevents
       ```

    3. ในหน้าต่างหลักของ Unreal Insights เลือก Trace ที่กำลังบันทึกอยู่ แล้วกด *Open Trace*
    4. ปล่อยให้เกมทำงานราว 30 วินาที แล้วปิดหน้าต่างของเกมด้วย Alt+F4
    5. แผง *Frames*: คลิกแท่งของเฟรม (Frame) หนึ่งในช่วงที่ความสูงของแท่งคงที่ (หลังสิบวินาทีแรก)
    6. แผง *Timing*: ดูแถบ *GameThread* ตั้งแต่ `FEngineLoop::Tick` ลงไปถึงกลุ่ม Tick `TG_PrePhysics` และบล็อก Tick ของ Actor แต่ละตัว
    7. ซูมด้วยล้อเมาส์เข้าไปที่บล็อกของ Actor หนึ่งตัวจนเห็นชื่อ Node ของ Blueprint
    8. แท็บ *Log*: กรองด้วย `Bench` เพื่อยืนยันบรรทัด `[Bench] Spawned`

    Unreal Insights ต้องเปิดก่อนเกม เพราะเกมเชื่อมต่อกับ Unreal Insights ที่เปิดอยู่เองโดยอัตโนมัติ `-statnamedevents` เพิ่มขอบเขตการจับเวลาให้ทุก Node ตัวเลขใน Trace จึงใช้อ่านโครงสร้างของต้นทุน ไม่ใช้แทนค่าที่วัด

## ความต้องการของระบบ

- Windows 10 หรือ Windows 11
- Unreal Engine 5.8 (ติดตั้งผ่าน Epic Games Launcher)
- JetBrains Rider 2026.x หรือใหม่กว่า (ใช้ได้โดยไม่มีค่าใช้จ่ายสำหรับงานที่ไม่ใช่เชิงพาณิชย์)

- ไม่บังคับ: โปรแกรม (Program) ตารางคำนวณ (Microsoft Excel หรือ Google Sheets) สำหรับแบบฝึกหัดข้อ 7 ของบท (คำนวณค่าตัวแทนของหนึ่ง File ด้วยมือ) หรือสำหรับการลดทอนโดยไม่ใช้ Python

## จุดตรวจสอบผลลัพธ์

ค่าที่เป็นตัวเลขในหัวข้อนี้มาจากเครื่องของผู้เขียน (ตาราง "คุณลักษณะของระบบที่ใช้ในการทดลอง" ของบท: โน้ตบุ๊ก Intel Core i9-11900H, RTX 3080 Laptop GPU, แผนการใช้พลังงาน Balanced) ค่าของเครื่องอื่นต่างออกไป แต่ทิศทางและโครงสร้างของผลพึงคงเดิม

**ขั้นที่ 1 — Base Class, Pure C++ และ Spawner (ทางเลือกที่ 1)**

- จุดประสงค์: ตารางทั้งสองของบทฉบับของเครื่องผู้อ่าน ครบ 18 เซลล์ (Cell) แต่ละ Cell สามรอบ

## ปัญหาที่พบบ่อย

- **กดแป้น `` ` `` แล้วคอนโซลไม่เปิด** — หน้าต่างของเกมไม่ได้รับแป้นพิมพ์ ให้คลิกในหน้าต่างของเกมแล้วกดอีกครั้ง อีกทางหนึ่งคือพิมพ์ `stat unit` ในช่อง *Cmd* ที่ด้านล่างของ Output Log ระหว่างเล่น ซึ่งส่งคำสั่งไปยังเกมที่กำลังเล่นอยู่
- **ค่า *Game* แกว่งหรือต่างจากที่บทระบุมาก** — ขณะเล่นใน Editor ค่านี้รวมงานของ Editor และเปลี่ยนตามสิ่งที่ Editor ทำในขณะนั้น (เช่น แผงที่เปิดอยู่หรือการเลื่อนเมาส์) ให้อ่านหลังเล่นราว 5 วินาทีโดยไม่แตะ Editor ทางเลือกที่ 1 ใช้ดูขนาดโดยประมาณและลำดับของสามแบบ ตัวเลขที่ใช้รายงานมาจากทางเลือกที่ 2
- **ทั้งสามแบบให้เวลาใกล้เคียงกันมาก** — `Tick()` ของ Base Class เรียก `RunWork()` (กล่องคำเตือนของหัวข้อ "สถาปัตยกรรมสามรูปแบบ") ทุกแบบจึงทำการรัน (Run) Workload ใน C++ และแบบ Blueprint ทำการ Run ซ้ำอีกรอบ ให้คืน `Tick()` ของ Base Class เป็นตัวอย่างชุดคำสั่งที่ 14.3
- **Pure Blueprint หรือ Hybrid เร็วกว่า Pure C++ และค่า *Result* เป็น 0.0** — Event Tick ไม่ทำงาน: `Tick()` ของ Base Class ไม่ได้เรียก `Super::Tick()` หรือ Node *Event Tick* ในกราฟ (Graph) ยังเป็น Node สีจางที่ปิดใช้งาน (ยังไม่ได้ลากสายออกจากพิน Exec)
- **ค่า *Result* ของ Pure Blueprint เป็น 2000.0** — *Last Index* ของ For Loop เป็น `Iterations` ไม่ใช่ `Iterations` ลบ 1 (For Loop ของ Blueprint รวมค่าปลาย Loop จึงทำงานเกินหนึ่งรอบ)
- **ค่า *Result* ของ Pure Blueprint เพิ่มขึ้นทุก Frame** — `AccSoFar` ถูกสร้างเป็นตัวแปรสมาชิก (Member Variable) ใน *Variables* แทนตัวแปรเฉพาะที่ (Local Variable) ใน *Local Variables* ของ `RunWorkBP` ค่าจึงสะสมข้าม Frame
- **หา `Iterations` หรือ `Result` ในแผง My Blueprint ไม่พบ** — ทั้งสองเป็นสมาชิก (Member) ที่สืบทอดจาก C++ ให้เปิด *Show Inherited Variables* ในตัวเลือกของแผง หรือคลิกขวาใน Graph แล้วพิมพ์ชื่อ
- **บรรทัด `[Bench] Arm Class "…" not found; use /Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C or /Script/HAPBook.BenchmarkActorCpp`** — ค่า `-BenchArm=` ในเครื่องหมายคำพูดคือค่าที่ Spawner ได้รับและหา Class ไม่พบ ค่าต้องเป็นเส้นทางของ Class ไม่ใช่ชื่อ Asset: Blueprint Class เขียนเป็น `/Game/Blueprints/BP_Arm_PureBP.BP_Arm_PureBP_C` (ชื่อ Asset ซ้ำหลังจุดและลงท้ายด้วย `_C`; Hybrid คือ `/Game/Blueprints/BP_Arm_Hybrid.BP_Arm_Hybrid_C`) ส่วน Pure C++ คือ `/Script/HAPBook.BenchmarkActorCpp` (ชื่อ C++ Class ไม่มีอักษร `A` นำหน้า) ค่าที่พบบ่อยว่าผิดคือ `BP_Arm_PureBP` อย่างเดียว เส้นทางที่ขาด `_C` และ Blueprint ที่บันทึกไว้นอก Folder `Content/Blueprints`
- **บรรทัด `[Bench] Arm Class not set, nothing spawned`** — บรรทัดคำสั่งไม่มี `-BenchArm=` และ *Arm Class* ของ Spawner ในแผนที่ว่าง
- **หน้าต่างของเกมแสดง Frame ละราว 10 มิลลิวินาทีและไม่มีบรรทัด `[Bench] Spawned`** — Spawner ไม่ได้สร้าง Actor ทดสอบเลย ให้ค้นหาบรรทัด `[Bench]` อื่นใน File `companion/HAPBook/Saved/Logs/HAPBook.log` ซึ่งบอกสาเหตุตามสองข้อก่อนหน้า
- **พิมพ์คำสั่งแล้วได้ข้อความแสดงข้อผิดพลาดของ PowerShell เช่น `The module '%UEBIN%' could not be loaded`** — หน้าต่างที่เปิดอยู่คือ PowerShell (บรรทัดคำสั่งขึ้นต้นด้วย `PS`) ซึ่งไม่เข้าใจ `set`, `%UEBIN%`, `%CD%` และ `^` ของ Command Prompt ให้พิมพ์ `cmd` แล้วกด Enter ก่อนพิมพ์คำสั่ง ผู้อ่านที่ต้องการใช้ PowerShell ให้ใช้รูปนี้ในบรรทัดเดียว (`--%` สั่งให้ PowerShell ส่งส่วนที่เหลือให้ Program ตามตัวอักษร):
  ```
  $UEBIN = "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64"; & "$UEBIN\UnrealEditor.exe" "$PWD\HAPBook.uproject" --% /Game/Maps/L_Ch14 -game -nosplash -windowed -ResX=1280 -ResY=720 -ExecCmds="viewmode unlit" -BenchArm=/Script/HAPBook.BenchmarkActorCpp -BenchN=25 -BenchI=1000 -BenchAutoCapture -ExitAfterCsvProfiling
  ```
- **ข้อความ `is not recognized as an internal or external command` ที่ชื่อ `UnrealEditor.exe`** — ค่า `UEBIN` ไม่ชี้ Folder ที่มี `UnrealEditor.exe`: ตรวจว่าเส้นทางในบรรทัด `set` ตรงกับที่ติดตั้ง Unreal Engine 5.8 (ค่าเริ่มต้น (Default Value) ของ Epic Games Launcher คือ `C:\Program Files\Epic Games\UE_5.8`) ว่า `UEBIN` ลงท้ายด้วย `\Engine\Binaries\Win64` และว่าไม่มีช่องว่างรอบเครื่องหมาย `=` ในบรรทัด `set` (ช่องว่างกลายเป็นส่วนหนึ่งของชื่อตัวแปร (Variable))
- **Unreal Editor เต็มรูปแบบเปิดขึ้นแทนหน้าต่างของเกม หรือ Command Prompt ไม่แสดง `More?` หลังบรรทัดที่ลงท้ายด้วย `^`** — มีช่องว่างหลังเครื่องหมาย `^` ท้ายบรรทัด เครื่องหมายนั้นจึงใช้กับช่องว่างแทนการต่อบรรทัด และคำสั่งทำงานโดยขาดบรรทัดที่เหลือ ให้ลบช่องว่างท้ายบรรทัดแล้วพิมพ์ใหม่
- **ค่าที่คำนวณเองในตารางคำนวณ (แบบฝึกหัดข้อ 7 ของบท) ต่างจากผลของ `Tools/ch14_reduce.py` เล็กน้อย** — สูตรใช้ `=TRIMMEAN(ช่วง, 0.05)` อาร์กิวเมนต์ (Argument) ที่สองคือสัดส่วนรวมที่ตัดออก ค่า 0.05 ตัดเพียงร้อยละ 2.5 ต่อปลาย ระเบียบวิธีของบทตัดร้อยละ 5 ต่อปลาย คือ `=TRIMMEAN(ช่วง, 0.1)` อีกสาเหตุหนึ่งคือช่วงของสูตรรวมสองแถวท้าย File (แถวชื่อคอลัมน์ซ้ำและแถวข้อมูลประกอบ) หรือใช้คอลัมน์ `GameThreadTime_CriticalPath` แทน `GameThreadTime`
- **ข้อความ `'python' is not recognized` เมื่อทำการ Run Script** — เครื่องไม่มี Python 3 หรือไม่ได้เพิ่มลงใน PATH ระหว่างติดตั้ง การลดทอนด้วย Program ตารางคำนวณให้ผลเดียวกัน: คำนวณค่าตัวแทนของทุก File ตามแบบฝึกหัดข้อ 7 ของบท แล้วหา `=AVERAGE` และ `=STDEV.S` ของสามรอบในแต่ละ Cell
- **Script ลดทอนพิมพ์ `4 run(s), protocol needs 3` ท้ายบรรทัดของ Cell ใด** — มี CSV File เดิม (เช่น รอบที่เปิดด้วยมือหรือรอบทดลอง) อยู่ใน Folder ระหว่างการวัด ให้ย้าย File นั้นออกจาก Folder แล้วพิมพ์ `python Tools\ch14_reduce.py` อีกครั้ง
- **`Tools\ch14_run_all.bat` แสดงข้อความแล้วหยุดทันที** — ข้อความบอกสาเหตุ: `UnrealEditor.exe not found` คือค่า `UEBIN` ของหน้าต่าง (หรือ Default Value ที่ต้น File เมื่อไม่ได้ตั้ง) ไม่ตรงกับที่ติดตั้ง `HAPBook.uproject not found` คือ Script File ถูกย้ายออกจาก `companion/HAPBook/Tools/` และ `An UnrealEditor.exe process is running` คือยังมี Unreal Editor เปิดอยู่
- **บรรทัด `FAILED (no exit after 180 s)` หรือ `FAILED (exited without a new CSV)` ใน `progress.log`** — รอบนั้นไม่มี CSV File บรรทัดถัดไปของ `progress.log` คือคำสั่งเต็มของรอบนั้น ให้คัดลอกไปวางใน Command Prompt เดิม แล้วกด Enter และรอจนหน้าต่างของเกมปิดเอง (ราว 70 วินาที) หากเกิดกับทุกรอบ ให้เปิดหนึ่งรอบด้วยตัวอย่างชุดคำสั่งที่ 14.8 แล้วอ่านข้อความของ Spawner ใน File Log ตามข้อถัดไป
- **ไม่มี CSV File ใหม่หลังรอบการวัด** — เปิด `companion/HAPBook/Saved/Logs/HAPBook.log` แล้วค้นหา `[Bench]` บรรทัด `[Bench] Spawned …` แปลว่า Spawner สร้าง Actor แล้วแต่การบันทึกไม่เริ่ม (ดูข้อ "หน้าต่างของเกมไม่ปิดเอง และไม่มี CSV File") ส่วนบรรทัด `Arm Class "…" not found` หรือ `Arm Class not set` บอกสาเหตุตามสองข้อที่เกี่ยวกับ `-BenchArm=` ด้านบน File Log ถูกเขียนใหม่ทุกครั้งที่เปิด Program (File ของครั้งก่อนถูกเก็บเป็น File สำรองที่มีวันเวลาในชื่อ)
- **`BenchmarkActorBase` ไม่อยู่ในรายการของ *Arm Class*** — เป็นการออกแบบ: Base Class เป็น `Abstract` ให้เลือกคลาสลูก (Derived Class) ใด Class หนึ่งในสามแบบ
- **ไม่พบ `BenchmarkSpawner` ในแผง Place Actors หรือ `BenchmarkActorBase` ในรายการ Base Class** — ยังไม่ได้ Build หลังเพิ่ม File หรือเปิด Unreal Editor ค้างไว้ระหว่าง Build ให้ปิด Editor แล้ว Build ใหม่ Class ใหม่ต้องการการเปิด Editor ใหม่
- **คำเตือน `Runaway loop detected (over 1,000,000 iterations)` ขณะวัด Pure Blueprint** — เกณฑ์ *Maximum Loop Iteration Count* ยังเป็น Default Value ให้ตั้งเป็น 10000000 ตามขั้นที่ 3 ข้อ 5 ของบท (ค่านี้อยู่ใน `companion/HAPBook/Config/DefaultEngine.ini`) ตัวนับของกลไกนี้รีเซ็ตครั้งเดียวต่อ Frame Actor ทุกตัวของ Pure Blueprint จึงใช้ตัวนับเดียวกัน
- **Player ของ Template ปรากฏใน `L_Ch14`** — *GameMode Override* ใน World Settings ยังว่าง ให้ตั้งเป็น `GameModeBase`
- **หน้าต่างของเกมไม่ปิดเอง และไม่มี CSV File** — บรรทัดคำสั่งขาด `-BenchAutoCapture` (Spawner จึงไม่ส่ง `csvprofile start`) หากมี CSV File แต่หน้าต่างไม่ปิด บรรทัดคำสั่งขาด `-ExitAfterCsvProfiling`
- **CSV File ชื่อ `Profile(...).csv` แทน `Bench_...`** — การบันทึกถูกเริ่มด้วยการพิมพ์ `csvprofile start` เอง ไม่ใช่โดย Spawner File นั้นไม่มีชื่อ Cell ให้ตรวจ Cell จากแถวข้อมูลประกอบท้าย File
- **รอบแรกหลัง Build ใช้เวลาเปิดนานและค่าใน CSV File กระโดดสูงบางช่วง** — การเปิดครั้งแรกด้วย `-game` ทำการ Compile Shader ของ Content ที่ยังไม่ Cook ให้เปิดหนึ่งรอบที่ไม่นับผลก่อนเริ่มวัด แล้วย้าย File ของรอบนั้นออกจาก Folder ก่อนลดทอน
- **ค่าที่วัดได้ (Raw Value) สูงและแกว่งกว่ารอบอื่น** — Unreal Editor หรือ Program อื่นยังเปิดอยู่ระหว่างวัด หรือมีการแตะเมาส์และแป้นพิมพ์ระหว่างรอบ ให้วัดรอบนั้นใหม่
