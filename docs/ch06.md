# บทที่ 6 — คณิตศาสตร์และฟิสิกส์ประยุกต์

สถานะของโปรเจกต์ (Project) เมื่อสิ้นสุดบทที่ 6 คือแท็ก (Tag) `ch06` บทนี้เพิ่มคลาส (Class) `AMathDemoActor` ซึ่งคำนวณคณิตศาสตร์เวกเตอร์ (Vector) ของบทที่ 6 ด้วยตัวเลขที่กำหนดตายตัว ผลลัพธ์ทุกบรรทัดจึงทำนายด้วยมือได้ก่อนกด Play ได้แก่

- การทำให้เป็นเวกเตอร์หนึ่งหน่วย (Unit Vector)
- Dot Product กับมุม
- Cross Product กับด้านซ้าย/ขวา
- ระยะทาง
- มุม Yaw จาก `FindLookAtRotation`
- Line Trace

## เริ่มต้น

ชุดโค้ดประกอบ (Companion) เก็บสถานะสุดท้ายของบท ผู้อ่านที่ต้องการสร้างทีละขั้นให้พิมพ์ตัวอย่างชุดคำสั่งตามลำดับที่บทแสดง

1. ดาวน์โหลดไฟล์ (File) zip ของ Tag `ch06` จากหน้า Releases (หรือ Tags) ของ repository — GitHub สร้าง File นี้ให้อัตโนมัติ ชื่อ File เป็น `game-ai-hap-companion-ch06.zip` แตก File แล้วได้โฟลเดอร์ (Folder) `game-ai-hap-companion-ch06/` ซึ่งมี `HAPBook/` อยู่ภายใน (ทางเลือกสำหรับผู้ใช้ git: `git checkout ch06` แล้วใช้ Folder `HAPBook/`)
2. เปิด Rider เลือก *File → Open* แล้วเลือก File `HAPBook.uproject` โดยตรง (วิธีหลัก) หากเปิดไม่สำเร็จ ให้ดูหัวข้อ "ปัญหาที่พบบ่อย" ของ `docs/ch02.md` เรื่อง .NET runtime ทางเลือกสำรองคือคลิกขวาที่ `HAPBook.uproject` เลือก *Generate project files* แล้วเปิดไฟล์ Solution (Solution File) ด้วย Rider
3. สั่ง Build (เมนู (Menu) *Build → Build Solution*) รอจนกระบวนการเสร็จสิ้นโดยไม่มีข้อผิดพลาด
4. เปิด Unreal Editor แล้วเปิดแผนที่ `Content/Maps/L_Ch06` ซึ่งมี `MathDemoActor` วางไว้แล้วที่ตำแหน่ง (0, 0, 100)
5. กด *Play* เมื่อกด Play แล้ว Player ของ Template จะปรากฏที่ PlayerStart ซึ่งไม่เกี่ยวกับตัวอย่างของบทนี้ ผลลัพธ์ของบทอยู่ใน Output Log และผู้อ่านสามารถบังคับ Player เดินสำรวจฉากได้ระหว่างนั้น
6. เปิดหน้าต่าง *Window → Output Log* แล้วพิมพ์ `Math` ในช่องกรอง เปรียบเทียบกับหัวข้อ "จุดตรวจสอบผลลัพธ์"

## จุดตรวจสอบผลลัพธ์

ก่อนกด Play ผู้อ่านควรทำนายสองข้อจากระบบพิกัด (Coordinate System) ของ Unreal (มือซ้าย, X ไปหน้า, Y ไปขวา, Z ขึ้น) (1) เป้าหมายที่ (700, 700, 0) อยู่ทางซ้ายหรือขวาของ Actor ที่หันหน้าไปทาง +X และ Cross Product จะให้ค่า Z เป็นบวกหรือลบ (2) มุมระหว่างทิศหน้ากับทิศเป้าหมายเป็นกี่องศา จากนั้นจึงเปรียบเทียบกับ Output Log ซึ่งต้องแสดงหกบรรทัดต่อไปนี้ทุกอักขระ

```
LogTemp: [Math] Direction (XY, normalized): (0.71, 0.71, 0.00)
LogTemp: [Math] Dot=0.71 -> Angle=45.00 deg
LogTemp: [Math] CrossZ=0.71 -> RIGHT
LogTemp: [Math] Distance3D=994.99
LogTemp: [Math] LookAtYaw=45.00
LogTemp: [Math] TraceDown: Hit=true Distance=100.50
```

- บรรทัดที่ 1: (700, 700, 0) − (0, 0, 100) ฉายลงระนาบ XY ได้ (700, 700, 0) ความยาว 989.95 หารแล้วได้ (0.71, 0.71, 0.00)
- บรรทัดที่ 2: Dot กับ (1, 0, 0) คือ 0.71 และ arccos(0.7071) = 45.00 องศา
- บรรทัดที่ 3: Cross((1,0,0), (0.71,0.71,0)).Z = 1·0.71 − 0·0.71 = 0.71 > 0 → RIGHT เพราะ Forward × Right = Up ในระบบมือซ้ายของ Unreal
- บรรทัดที่ 4: √(700² + 700² + 100²) = √990000 = 994.99 (ระยะสามมิติ ไม่ฉายลงระนาบ)
- บรรทัดที่ 5: Yaw = atan2(700, 700) = 45.00 องศา (ค่าบวก = หันไปทางขวา ตามนิยามของ `FRotator`)
- บรรทัดที่ 6: Line Trace เริ่มจาก Z = 100 ลงล่างได้ระยะ 100.50 ไม่ใช่ 100.00 เพราะเส้นตรวจสอบชนผิวการชน (Collision Surface) ของพื้นซึ่งอยู่ที่ Z = −0.5 cm ไม่ใช่ผิวของโมเดล (Model) ที่มองเห็น Line Trace ทำงานกับเรขาคณิต Collision ค่าที่เอนจิ้น (Engine) วัดได้คือค่าที่ควรเชื่อถือ ไม่ใช่ค่าที่สมมติไว้

การทดลองเพิ่มเติม: เลือก `MathDemoActor` ในฉาก แก้ `Target Point` เป็น (700, −700, 0) แล้ว Play ใหม่

- บรรทัดที่ 3 จะเป็น `CrossZ=-0.71 -> LEFT`
- บรรทัดที่ 5 จะเป็น `LookAtYaw=-45.00`
- บรรทัดที่ 2 และ 4 ไม่เปลี่ยน

## ปัญหาที่พบบ่อย

- ไม่มีบรรทัดใดใน Output Log — ตรวจสอบว่าแผนที่ที่เปิดอยู่คือ `L_Ch06` และได้กด *Play* แล้ว หากผู้อ่านลบ `MathDemoActor` ออกจากแผนที่ไป ให้ค้นหาในแผง *Place Actors* ลากกลับไปวาง แล้วตั้งตำแหน่งในแผง Details เป็น (0, 0, 100)
- ด้านออกมาสลับกัน (คาดว่า LEFT แต่ได้ RIGHT หรือกลับกัน) — ผู้อ่านคิดใน Coordinate System มือขวา Unreal ใช้ระบบมือซ้ายที่ X ไปหน้า Y ไปขวา Z ขึ้น และ `FVector::CrossProduct(Forward, Right)` ให้ค่า Up ดังนั้น Z ของ Cross(Forward, TargetDir) เป็นบวกเมื่อเป้าหมายอยู่ทางขวา สูตรใน `MathDemoActor.cpp` ถูกต้องสำหรับ Unreal ไม่ต้องแก้
- มุมเป็น 0 หรือ NaN — ทิศทางไปเป้าหมายไม่ได้ทำให้เป็น Unit Vector หรือมีความยาวเป็นศูนย์ (เป้าหมายอยู่ตรงตำแหน่ง Actor พอดีหรืออยู่เหนือหรือใต้ Actor พอดี จนการฉายลงระนาบ XY เหลือศูนย์) `GetSafeNormal()` คืน Vector ศูนย์ในกรณีนั้น และ Dot ที่ไม่ได้อยู่ในช่วง [−1, 1] ทำให้ `Acos` ให้ NaN โค้ด (Code) สาธิตจึง Clamp ค่าก่อน
- ระยะของเส้นตรวจสอบไม่ใช่ 100.50 — Actor ไม่ได้อยู่ที่ (0, 0, 100) หรือพื้นถูกย้ายหรือถูกแทนที่ด้วยพื้นอื่น ให้ตรวจตำแหน่ง Actor ในแผง Details และตรวจว่าพื้นของแม่แบบ (Template) ยังอยู่ที่ตำแหน่งเดิม (ผิว Collision ที่ Z = −0.5) หาก `Hit=false` แสดงว่าไม่มีพื้นใต้ Actor ในระยะ `TraceLength`
- ตัวเลขต่างจากที่ระบุในหลักสุดท้าย — เป็นผลของการปัดเศษทศนิยม ให้เปรียบเทียบที่ทศนิยมสองตำแหน่งตามรูปแบบ `%.2f` ที่ Code ใช้ ค่าที่ต่างกันเกินกว่านั้นจึงถือว่าผิด
